# minio: спецификация

Полный prepared workflow явно выбирает `compose.yml` и `compose.owner-image.yml`. Только этот opt-in overlay задаёт `AELEV_INFRASTRUCTURE_MINIO_IMAGE` для восьми servers, bucket-provisioner и site-replication-applier: точный native image ID либо допущенный digest должен совпадать с существующей owner-build receipt и owner-compose definition. Base recipe/tag, Dockerfile, stack, topology, TLS, users, volumes, health и legacy env остаются прежними. Это связывание образа, не сборка/start/admission; каталог сохраняет все IDs/kinds. До изменения проверена история; прогноз 25–35 минут вместе с совместной проверкой моделей потребителя. Основания: [Compose image](https://docs.docker.com/reference/compose-file/services/#image), [merge](https://docs.docker.com/reference/compose-file/merge/), [owner-build](../docs/api/owner-build.md), [owner-compose](../docs/api/owner-compose.md).

Присутствие собственного издателя, штатная подтверждённая отписка и потеря связи определяются только [каноническим UI-контрактом](../docs/api/platform-ui-injection.md#присутствие-и-штатная-отписка) и 00-INFRA-20261106-0008-platform-ui-owner-injection. Отписка скрывает модуль без удаления журнала или изменения ревизии; отсутствие публикаций без отписки оставляет строку с потерей связи. Повтор и восстановление сохраняют владельца, UUID, последовательность и точные неподтверждённые байты.

Нативная топология, ответственность, безопасность и сроки хранения определены в [документации развёртывания](../docs/architecture/deployment.md), относящихся к продукту принятых ADR и [README](README.md). Конкретные потребители, их данные/контракты и политики не входят в поставку инфраструктуры.

Сборка MinIO и `mc` использует canonical Go pseudo-versions тех же закреплённых commits, без динамического разрешения hash через VCS: `v0.0.0-20250422221226-0d7408fc9969` и `v0.0.0-20250416181326-b00526b153a3`. Builder принимает только соответствующие полные commit pins, получает модули через `https://proxy.golang.org` и сохраняет проверку `sum.golang.org`; отказ proxy закрывает сборку. Go 1.24.2, Alpine 3.21, UBI runtime, release labels, исходные commits и лицензии сохраняются. Основания — [canonical pseudo-versions](https://go.dev/ref/mod#pseudo-versions), [GOPROXY protocol](https://go.dev/ref/mod#goproxy-protocol) и [module authentication](https://go.dev/ref/mod#authenticating).

Собственное техническое состояние публикуется независимой необязательной ролью `ui` по [каноническому протоколу](../docs/api/platform-ui-injection.md). Описание имеет тип INFRASTRUCTURE и перечисляет только собственные компоненты. Владельцу принадлежат проверки, identity, журнал и сборка; источников соседних сервисов, Docker API или общего образа издателя нет. Недоступность UI не останавливает нативный процесс; сетевое отсутствие подтверждения и истечение срока свежести означают UNKNOWN, а не доказанный OFFLINE. Отдельная задача развёртывания получает административные файлы только явно и удаляется после выполнения.

Каждая площадка монтирует свой TLS-каталог `secrets/site-a` или `secrets/site-b` целиком read-only; в нём находятся leaf, ключ и публичный набор доверия `CAs/aelev-minio-sites.crt`. Атомарное продление leaf поэтому становится видимо после адресного rolling restart и не оставляет узел на отсоединённом inode отдельного файлового mount. Локальные leaf имеют `CA=false`, принадлежат отдельным локальным issuer и проходят общий owner-declared lifecycle gate со свежим receipt; production использует внешний PKI.

## Устойчивый журнал и конечное восстановление

Образ собственного издателя закрепляет SQLite 3.53.4 из публичного образа транспортной библиотеки по digest, сохраняя Python 3.13.7, Alpine 3.22 и клиент Platform UI 1.1.2. Перед заменой единственный писатель останавливается, полный собственный том с WAL сохраняется и проверяется старым и новым движком на изолированных копиях; UUID, последовательность и неподтверждённые байты должны совпасть.

`AELEV_INFRASTRUCTURE_MINIO_UI_RESTART_POLICY` по умолчанию в примере равен `no`: новый экземпляр не получает автоматических попыток до проверки здоровья и регистрации либо передачи прежнего бюджета в [существующем ограничителе](../USER_MANUAL.md#ограниченное-восстановление-по-unhealthy). У ещё не переведённых целей прежний ограничитель использует оставшийся бюджет `on-failure:N`, при исчерпании — `no`. После явного перевода на 00-INFRA-20261106-0010-bounded-recovery-and-process-control native-политика остаётся `no`, а тот же хостовый контроллер выполняет ограниченные по частоте повторные попытки с сохранением накопленной истории. Значение env остаётся `no` для безопасного создания следующей инкарнации и не пересоздаёт уже зарегистрированную. Создание нового контейнера не обнуляет прежние попытки. Отказ наблюдаемого провайдера не является отказом живого цикла издателя.

## Лёгкая проба издателя

Docker-проба собственного издателя запускает `python -S /opt/aelev/publisher-health.py AELEV_INFRASTRUCTURE_MINIO_` и читает только UUID и подтверждённый heartbeat собственного журнала `/var/lib/aelev-status/outbox.sqlite` в режиме только чтения. Проверка из закреплённого `aelev-platform-ui-client==1.1.2` не импортирует издатель или приложение и не выполняет HTTP/TLS-подключений; отсутствующий, чужой, устаревший или некорректный сигнал отклоняется. Прежние предел свежести `2 × UI_INTERVAL_SECONDS + 40 × UI_TIMEOUT_SECONDS`, интервалы и таймауты сохраняются. Это живость цикла, а не готовность провайдера или подтверждение доставки; порядок обновления — в [руководстве](USER_MANUAL.md#лёгкая-проба-издателя).
