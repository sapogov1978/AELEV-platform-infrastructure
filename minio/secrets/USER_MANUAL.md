# Руководство: Секреты MinIO

Полный порядок получения, первоначальной генерации, хранения и ротации, включая собственную identity издателя, описан в [README владельца](../USER_MANUAL.md#секреты-получение-и-подготовка). Этот файл перечисляет формат доставки, не заменяет эксплуатационную инструкцию.

Этот каталог содержит только локальный TLS-материал и корневые учётные данные конкретной установки. Все файлы, кроме этого README, игнорируются Git и не должны попадать в образ, журнал, резерв исходного кода или запрос на слияние.

Обязательные файлы:

- `root-user` — случайный корневой `access key` MinIO;
- `root-password` — случайный корневой `secret key` MinIO;
- `site-a/private.key` — закрытый TLS-ключ площадки A;
- `site-a/public.crt` — сертификат площадки A с полной необходимой цепочкой и SAN её четырёх узлов и балансировщика;
- `site-a/CAs/aelev-minio-sites.crt` — публичный overlap bundle обеих площадок внутри атомарно монтируемого каталога A;
- `site-b/private.key` — закрытый TLS-ключ площадки B;
- `site-b/public.crt` — сертификат площадки B с полной необходимой цепочкой и SAN её четырёх узлов и балансировщика;
- `site-b/CAs/aelev-minio-sites.crt` — та же проверенная публичная копия внутри каталога B;
- `sites-ca.crt` — набор доверенных выпускающих или корневых сертификатов обеих площадок для узлов и административных клиентов.

Для локального стенда файлы безопасно создаёт `../generate-local-configuration.sh`. Для рабочей установки учётные данные выдаются утверждённым хранилищем секретов, а сертификат каждой площадки должен содержать SAN каждого реально используемого DNS-имени её узлов и балансировщика. Site replication требует совместимых корневых учётных данных на обеих площадках. Отсутствующий файл не создаётся Docker автоматически: Compose завершает создание контейнера ошибкой.
