# SPIRE: установка на рабочий стенд 20 октября 2026

## Область и состояние проверки

По отдельному разрешению владельца устанавливаются только SPIRE Server, его наблюдатель, издатель состояния и отправитель телеметрии в собственном проекте `aelev-spire-stand-20261020`. Среда — `local`, trust domain — `local.aelev`, Linux ARM64 / Docker Desktop на macOS. Существующие потребители не переводятся на SVID; их сертификаты, очереди, PostgreSQL и остальные провайдеры не переключаются. Это не кластеризация SPIRE и не допуск внешней production-площадки.

Установка завершена. Server и все три роли наблюдения работают на указанных ниже окончательных образах, Docker health — `healthy`, число рестартов каждого — 0. Установщик завершился успешно после действительных проб, а не только создания контейнеров.

## Живая проверка

- Через обычный вход `platform-operator` в действующий Platform UI подтверждены `ONLINE` / `CONNECTED` и все четыре компонента `server`, `publisher`, `observer`, `telemetry` в `ONLINE`. [Снимок строки](stand-status-20261020.png) показывает результат. Для браузерной проверки локального доверия использованы точные публичные SPKI трёх существующих провайдеров, без изменения системного хранилища доверия или общего отключения TLS.
- Через защищённый API действующей Grafana проверены точные папка/панель/правило и `aelev_spire_native_ready{owner_instance="294685b6-cb4f-502f-9c94-57ca8a3103b6"}=1` в центральном Prometheus. Возраст фактического исходного sample через `timestamp(...)` — 16,34 секунды; время выполнения самого запроса не выдаётся за свежесть данных.
- Внутри установленных Server и sender `sqlite3.sqlite_version` возвращает `3.53.4`; один лишь успешный build не был принят за подтверждение рабочего состояния.
- При холодном старте издателя был `TimeoutError` публикации и первое промежуточное `UNKNOWN`; позже наблюдался ещё один кратковременный таймаут. Следующие публикации возвращались в `ONLINE` штатно, без ручного действия или рестарта; последовательности 8–11 успешно опубликованы. Рабочие таймауты не увеличивались. Причина отдельного позднего таймаута этим установочным прогоном не установлена; гарантированная задержка под длительной нагрузкой не объявляется проверенной.
- Временный административный token Grafana отозван, собственная первоначальная административная учётная запись ID 8 отключена и проверена повторным чтением API. Ограниченная identity панели ID 7 сохранена. Её token не смонтирован в постоянные роли.
- Обычный повтор `install.sh observation` без исходного каталога и без `--update` завершился успешно после отзыва административного token: ID и время старта всех четырёх собственных контейнеров остались прежними, одноразовые административные задачи не запускались. Повторный защищённый запрос с отозванным token отклонён, но UI остался ONLINE, а возраст центральной метрики составил 11,72 секунды.
- Все 51 ранее работавший контейнер проекта существующей инфраструктуры сохранили прежние ID и время старта. Административные ресурсы подготовлены через публичные операторские API; существующие провайдеры не пересозданы.

## Найденные и устранённые причины

- Обёртка издателя передавала собственный аргумент `publish` в CLI публичного клиента Platform UI, который ожидает `run`. Процесс завершался с кодом 2; исправлены передача аргументов и их восстановление, добавлена регрессия.
- Первоначальные административные операции Keycloak превышали рабочие 2 секунды: в отдельном измерении создание/обновление клиента заняло 5,76 секунды. Подготовка получила отдельный ограниченный бюджет 30 секунд; издатель и пробы не получили увеличенных таймаутов.
- В защищённой пробе отправителя один файл доверия используется для серверной проверки и проверки клиентского удостоверения. В собственный bundle добавлен только соответствующий серверный корень наряду с корнем чтения; отдельный корень записи не добавлен. Проверки CA/SAN остаются включены.
- Native SPIRE использует SQLite 3.53.4, но Python в прежнем runtime загружал 3.40.1, публичный sender — 3.49.2. В собственных сборочных стадиях закреплены официальный архив и SHA3 исходника SQLite 3.53.4; проверяется фактически загруженная библиотека, а не только наличие нового файла. Debian Bookworm / Alpine, Python, код и протокол публичного sender сохранены. Старые системные пакеты не объявляются исправленными или удалёнными.
- Для явно объявленных локальных HTTPS endpoint установщик сохраняет разрешённые маршруты Docker-хоста; production-профиль их отвергает. Исходная гипотеза, что прежний `host-gateway` обязательно направлял запрос не туда, не подтвердилась: отдельный запрос OIDC discovery вернул 200 за 0,95 секунды. Доказанная причина первоначального отказа SSO — короткий бюджет административных вызовов, не отключённая проверка TLS.

## Полномочия и ограничения

Стабильный UUID модуля — `294685b6-cb4f-502f-9c94-57ca8a3103b6`; название в Platform UI — «Удостоверения рабочих нагрузок». Собственный OIDC-клиент `infrastructure-spire-status` имеет роль издателя Platform UI, не административную роль. В Grafana используются отдельная папка `infrastructure-spire`, панель `aelev-infrastructure-spire`, правило `aelev-spire-readiness` и ограниченная учётная запись панели. Для первоначального правила использован отдельный административный token на один час, отозванный после установки. Уведомления используют существующую политику Grafana; отдельный SMTP или уведомитель не создаётся.

Первоначальные совместимые TLS-удостоверения наблюдения и ограниченный token панели на этом локальном стенде имеют срок семь дней. Их продление существующими внешними владельцами PKI/Grafana не реализуется выпуском SVID и не объявляется автоматическим этой установкой; CA-ключи и административные полномочия не попадают в постоянные роли. Производственная доставка исходного доверия и секретов остаётся отдельным входом владельца площадки по [руководству](../USER_MANUAL.md). Корни существующих провайдеров не заменены. Windows, Linux AMD64, два физических узла, HSM/KMS и фактическая отправка уведомления по SMTP этим прогоном не проверяются.
