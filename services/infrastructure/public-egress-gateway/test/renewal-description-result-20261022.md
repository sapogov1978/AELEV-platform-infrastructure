# Читающий операторский интерфейс — 22 октября 2026

## Согласованный объём

Пользователь отдельно разрешил публичное читающее описание уже существующего клиентского одобрения и выпуск закрепляемого артефакта. Реализованы `renewal.py describe --state-directory ...` и отдельный `Dockerfile.renewal` с тремя модулями/описью. [Спецификация](../SPEC.md#локальное-операторское-продление) определяет закрытый состав identity, отпечатков CA/scope и путей публичных выходов. Private key, исходное approval, аудит, actor и административные пути не возвращаются. Команда не создаёт lock, не ждёт мутацию, не вызывает OpenSSL и не записывает отчёты/сертификаты/grants/аудит; отказ не восстанавливает право. Runtime Dockerfile остался побайтно прежним.

## Проверки и артефакт

**98 тестов прошли** в собственном locked test-target на Python 3.13.7/Bookworm, 23,04 с. В том числе 21 новый случай: закрытая проекция, отсутствие зависимостей от обоих private keys и status, стабильность scope после штатного продления, отзыв/повторный apply, expiry, изменение scope/CA/expected digest, повреждённый/неполный аудит, неизвестное одобрение, отсутствие lock и FIFO вместо lock/CA/grant, конкурентная мутация и настоящий CLI без записей. Снимки файлов до/после включают bytes/inode/mtime/mode. Строгий Pyright из собственного lock положителен; Black/Ruff положительны. Попытка общего Pyright из другого сервисного окружения обнаружила несовпадение версии/type stubs, поэтому итог взят из собственного locked образа, а не из чужого окружения. Первичная попытка включить operator stage в runtime Dockerfile была отвергнута существующим тестом изоляции и убрана: новая поставка полностью отдельна.

Окончательный локальный операторский image ID — `sha256:861542100a50f52ec636a11982299d4ef9abb58cd0b3c36ad8b1e648b4ca8e91`, marker `io.aelev.egress.renewal-interface=1`. Это локальный выпуск, не заявление о загрузке в удалённый registry. [Сценарий артефакта](renewal_artifact_sandbox.py) прочитал из network-none/read-only контейнера только четыре разрешённых файла, сверил каждый SHA-256 с описью и исходниками, отказался бы от дополнительных путей/links и проверил настоящий нативный `describe --help`. Неизменяемая копия находится в игнорируемом `runtime/renewal-description-20261022`; старые runtime-пакеты не перезаписывались.

## Настоящее чтение и границы

Извлечённый оператор выполнен нативно через Python 3.13 с `-B` на прежнем действующем клиентском одобрении: `EGRESS_RENEWAL_BINDING_VERIFIED`. Identity совпала с единственным SAN существующего клиентского leaf, SHA-256 CA — с собственным trust anchor, публичные пути — с фактическими выходами владельца. Чтение происходило под существующим host flock; контейнерная копия lock не выдавалась за общую блокировку с macOS. Сама команда не запускала `once`, enroll, apply или revoke.

Клиентский и независимый server TLS plist сохранили прежние хеши; рабочие gateway/server TLS и остальные провайдеры не обновлялись. Проверка удостоверяет существующую привязку, не handshake, готовность модели, доставку уведомления или завершение перевода таймера потребителя. Потребитель всё ещё должен автоматически получить артефакт, построить собственный нативный план и сохранно перевести прежнее действие в согласованном переносе; новый таймер не создаётся.
