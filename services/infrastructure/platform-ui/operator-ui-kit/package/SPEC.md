# Интерфейсы: Platform UI SDK

Шапка сохранённой оболочки использует название платформы `Discovery Research Platform`, не имя исторического прикладного контура. Исходная оболочка не является владельцем сервисов или их реестров; неизменяемые прежние пакеты не переупаковываются ради подписи.

SDK Platform UI не является источником предметных контрактов. Сохранённые `QueueServiceApp`, `QueueCurrentState` и `QueueResultHero` обслуживают прежний протокол очередей; ссылки на его снятые разделы ниже закреплены за исторической редакцией Git. Они не описывают нынешние API Base/Advance и не разрешают возвращать снятый координатор. Текущие API и предметные интерфейсы определяет владелец по [архитектуре UI](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/architecture/22-platform-ui.md); самодостаточные поставки используют закреплённый неизменяемый артефакт SDK.

`useDeliverySnapshot` читает собственный согласованный снимок передачи без параллельных запросов. Время измерения видно оператору; интервал задаёт UI владельца, а по умолчанию опрос выполняется раз в пять минут. Ограниченные повторы `503 Retry-After` и `refreshing` автоматически заканчиваются после прогрева. Последнее целостное значение сохраняется, таймеры и активный запрос отменяются при отключении. Источник и владение — [контракт доставки](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/api/discovery-delivery.md#операторский-api).

`QueueServiceApp` принимает явный интервал от приложения-владельца и применяет его к обзору, состоянию процессов и диагностике доставки. Сохранённая оболочка Deep Screening задаёт одну минуту; это не работающая экспертная backend-поставка. Нынешние Base/Advance и Zone Ingestion имеют собственные компоненты обзора, поэтому их фактические интервалы нельзя выводить из значения по умолчанию этой оболочки.

Корень `QueueServiceApp` объявляет opt-in-класс `.aelev-owner-ui`. При внедрении в Platform UI он получает общие визуальные примитивы закреплённого presentation CSS; предметные сетки, очереди, метрики и опасные действия остаются в CSS владельца. Для самостоятельного режима пакет экспортирует `presentation.css`, побайтно совпадающий с текущим публичным артефактом оболочки.

`QueueServiceApp` подключает текущую работу модельной стадии через точную публичную поверхность координатора `panels.activity`, а не технический журнал `/jobs`. Очередь находится внутри «Работы сервиса»; пять категорий, FIFO и проверка доставки принадлежат [владельцу маршрутов](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/api/discovery-cascade.md#текущая-работа-фильтров). Kit отвечает только за навигацию и изоляцию рамки, не определяет тематические решения или способ повторного исполнения и не обращается к чужой БД. Совместимый `OwnedQueuePanel` остаётся средством технической диагностики, не основным операторским списком.

Необязательный `standaloneRedirectUri` в `bootstrapModule` допускает только точный корень собственного origin, не произвольный callback. Сохранением и однократным восстановлением разрешённых параметров своей глубокой ссылки управляет приложение-владелец; kit не сохраняет токены и не меняет вложенный PKCE. Начальный язык читается после восстановления собственного маршрута.

`QueueCurrentState` принимает проверенную владельцем расшифровку `outcome_details` и вместо общей категории показывает завершённое историческое техническое исследование, отсутствие записанного исхода или недопустимый исход. Старый ответ явно обозначается как нерасшифрованный. Библиотека не создаёт тематических меток и не выполняет перепланирование; нормативный источник — [API каскада](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/api/discovery-cascade.md#операторские-api).

Главный результат использует переданную владельцем историю выполненной работы `activity`, не уменьшает итог или скорость при последующем отзыве результата. «Текущее состояние» отдельно показывает действующие неотменённые ответы. При старом API история явно обозначается как неполная; отмена до выполнения не считается обработкой. Семантика определена только [контрактом владельца](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/api/discovery-cascade.md#операторские-api).

Общие карточки результатов явно называют входящие значения заданиями, включая историю отмен. Библиотека не пересчитывает их в домены, не сверяет БД разных владельцев и не приравнивает модельный ACCEPT к подтверждённому handoff. Локальные приложения передают собственные исходные счётчики и маршруты.

`QueueCurrentState` размещает три карточки текущего состояния по образцу базового отсева и раскрывает переданный исходный ответ по каждой цифре. Владелец передаёт название, подписи маршрутов и проверенные значения; библиотека не читает предметный API и не выводит факт доставки из модельного ответа. `QueueOutcomes` и `QueueRoutes` являются входами представления, не вторым контрактом статистики. Источник и семантика — [API каскада](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/api/discovery-cascade.md#операторские-api).

`QueueResultHero` оформляет основной результат очереди и четыре раскрываемых показателя, принимая готовые значения и переход от приложения владельца. `QueueProgress` — только форма входов представления, не второе определение административного API. `QueueServiceApp` размещает блок в обзоре; источники и проверка данных остаются в сервисных приложениях. Нормативная семантика — [API каскада](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/api/discovery-cascade.md#операторские-api).

`PlatformPage` — единственный платформенный каркас владельческой страницы. Он формирует корень `app-shell aelev-owner-ui`, заголовок `page-intro`, рабочую область и необязательные слоты автономной шапки и модальных элементов. Режим `layout="filter"` добавляет платформенные классы `filter-app` и `filter-content`, не создавая отдельного типа страницы или второго источника оформления. Компонент не публикует манифест, не управляет iframe, авторизацией, состоянием, опросом или командами; предметные блоки и их локальные специализации остаются у сервиса.

Канонические правила находятся в `platform-ui/presentation`, а `build_presentation.py` создаёт неизменяемый `/presentation/v6.css` и его точную SDK-проекцию. Экспорт `presentation` содержит точные публичный путь и SHA-256 этой проекции; bridge владельца не хранит их второй копии. Приложение импортирует `presentation.css` после собственных предметных специализаций, а внедрённый режим повторно подключает только те же проверенные байты. Файлы `presentation.css` в приложениях не редактируются и не форкаются. Любое изменение общих классов, поведения стандартных элементов или базовой геометрии требует нового presentation-артефакта и нового выпуска SDK; опубликованные версии не переписываются.

`useGuardedNavigation` и `NavigationConfirmation` подтверждают уход с введёнными данными внутри самого приложения, без браузерного модального окна или дополнительных разрешений iframe. Отмена сохраняет ввод и восстанавливает фокус; переход без сохранения требует отдельного действия. Это техническая защита формы, не сохранение предметного решения.

При смене страницы или фильтра `OwnedQueuePanel` снимает прежний выбор и исходный текст, не применяет запоздалые ответы другой страницы и не показывает ноль до получения счётчиков. Фоновое обновление сохраняет выбранное задание только пока оно присутствует в текущем списке; ответ после отключения не меняет состояние.

`ServiceNavigation` и `QueueServiceApp` задают единое оформление разделов и рабочих карточек; названия, счётчики, чтения и адреса панелей передаёт владелец. `ServiceSurfaceFrame` изолированно подключает точный UI владельца с собственным PKCE, не получает токенов или документов через `postMessage`, проверяет origin, окно и сеанс и передаёт только язык, размер и признак ввода. Список разрешённых родителей задаётся владельцем через `VITE_EMBEDDING_ORIGINS` и по умолчанию пуст. Несохранённая вложенная форма защищается при переключении панели, а признак ввода передаётся родительскому функциональному приложению. Общая библиотека не назначает стадию человеческому решению и не становится владельцем журнала.

`OwnedQueuePanel` отображает переданные владельцем строки и JSON, не содержит путей API или предметных моделей. Загружает данные последовательно раз в пять минут, раскрывает факты и исходные документы через функции владельца и освобождает таймер при отключении.

SDK Platform UI содержит технический каркас, безопасный опрос и панели управления. Он упаковывается в отдельные UI и не содержит предметных моделей, канонических хранилищ или токенов инфраструктурной сессии. Предметные приложения находятся в областях владельцев; инфраструктурного каталога потребителей нет. Проверки выполняются Platform UI и приложениями-потребителями.

Встроенное приложение автоматически проверяет существующую сессию через свой OIDC-клиент с PKCE. Фоновая попытка запрашивает одноразовый code без формы входа, ограничена десятью секундами и очищает iframe, таймер и обработчики при любом завершении или отключении. Callback приходит только собственному приложению после проверки origin, окна, пути и state; токены не пересылаются. При недоступном фоновом входе сохраняются ручная авторизация и самостоятельное открытие. Используется прежний точный `/auth-callback.html`; новые redirect URI и внешние origin не требуются.
`DeliveryStatusPanel` подключается отдельно в «Состоянии» и читает только собственный авторизованный `GET /delivery` с заданным UI владельца интервалом, по умолчанию раз в пять минут. Обзоры фильтров не подключают эту панель и её опрос по [правилам интерфейса](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/architecture/22-platform-ui.md). Диагностика показывает накопленный подтверждённый приём и текущую очередь передачи; исходные сообщения, восстановление, карантин и исторические потери открываются через `EvidenceDialog`. Неизвестные показатели не подменяются нулём. `deliverySummary` — проверка входов представления, не второе определение API или новый владелец данных. Семантика — [контракт Discovery delivery](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/api/discovery-delivery.md).
