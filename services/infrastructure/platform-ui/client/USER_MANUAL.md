# Руководство: Клиент Platform UI

Самостоятельная библиотека Python 3.13, а не общий образ издателя и не новый сервис. Она реализует только HTTPS/JWT/mTLS, устойчивую последовательность и точные повторы по [каноническому контракту](../../../../docs/api/platform-ui-injection.md). Описания, состав, проверки здоровья, настройки, полномочия и запуск определяет владелец поставки. Каталога продуктов и обнаружения контейнеров нет.

Сборка: `poetry build --format wheel`. Текущий выпуск `aelev-platform-ui-client==1.1.1` распространяется как wheel; поставка включает его в собственный `vendor`, а Poetry lock закрепляет SHA-256. После извлечения каталога сервиса сборка не обращается к исходникам библиотеки, соседним каталогам или общему образу. В рабочем процессе библиотека уже находится внутри его собственного образа. Обновление библиотеки у одного владельца не обновляет других.

Версия 1.1.1 добавляет автономный `health.py` для исполнения напрямую через `python -S`, без импорта пакета издателя, TLS, HTTP, SQLAlchemy или PostgreSQL-драйвера. Файл извлекается из закреплённого wheel при сборке собственного образа; источники соседнего сервиса не копируются. Единственный аргумент — собственный префикс `AELEV_*`; проба читает только подтверждённый heartbeat и UUID из своего SQLite-журнала с ожиданием блокировки не более 50 мс. Она не создаёт отсутствующий журнал, не меняет последовательность, проверяет владельца и прежний предел свежести `2 * interval + 40 * timeout`. Отказ публикации или неизвестность зависимости не подменяются отказом собственного живого цикла; остановившийся цикл даёт нездоровое состояние. Legacy-команда `health` остаётся совместимой. Байты 1.1.0 не меняются, миграции журнала нет.

Повтор после отказа сохраняет байты и исходное время до успешного ответа; последовательность хранится в собственном SQLite WAL/FULL. Этот журнал содержит только техническое представление, не доменные данные. По [ADR-0115](../../../../docs/adr/20261012-0115-owner-local-embedded-sqlite.md) файл находится в собственном постоянном локальном томе издателя, не в общей сетевой папке или БД оболочки. UUID, sequence, ожидающее сообщение и намерение выхода не являются потеряемым кэшем; нужен согласованный backup/restore собственного журнала. Файлы доверия и client secret принадлежат владельцу; административные файлы доступны только одноразовой задаче `provision`. Повторная публикация восстанавливает актуальную декларацию и новое состояние оболочки, но не прежний журнал/защитные записи приёмника: их сохраняет его собственная резервная копия. Потеря последовательности при сохранённой оболочке требует восстановления собственного журнала, не сброса sequence. Версионированная библиотека подготавливает совместимую встроенную схему до отправки; PostgreSQL-мигратор этим не заменяется.

Проверенный артефакт выпуска: `aelev_platform_ui_client-1.1.0-py3-none-any.whl`, SHA-256 `48107175d7e7d090118d11e55b0255ffd4d928bf37d7dfbbe81cef09ab4325a6`. Копия в `platform-ui/public/presentation/client/1.1.0` доступна через HTTPS оболочки после её сборки; каждый владелец проверяет digest и включает wheel в собственный `vendor`. Исходники этого каталога — канонический источник транспорта; встроенные копии — артефакты, не отдельные реализации контракта. Библиотека не имеет рабочих зависимостей. Для браузерного теста на операторской машине отдельно нужны закреплённые `playwright==1.56.0` и Chromium; в постоянном издателе браузер не запускается.

Проверки библиотеки находятся в `../test`; проверки конкретных проб и жизненного цикла — только в `test` владельца.

Версия 1.1.0 добавляет подтверждаемое присутствие и штатную отписку по [ADR-0105](../../../../docs/adr/20261010-0105-publisher-presence-and-graceful-withdrawal.md). `run` при SIGTERM/SIGINT сохраняет намерение отписки, подтверждает прежнее сообщение и новую отписку; при следующем запуске завершает неподтверждённый выход перед свежей публикацией. UUID, ревизия и последовательность не сбрасываются. При невозможности подтверждения строка остаётся с потерей связи; аварийное завершение не выдаётся за штатное. `once` публикует одно наблюдение без автоматической отписки. Сначала обновляется API оболочки, затем отдельные образы владельцев. Публичные байты выпуска 1.0.0 остаются неизменными для прежних потребителей.

Для браузерной проверки на операторской машине, из каталога своего сервиса, проверьте `python3.13 --version` и `docker compose version`, затем подготовьте отдельное окружение. Проверка не устанавливает инструменты в рабочий контейнер:

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install vendor/aelev_platform_ui_client-1.1.0-py3-none-any.whl playwright==1.56.0
.venv/bin/python -m playwright install chromium
.venv/bin/python test/status_publication.py --help
```

Если Python 3.13 отсутствует, порядок проверки и установки приведён в [README оболочки](../PROVIDER_OPERATIONS.md#требования-и-подготовка). В `--chromium` передайте путь установленного Chromium; его можно получить из `playwright.chromium.executable_path` внутри `sync_playwright()`. Обязательные аргументы, пределы разрешённого stop/start и подготовка настоящих удостоверений остаются в README владельца. Только операторский процесс теста управляет Docker; постоянный издатель этих полномочий не получает.

После выпуска байты версии и её digest неизменяемы. Изменение транспорта выпускается под новой версией и отдельно принимается владельцем; автоматического обновления всех образов нет.

Откат на клиент 1.0.0 требует автономной подготовки собственного журнала после подтверждённой отписки: прежняя вставка SQLite несовместима с дополнительной колонкой `withdrawal`. Без обнуления UUID/sequence и только при отсутствии неподтверждённых сообщений применяется проверяемый операторский пример из [user manual](../USER_MANUAL.md#отправить-метаданные-из-python), затем возвращается прежний образ; прежний API — последним. При неподтверждённом выходе такой откат запрещён до восстановления связи и завершения отправки текущим клиентом.

В собственных сервисных Compose издателю выделены две минуты `stop_grace_period`: стандартных десяти секунд Docker может не хватить на завершение текущей проверки, подтверждение прежнего запроса и отписки через удалённый HTTPS. Это ограниченное ожидание, не гарантия при недоступной сети. Если владелец увеличивает сетевые таймауты, он согласует с ними собственное время остановки; по исчерпании срока отсутствие отписки остаётся потерей связи, не скрытым модулем.
