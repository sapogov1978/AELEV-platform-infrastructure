# Keycloak — проверки собственного издателя

Дата: 2026-10-10 по Europe/Belgrade. Итог: PASS. Проверки выполнены на Python 3.13 в собственном образе `aelev/keycloak-status-checks:local`, собранном только из каталога Keycloak с закреплённым `poetry.lock`. Docker socket не монтировался.

| Проверка | Результат |
|---|---|
| Модульные проверки издателя | 21 из 21 пройдены |
| Конфигурационные проверки поставки | 6 из 6 пройдены |
| Black | Пройден |
| Ruff | Пройден |
| Строгий Mypy рабочего издателя | Пройден |
| Сборка собственного runtime и образа проверок | Пройдена |
| Повтор собственной задачи provision на реальном IdP | Пройден без пересоздания клиента |
| Изолированное разрешение новых блоков корневого Compose | Пройдено: собственные build context и secret paths, административный пароль отсутствует в runtime |

Проверены точное собственное описание без потребителей, подтверждённые `UP`/`DOWN`, неизвестное состояние при ошибке сети/доверия, сохранность номера и точного неподтверждённого сообщения после нового открытия тома, отказ чужому UUID, неподходящее подтверждение, повтор при потерянном ответе, сохранение сообщения при отказе получения токена, запрет HTTP/перенаправления и отказ перезаписать чужую publisher identity.

Команды повторения сборки, pytest, Black, Ruff и Mypy находятся в [README](../USER_MANUAL.md#публикация-в-состоянии-платформы). Последний полный прогон 2026-10-10 по Europe/Belgrade: `pytest -q`, результат `27 passed in 0.25s`. Black, Ruff и строгий Mypy повторно пройдены. Дополнительно проверены ревизия 2 собственного состава, отдельные результаты процесса и соединения с БД, неизвестная БД при отсутствующей/неоднозначной проверке, подтверждённый отказ БД при работающем процессе и точное сохранение составного отчёта после потерянного подтверждения. Проверки используют временное хранилище; контейнеры инструментов удалены через `--rm`. Рабочий publisher, его identity, сертификат, том и реальная запись остаются как обычная поставка, не как тестовая фикстура. Provision и изолированные блоки корневого Compose в таблице проверены при первоначальном добавлении издателя; для добавочного состава повторная настройка identity не требовалась.

Настоящие JWT/mTLS и отображение Keycloak, а также рестарт только издателя без обнуления последовательности проверены отдельно: [результат](status-publication-result.md), [снимок](status-publication.png). Keycloak и его PostgreSQL не перезапускались. Временное браузерное окружение удалено.

Полное разрешение корневого Compose с существующими рабочими env не прошло из-за ранее пустых параметров provisioning, в частности `AELEV_INFRASTRUCTURE_MINIO_PROVISION_ACCESS_KEY`/`AELEV_INFRASTRUCTURE_ZONE_BUCKET_ACCESS_KEY` и `AELEV_INFRASTRUCTURE_POSTGRESQL_PROVISION_PASSWORD`/`AELEV_INFRASTRUCTURE_BASE_SCREENING_DATABASE_PASSWORD`. Эти настройки не менялись. Проверка новых блоков выполнена отдельно; общая инфраструктура не запускалась и её интеграционное тестирование не объявляется пройденным.

Сборка сообщает два предупреждения об обязательном Docker ARG без значения по умолчанию. Закреплённый образ передан из собственного env; сборка успешна, запасной источник настройки не добавлялся. Проверка локальной PKI не является допуском WAN, ротации или внешней production PKI.
