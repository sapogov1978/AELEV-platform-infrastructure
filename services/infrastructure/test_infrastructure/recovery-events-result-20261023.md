# Устойчивые события восстановления — 23 октября 2026

## Причина и исправление

Docker удерживал 256 событий примерно за 10 секунд; прежний контроллер опрашивал их через 15 секунд после прохода. Healthcheck создавали достаточно exec-событий, чтобы доказательство `die` исчезло до опроса. Защитный отказ `AUTOMATIC_EXIT_UNCONFIRMED` поэтому возникал после обычных аварий. Это дефект наблюдения, не разрешение запускать по одному `ExitCode`.

Прежний `recovery.py` теперь совмещает непрерывное сохранение минимальных событий и прежний исполнитель в одном `watch` под прежним планировщиком. Свежий хвост Docker соединяется только с доказанным сохранённым покрытием. Пропуск истории и ручные действия запрещают start; отставание читателя даёт ожидание. Нового контроллера, таймера, runtime socket или канала тревог нет. Норма — в [SPEC](../SPEC.md#контейнерный-оператор-восстановления).

Docker включает длинную многострочную команду в Action события `exec_create`. Формат потока заменяет неизвестные действия на `other` до чтения строки: команды, labels и env не попадают ни в минимальный кадр, ни в журнал. Это устраняет ложные переподключения на обрезанных кадрах.

## Проверки и установка

Новые 16 проверок покрывают вытесненный аварийный выход, семь управляющих действий оператора, нулевой выход, разрыв/отставание, повтор сессии, принадлежность daemon и минимизацию данных; отдельная регрессия проверяет ожидание завершения `watch` при upgrade. Black, Ruff и строгий MyPy проверены для изменённого оператора и новых проверок.

Настоящий `recovery_events_sandbox.py` использует два собственных контейнера без сети, рабочих томов и credentials. Проверены многострочный exec, реальное вытеснение `die`, один автоматический start, запрет после ручного stop и отсутствие посторонних ID в журнале. Тестовые ускоренные интервалы действуют только в отдельном процессе/журнале. Обе временные оболочки удалены по точным проверенным ID, рабочие данные не подключались.

Первый адресный upgrade сохранил 87 identities/guards, историю и десять удержаний. После возврата двух разрешённых ролей финальный выпуск сохраняет оставшиеся восемь удержаний. ## Две рабочие роли

Zone worker завершился после `SQL_CONNECT_TIMEOUT` внутри группы задач. Перед возвратом штатный читающий guard подтвердил кворум/DCS/fencing; три собственные SQL-проверки Zone заняли 0,041/0,001/0,001 секунды. Пользовательские зоны `aaa`, `research`, `gov` и команды RUNNING сохранены. Это не доказательство повреждения БД или истечения сертификата.

Sender переводчика завершился с `INGESTION_LISTENER_STALLED`: сохранены фаза ACCEPT, задержка supervisor 8,068 секунды и ограниченные собственные стеки. Они совместимы с общей задержкой исполнения потоков, но точную причину планирования ОС не доказывают. OOM не было; таймауты этим исправлением не увеличены, предположение не названо доказанной сетевой блокировкой. Полный остановленный журнал сохранён до запуска.

Оба прежних ID после разрешённых операторских стартов healthy без пересоздания, native RestartCount остался 0; sender отдельно прошёл mTLS `/health`. Накопленные attempts Zone — 552, sender — 0. Возобновлено только наблюдение новых здоровых инкарнаций; восемь других защитных удержаний не отменены. После первого start Zone читающий inspect кратко отказал; успешный запуск согласован чтением, команда start не дублировалась.

## Доказательства и ограничения

Закрытые полные журналы, копия sender и квитанции находятся в игнорируемом `runtime/recovery-events-20261023`: `installation.json`, `installation-final.json`, `pair-restoration.json`, `sandbox-v3/result.json`. Ключи, конфигурация и исходные сообщения не публикуются. Потерянные старые события не реконструируются, накопленная история не сбрасывается.

На Mac проверяется действующий LaunchAgent; Linux/Windows покрыты проверками генерации задач, не новым испытанием на этих ОС. Qwen не запускается, Advance остаётся PAUSED. Этот результат не объявляет автоматически завершённой общую цель готовности остальных компонентов.

Финальная читающая сверка: 92 из 94 плановых ролей healthy, 87 регистраций/восемь прежних удержаний сохранены, новых native-рестартов нет. Непрерывный читатель продвигается без переподключения в проверяемом интервале; центральная метрика переводчика имеет возраст 15,455 секунды. Две нездоровые роли — прежние защищённые Base delta-consumer/outbox, завершившиеся ещё в 15:22:52/15:23:25 UTC до исправления наблюдения. Их доступные журналы отдельно сохранены; у delta-consumer найден SQL statement timeout, причина outbox этим срезом не установлена. Их запуск не входил в согласованный возврат двух ролей и не выполнен. Доказательства — `final-proof.json` и `base-protected-diagnosis.json` того же закрытого каталога.
