Команды из корня репозитория:

```sh
docker build --target runtime -t aelev/observability-tools:python3.13.7 services/infrastructure/observability
docker build --target checks --build-context tests=services/infrastructure/observability/test -t aelev/observability-checks:local services/infrastructure/observability
docker run --rm --network none aelev/observability-checks:local sh -c 'ruff check prepare.py initialize.py test && black --check prepare.py initialize.py test && mypy prepare.py initialize.py test && pytest -p no:cacheprovider -q test'
```

Смежная совместимость на момент этого прогона: перенесённая регрессия правил Base Screening прошла штатный `promtool`; Platform UI прошёл 15 UI-тестов, TypeScript/Vite-сборку, 12 прежних проверок поставки и четыре Python-проверки конфигурации. Исторический тест защищённого proxy до ADR-0101 проверил 11 этапов на реальном Prometheus с точной очисткой; он принадлежит UI, не провайдеру наблюдения. Это не проверка всей корневой оркестрации и не подтверждение TLS-экспорта рабочего Base Screening.

Внешний SMTP-провайдер/отправитель ещё не выбран; реальные внешние письма не отправлялись. Продукционная PKI/SVID, ротация, WAN, независимое резервное восстановление, внешний контроль потери узла, нагрузка и допуск цепочки поставки остаются открытыми по [TASKS](../TASKS.md). При сборке UI прежний npm lock сообщил об одной уязвимости уровня high; достижимость и допуск не проверены, стек не изменён.
