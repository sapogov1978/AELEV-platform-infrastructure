# blackbox-exporter: спецификация самостоятельной поставки

## Локальная живость и восстановление

Постоянные роли создаются с `restart=no`. Автоматическое восстановление явно зарегистрированного экземпляра выполняет только существующий хостовый контроллер по ADR-0155; регистрация/замена сохраняет прежнюю историю, ручную остановку и защитные запреты. Этот режим не является бесконечным независимым restart-циклом Docker и не меняет зависимости или предметные очереди.

Собственный нативный образ сохраняет точный upstream и его ОС, добавляя только статическую пробу из закреплённого `aelev-native-health-1.0.0.tar.gz`. Она проверяет только собственный loopback TLS/HTTP-listener с прежними клиентскими удостоверениями и CA/SAN; DNS, внешних обращений и чтения тела нет. Общий дедлайн — три секунды, корректный окончательный HTTP-ответ подтверждает живость независимо от готовности зависимостей. Прежний защищённый readiness остаётся источником прикладной готовности.

Операторский вход использует `aelev-observability-tools==1.1.2` без смены зависимостей. Каждый из двух настоящих event loop обновляет свой локальный heartbeat; автономная Docker-проба через `python -S` читает оба сигнала с пределом свежести 15 секунд. Отказ IdP/upstream не подменяется зависанием процесса. Собственный `OPERATOR_IMAGE` отделён от образа уже работающего издателя, поэтому его замена не требует неявного обновления журнала издателя.



Ревизия 4 собственного описания содержит отдельный ui_url из OPERATOR_PUBLIC_URL и компонент operator по [ADR-0111](../../../../docs/adr/20261011-0111-owner-operator-access-modes.md). Явные local-test/prod меняют только браузерный вход: чтение с собственным OIDC/PKCE без клиентского сертификата браузера. Нативные порты и приватная проверка operator сохраняют mTLS; сертификаты, данные, UUID и sequence не сбрасываются.

По [ADR-0107](../../../../docs/adr/20261011-0107-independent-observability-products.md) единственный Compose этого владельца определяет нативный процесс без профиля, собственные конфигурацию, сеть, удостоверения, данные и явную подготовку тома, где он существует. Родитель observability только включает его без поправок. Защищённые адреса зависимостей настраиваются в собственном env и не требуют общей Docker-сети между узлами. Выполняет технические HTTPS/TCP-пробы, заданные вызывающей стороной; каталога приложений и собственного хранилища нет.

Нативный процесс не имеет постоянного тома данных проб и DATA_OWNER; постоянный журнал UI принадлежит собственному издателю. Одновременные писатели журнала запрещены; штатные stop/down его не удаляют. Подготовка использует публичный закреплённый артефакт внутри собственного образа, не общий runtime. Секреты и производные runtime-файлы находятся только внутри поставки владельца.

Присутствие собственного издателя, штатная подтверждённая отписка и потеря связи определяются только [каноническим UI-контрактом](../../../../docs/api/platform-ui-injection.md#присутствие-и-штатная-отписка) и ADR-0105. Отписка скрывает модуль без удаления журнала или изменения ревизии; отсутствие публикаций без отписки оставляет строку с потерей связи. Повтор и восстановление сохраняют владельца, UUID, последовательность и точные неподтверждённые байты.

UI-часть публикует собственный UUID с типом `INFRASTRUCTURE`, без функциональных разделов; состав — `server`, `operator` и `publisher`. Источник `server` — только собственный HTTPS readiness, `operator` — собственная приватная mTLS-проба процесса, `publisher` — выполнение собственного цикла. Общее состояние ONLINE допустимо только при положительном подтверждении всех частей. Чужие endpoints, хранилища и модели не читаются.

Поставка имеет собственные образ, Poetry lock, рабочие/одноразовые удостоверения и постоянный журнал. Отсутствие UI не останавливает нативный процесс; отсутствие другого продукта не останавливает этот издатель. Секреты не попадают в env, Git или лог. JWT/mTLS, повтор точных байтов, исходное время и последовательность соответствуют [каноническому API](../../../../docs/api/platform-ui-injection.md). Журнал не удаляется при обычной остановке; потеря журнала не позволяет начать последовательность заново под прежним UUID.

Операционные команды, смысл параметров, подтверждаемые границы и тесты определены в [README](README.md). Локальная PKI/один Docker host не доказывают production PKI/SVID, географическую отказоустойчивость и WAN.

## Устойчивый журнал и конечное восстановление

Образ собственного издателя закрепляет SQLite 3.53.4 из публичного образа транспортной библиотеки по digest, сохраняя Python 3.13.7, Alpine 3.22 и клиент Platform UI 1.1.1. Перед заменой единственный писатель останавливается, полный собственный том с WAL сохраняется и проверяется старым и новым движком на изолированных копиях; UUID, последовательность и неподтверждённые байты должны совпасть.

`AELEV_INFRASTRUCTURE_BLACKBOX_EXPORTER_UI_RESTART_POLICY` по умолчанию в примере равен `no`: новый экземпляр не получает автоматических попыток до проверки здоровья и регистрации либо передачи прежнего бюджета в [существующем ограничителе](../../USER_MANUAL.md#ограниченное-восстановление-по-unhealthy). У ещё не переведённых целей прежний ограничитель использует оставшийся бюджет `on-failure:N`, при исчерпании — `no`. После явного перевода на ADR-0155 native-политика остаётся `no`, а тот же хостовый контроллер выполняет ограниченные по частоте повторные попытки с сохранением накопленной истории. Значение env остаётся `no` для безопасного создания следующей инкарнации и не пересоздаёт уже зарегистрированную. Создание нового контейнера не обнуляет прежние попытки. Отказ наблюдаемого провайдера не является отказом живого цикла издателя.

## Лёгкая проба издателя

Docker-проба собственного издателя запускает `python -S /opt/aelev/publisher-health.py AELEV_INFRASTRUCTURE_BLACKBOX_EXPORTER_` и читает только UUID и подтверждённый heartbeat собственного журнала `/var/lib/aelev-status/outbox.sqlite` в режиме только чтения. Проверка из закреплённого `aelev-platform-ui-client==1.1.1` не импортирует издатель или приложение и не выполняет HTTP/TLS-подключений; отсутствующий, чужой, устаревший или некорректный сигнал отклоняется. Прежние предел свежести `2 × UI_INTERVAL_SECONDS + 40 × UI_TIMEOUT_SECONDS`, интервалы и таймауты сохраняются. Это живость цикла, а не готовность провайдера или подтверждение доставки; порядок обновления — в [руководстве](USER_MANUAL.md#лёгкая-проба-издателя).
