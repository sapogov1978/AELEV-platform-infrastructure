## Joint conflict/regression review

- Trust publisher → Nginx and Nginx → API are distinct. `X-Verified-Publisher` has authority only on the authenticated, allowed proxy connection. Probe certificates do not become proxy identities. TLS extension comes from transport, never headers. Missing/malformed peer information denies metadata access in network mode. `CERT_REQUIRED` and chain verification remain mandatory; parsing a URI does not replace them.
- The adapter is per connection and injects per-request scope; another connection cannot inherit a previous client's certificate. It is tested on the pinned H11 implementation. No Uvicorn fork, library upgrade or WebSocket contract is introduced.
- API settings accept only the exact old field set or that set plus the explicitly validated optional proxy identity. Selecting published network mode with old settings fails before serving or touching metadata.
- No-argument render keeps old fields and outputs. Network role rendering avoids the prior all-private-keys-on-one-node prerequisite. Local development PKI is still an explicit trusted-operator procedure; production receives role identities through the existing PKI/SPIRE delivery.
- API metadata/tombstone/ownership/revision/sequence, single-writer WAL/FULL serialization, issuer/audience, browser PKCE/CSP/iframe and owner declaration protocol remain unchanged. Multiple SQLite writers/HA are not admitted by this profile. No Swagger endpoint is added where intentionally disabled.
- Each runtime instance has separate state, secrets and networks. Routes are declared endpoints; no shared bridge, peer volume or hardcoded Keycloak alias is required. Owner workflow starts exact roles with `--no-deps` after prerequisites. Local-only co-location overlays are not silently applied.
- New TLS/config files are whole-directory mounted where rotation is relevant. No existing key, journal, token, data or recovery budget is replaced. API/own publisher metadata recovery remains an explicit qualification, not implied by a healthy listener.

Three incompatible approaches without a selected solution require an interview. Current selected approach preserves the accepted stack and trust boundaries; implementation still needs green proof.

Native preflight found a prior root-operator incompatibility: `prepare.settings` rejected GID 0 although `init`/PKI use the operator's `os.getgid()`. All new TLS checks passed; the existing PKI test failed before creating credentials. Before correction, a 5–10 minute estimate was announced. Accept the non-negative POSIX GID range while retaining positive ports/timeouts and invalid/negative GID refusal. [Compose group_add](https://docs.docker.com/reference/compose-file/services/#group_add) and [Python getgid](https://docs.python.org/3.13/library/os.html#os.getgid) are the official grounds. Preserve the initial packaged FAIL; no image pin or runtime identity is changed by validation.

## Official and internal grounds

- Preflight inspection identified restrictive operator `umask 077` plus whole-directory binds producing a `0700` runtime root. Announced correction **5–10 minutes**: network render creates/chowns its own runtime root to configured `SECRET_GID` and mode `0750`, with role subprocess tests under `umask 077`. [Python mkdir/umask](https://docs.python.org/3.13/library/os.html#os.makedirs), [chown](https://docs.python.org/3.13/library/os.html#os.chown) and Compose `group_add` define the mechanism. Legacy rendering and runtime credentials are untouched. The Desktop bind remapped the directory to runtime UID 101, so this was not a reproduced runtime refusal there; packaged Linux tmpfs tests must establish the directory mode/GID independently. The first actual runtime failure was fixture publisher filenames `client.*` instead of SDK `publisher.*`; preserve it separately and correct only disposable inputs.
