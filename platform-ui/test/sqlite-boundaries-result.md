## Среда и воспроизведение

Первоначальная проверка использовала собственный образ `aelev/platform-ui-checks:local` с read-only mounts актуальных `api.py` и `test`. Дополнение 2026-10-14 выполнено штатным `test/checks.py` в свежесобранном из текущего дерева образе с тем же именем; секреты, Docker socket, host `.env`, рабочие конфигурации и постоянные тома не передавались.

Из каталога platform-ui, при наличии этого образа:

```sh
docker run --rm --network none --read-only --tmpfs /tmp:rw,size=128m \
  --cap-drop ALL --security-opt no-new-privileges:true \
  -e PYTHONDONTWRITEBYTECODE=1 \
  --mount "type=bind,src=$PWD/api.py,dst=/work/api.py,readonly" \
  --mount "type=bind,src=$PWD/test,dst=/work/test,readonly" \
  aelev/platform-ui-checks:local \
  pytest -q -p no:cacheprovider test/test_storage_boundaries.py
```

Для полной регрессии уберите последний путь теста. Полный выполненный прогон дополнительно монтировал актуальные README/SPEC/CHANGELOG. Сборка собственного checks-образа из текущего выпуска описана в [README](../PROVIDER_OPERATIONS.md#проверки); новый образ в этой проверке не собирался. Для качества выполнены `black --check test/test_storage_boundaries.py`, `ruff check --no-cache test/test_storage_boundaries.py` и `mypy --cache-dir=/tmp/mypy test/test_storage_boundaries.py` в том же изолированном окружении.

## Версия движка и открытые ограничения

В использованном тестовом образе `sqlite3.sqlite_version` равна **3.49.2**. Разработчики SQLite описывают редкую WAL-reset race при одновременной записи/checkpoint через два или более соединения; исправление движка опубликовано в 3.51.3. [Официальное предупреждение](https://www.sqlite.org/wal.html#walreset). Принятый стек не менялся: API устраняет необходимое условие ошибки, сериализуя полное время жизни соединений одним `RLock`, а новая конкурентная регрессия это доказывает. Издатель имеет один последовательный цикл. Обновление движка до 3.51.3+ остаётся совместимым усилением, но не является единственной защитой текущей поставки.

Backup/restore проверен на настоящих временных файлах SQLite, созданных Pytest, не на рабочих томах и не на независимой целевой площадке. Реальные OIDC/TLS, браузер, stop/start инфраструктуры, нагрузка, WAN, отказ диска и целевые RPO/RTO в этом прогоне не проверялись. Принятие SQLite не объявляет эти эксплуатационные проверки пройденными.

Все временные файлы находились в tmpfs удалённых `--rm` контейнеров. Новые образы, именованные тома, пользовательские сети и записи в рабочий архив не создавались. Рабочие контейнеры, данные и identities сохранены.
