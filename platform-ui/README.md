# Platform UI

Операторская оболочка для разделов и технических состояний, опубликованных владельцами сервисов.

## Основные возможности

- Общий вход и навигация.
- Декларативный порядок функциональных разделов, задаваемый их владельцами.
- Изолированное встраивание самостоятельных UI.
- Единый версионированный `PlatformPage` и presentation CSS для самостоятельных и внедряемых UI; приложения добавляют только предметные блоки и локальные специализации.
- Раздельное отображение последнего владельческого состояния и свежести связи с его издателем.
- Отдельное локальное полномочие publisher CA с явной перекрывающей ротацией по 00-INFRA-20261106-0013-owner-certificate-lifecycle; в production используется внешний issuer.

## Запуск

После подготовки по [руководству](PROVIDER_OPERATIONS.md), из этого каталога:

```sh
docker compose config --quiet
docker compose up -d --no-build --pull never
```

Для совместного локального размещения с Keycloak используйте владельческий overlay после запуска IdP: `docker compose -f compose.yml -f compose.local-keycloak.yml ...`. Он подключает только API и одноразовую задачу к объявленной ingress-сети IdP; удалённый режим использует основной Compose и маршрутизируемый HTTPS endpoint. Первоначальная сборка, обновление и восстановление описаны в руководстве. При работе через общую инфраструктурную композицию не запускайте отдельный проект поверх тех же данных.

Корневая локальная композиция также включает `compose.local-bridge.yml`: тот же TLS endpoint оболочки публикуется только на private IPv4 gateway стандартного Docker bridge, чтобы самостоятельные status publishers достигали его через `host.docker.internal`. Основной listener остаётся отдельным; wildcard/LAN bind и отключение TLS не используются.

UI-сборка устанавливает security patches в принятой Alpine 3.22 и работает под UID 101. CI сохраняет scan/SBOM фактического image ID по [общему правилу проверки образов](../docs/security/supply-chain.md).
