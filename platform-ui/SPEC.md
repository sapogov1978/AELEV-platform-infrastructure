# Platform UI — нормативная спецификация

Сборка Nginx UI устанавливает доступные security patches из принятой ветки Alpine 3.22, сохраняя прежний закреплённый базовый образ и приложение. Конечный пользователь — UID/GID 101; временный build-root не становится runtime user. Фактический image ID, состав пакетов и High/Critical gate подтверждаются [image evidence](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/docs/security/supply-chain.md).

Внешние ссылки и внедряемые разделы имеют строго ограниченное исключение HTTP для точных loopback hostname по [00-INFRA-20261106-0007-workload-and-operator-identity](../docs/adr/00-INFRA-20261106-0007-workload-and-operator-identity.md), [00-INFRA-20261106-0007-workload-and-operator-identity](../docs/adr/00-INFRA-20261106-0007-workload-and-operator-identity.md) и [каноническому контракту](../docs/api/platform-ui-injection.md#ссылки-на-собственные-интерфейсы). Это адрес станции браузера, не произвольный сетевой адрес; все ограничения sandbox и самостоятельная целевая авторизация сохраняются. Оболочка не определяет режим чужой установки, не подключается к её API и не передаёт свою сессию.

Присутствие собственного издателя, штатная подтверждённая отписка и потеря связи определяются только [каноническим UI-контрактом](../docs/api/platform-ui-injection.md#присутствие-и-штатная-отписка) и 00-INFRA-20261106-0008-platform-ui-owner-injection. Отписка скрывает модуль без удаления журнала или изменения ревизии; отсутствие публикаций без отписки оставляет строку с потерей связи. Повтор и восстановление сохраняют владельца, UUID, последовательность и точные неподтверждённые байты.

При потере связи API сохраняет эффективное `state=UNKNOWN`, но добавочно возвращает последнее `reported_state` владельца. Оболочка показывает его обычным цветом вместе с отдельным красным сообщением «Нет связи с издателем» и прежним `observed_at`; последнее наблюдение не выдаётся за текущее состояние, а отказ издателя не подменяется утверждением о полном отказе сервиса.

Собственная optional-роль `ui` инъектирует nginx, API и издатель через тот же авторизованный JWT/mTLS API, не через прямую запись SQLite. Она не знает других владельцев или Docker metadata и не является зависимостью запуска оболочки. Nginx и API реализуют [единый контракт живости и готовности](../docs/api/health-readiness.md), а издатель проверяет API только по owner-unique адресу `platform-ui-api`. Полностью выключенный приёмник не может доставить свежий собственный отчёт: ранее открытый браузер показывает неизвестность связи, после восстановления принимаются точные сохранённые байты и новые наблюдения. Публичная библиотека `aelev-platform-ui-client` распространяется отдельным версионированным wheel и закрепляется SHA-256 внутри каждой собственной поставки; библиотека не содержит каталога продуктов, их моделей или проб и не создаёт общего runtime-образа.

Каноническое решение — [00-INFRA-20261106-0008-platform-ui-owner-injection](../docs/adr/00-INFRA-20261106-0008-platform-ui-owner-injection.md), модель и совместимость — [контракт инъекции](../docs/api/platform-ui-injection.md). Этот документ не создаёт второго определения контракта.

Ссылки «Открыть» предоставляются только владельцем по [добавочному контракту](../docs/api/platform-ui-injection.md#ссылки-на-собственные-интерфейсы); компоненты не наследуют адрес группы. Функциональный модуль с внедрённым UI открывает здесь только Swagger. Обычная человеческая identity — только `platform-operator`; отдельная вкладка автоматически получает собственный token владельца через PKCE и общую Keycloak SSO-сессию, но не получает token, ссылку на родительское окно или Referer от оболочки. Целевая проверка audience/ролей и mTLS сохраняется. Без ссылки нет кнопки и нет попытки обнаружить UI из продукта, порта или сетевой пробы.

Оболочка отвечает только за навигацию, единый версионированный CSS, вход, показ присланных названий/разделов и технического состояния. Свежий владельческий `OFFLINE` показывается оранжевым как ограниченная доступность, а красный используется только при `connection=LOST`; цвет не изменяет присланное состояние и не выводит причину самостоятельно. Встроенный перечень участников, обнаружение контейнеров, proxy предметных API, доменные формы и команды запрещены. Канонический UI и его поведение принадлежат издателю. Географическое размещение не требует общего диска, сетевого bridge или исходников соседнего каталога.

В левом меню «Подключенные сервисы» видны только описания с явно опубликованным владельцем `service_kind=FUNCTIONAL` и непустым списком разделов; инфраструктурные, неопределённые и функциональные описания без страниц остаются на странице состояния. Единственный раздел отображается одной кнопкой с названием сервиса, а название самого раздела в меню не дублируется; вложенные кнопки появляются только для нескольких разделов. Необязательный `navigation_order` сортирует функциональные модули по возрастанию, отсутствие означает обычное значение `0`, а равные значения стабилизируются по `module_id`. Оболочка не рисует над iframe ещё один заголовок модуля или раздела: страницу называет собственный UI владельца. При смене категории открытый раздел закрывается. Правила необязательных полей, ревизии и совместимости определены только в [каноническом контракте](../docs/api/platform-ui-injection.md#инъекция); категория и порядок не являются разрешением и не выводятся из конкретного продукта.

API принимает описания и состояние после проверки JWT/mTLS, сохраняет неизменяемое владение субъектом, ревизии, последовательности и технический журнал. WAL/FULL фиксирует изменение до ответа. Отзыв оставляет tombstone; повторное создание требует более новой ревизии и не оживляет старое состояние. Свежесть измеряется по исходному `observed_at`, отсутствие/устаревание даёт `UNKNOWN`. Ошибка чтения браузером также не доказывает `OFFLINE`.

По [00-INFRA-20261106-0006-technical-storage-boundaries](../docs/adr/00-INFRA-20261106-0006-technical-storage-boundaries.md) SQLite является разрешённым встроенным техническим хранилищем: база API и журнал издателя находятся в разных собственных постоянных томах, без межсервисных mounts или общего файла через WAN. Декларация принадлежит издателю, но принятые ревизии/sequence, защита владения, tombstone и журнал приёмника требуют его согласованного backup; повторная публикация их не восстанавливает. Журнал издателя сохраняется отдельно с UUID, точными неподтверждёнными байтами и намерением отписки. Подготовка совместимой схемы до обработки принадлежит версионированному выпуску владельца и не разрешает DDL в PostgreSQL runtime. API является единственным процессом-писателем и сериализует полное время жизни SQLite-соединений, включая checkpoint; эта проверяемая инварианта исключает необходимое условие известной WAL-reset race SQLite до 3.51.3 без смены принятого Python/OS-стека.

Состав сервиса объявляет только владелец по [добавочному контракту](../docs/api/platform-ui-injection.md#составные-компоненты). На странице состояния это раскрываемая группа с отдельными показаниями и временем каждой части. Неизвестное или просроченное состояние не наследует доступность родителя. Отдельных identities, обнаружения, полномочий управления и вложенных функциональных разделов состав не создаёт; обычные публикации без состава совместимы.

Единым индикатором в шапке слева от кнопки состояния управляет текущий открытый источник по [00-INFRA-20261106-0008-platform-ui-owner-injection](../docs/adr/00-INFRA-20261106-0008-platform-ui-owner-injection.md). На странице состояния это собственный API оболочки; в сервисном разделе — его UI через технический `AELEV_UI_REFRESH` из [канонического контракта](../docs/api/platform-ui-injection.md#общий-индикатор-получения-данных). Принимаются только сообщения точного текущего iframe/origin с новой последовательностью и допустимыми полями. Ошибка и загрузка сохраняют прежнее время успеха, переключение раздела или новая загрузка iframe сбрасывает показания, а фоновый ответ API оболочки не перезаписывает их в открытом сервисе. Интервал берётся у текущего источника, для `60` секунд показывает обновление раз в минуту; до первого сообщения владельца неизвестен. Опрос собственной страницы выполняется последовательно с паузой после завершения запроса. Индикатор не гарантирует точную минутную доставку, не меняет `observed_at` состояния и не передаёт доменные данные или права.

Индикатор не приравнивает HTTP-успех к полноте состояний: пустой список и неизвестные состояния имеют отдельные незелёные показания. Время без дополнительной подписи обозначает приём метаданных; исходные времена владельцев остаются в строках. Отметка успеха истекает по часам браузера без нового сетевого ответа по [каноническим правилам свежести](../docs/api/platform-ui-injection.md#общий-индикатор-получения-данных); право активного iframe и защита от чужих сообщений сохраняются.

Страница владельца открывается только на отдельном origin в sandbox: HTTPS обязателен для remote/production, точный loopback HTTP разрешён локально. Её DOM, авторизация и команды не принадлежат оболочке. Platform UI является единственным источником базовой разметки, классов и оформления: публичный `/presentation/v6.css` с SHA-256 и выпущенный из того же каталога `@aelev/operator-ui-kit` 0.1.4 предоставляют один `PlatformPage`; его автономный `presentation.css` побайтно совпадает с публичным артефактом, а точные путь и digest экспортируются SDK и не дублируются в bridge-коде владельцев. Приложение-владелец передаёт компоненту предметное содержимое и добавляет только собственные сетки, метрики, технические и опасные действия; канонический presentation-слой применяется после локальных специализаций как в самостоятельной сборке, так и после проверенного внедрения. Изменение общих правил требует новой неизменяемой версии presentation и SDK; `/presentation/v1.css`–`/presentation/v5.css` остаются доступными без изменения байтов. Протокол `postMessage` передаёт только оформление, язык и технические показания индикатора, проверяя точные origin/source. Bearer/refresh-токены, пользовательские данные и команды не передаются. Отключение страницы уничтожает iframe; последовательный опрос метаданных не накладывает запросы.

Владельческий `/presentation/v6.css` передаётся точному iframe через `AELEV_UI_CONTEXT`, но не подключается к DOM самой оболочки. Оболочка сохраняет собственные левую навигацию, компоновку страницы состояний и геометрию iframe; глобальные селекторы владельческого артефакта не могут переопределять эти элементы.

Одна поставка — непривилегированный nginx и Python API, один собственный постоянный том и явная задача provision. Сборка использует только свой каталог, env содержит только свои обязательные настройки; конфигурация runtime производна и подготавливается проверяемым генератором. Отсутствие переменной, файла доверия или роли не даёт резервного plaintext/анонимного пути. IdP может быть удалённым; API и provision проверяют HTTPS CA/SAN. Подробности установки, ограничений, восстановления и всех параметров находятся в [README](README.md).

`/healthz` оболочки проверяет только живость её nginx и остаётся Docker-пробой, поэтому отказ API не вызывает бессмысленный перезапуск живого nginx. `/readyz` оболочки защищённо проксирует точный `/api/readyz` владельческого `platform-ui-api`: оболочка не считается готовой к обслуживанию страницы состояний без собственного приёмника метаданных. Постоянные роли `platform-ui`, `platform-ui-api` и `platform-ui-status-publisher` явно допускают первоначальную точную регистрацию в единственном контроллере 00-INFRA-20261106-0010-bounded-recovery-and-process-control; native-политика остаётся `no`, а пересоздание требует передачи прежней истории через штатный `replace`.

По [00-INFRA-20261106-0004-self-contained-service-delivery](../docs/adr/00-INFRA-20261106-0004-self-contained-service-delivery.md) собственная задача называется `platform-ui-configuration-init` уже в сервисном Compose. Корень включает ту же модель без переименования, изменения зависимостей или повторного runtime.

Установка конкретного владельца не меняет код, env и образ оболочки. Технические описания — производная рабочая копия с источником, владельцем и процедурой повторной публикации; доменные данные в том не поступают. Масштабирование API-писателей поверх отдельных SQLite не поддерживается; утверждение о высокой доступности не делается. Локальная PKI и тест не закрывают production-допуск, ротацию, WAN или резервное восстановление.

По [00-INFRA-20261106-0013-owner-certificate-lifecycle](../docs/adr/00-INFRA-20261106-0013-owner-certificate-lifecycle.md) локальный publisher CA сопровождает только оператор Platform UI. `publisher_authority.py prepare` создаёт отдельное 365-дневное поколение без автоматической активации, а `stage` расширяет входной `publisher-ca.crt` старым и новым корнем и никогда не удаляет прежний. Leaf конкретного издателя выпускает отдельная owner-задача с 90-дневным сроком и 30-дневным окном; потребитель получает только публичный leaf и квитанцию через свой проверяющий helper. Runtime Platform UI и издателя не получают CA key. Production использует внешний PKI/KMS/HSM/Vault, а локальные команды закрыто запрещены.

## Устойчивый журнал и конечное восстановление

Образ собственного издателя закрепляет SQLite 3.53.4 из публичного образа транспортной библиотеки по digest, сохраняя Python 3.13.7, Alpine 3.22 и клиент Platform UI 1.1.1. У Platform UI это отдельная стадия `publisher`, не изменение работающего API. Перед заменой единственный писатель останавливается, полный собственный том с WAL сохраняется и проверяется старым и новым движком на изолированных копиях; UUID, последовательность и неподтверждённые байты должны совпасть.

`AELEV_INFRASTRUCTURE_PLATFORM_UI_UI_RESTART_POLICY` по умолчанию в примере равен `no`: новый экземпляр не получает автоматических попыток до проверки здоровья и регистрации либо передачи прежнего бюджета в [существующем ограничителе](../USER_MANUAL.md#ограниченное-восстановление-по-unhealthy). У ещё не переведённых целей прежний ограничитель использует оставшийся бюджет `on-failure:N`, при исчерпании — `no`. После явного перевода на 00-INFRA-20261106-0010-bounded-recovery-and-process-control native-политика остаётся `no`, а тот же хостовый контроллер выполняет ограниченные по частоте повторные попытки с сохранением накопленной истории. Значение env остаётся `no` для безопасного создания следующей инкарнации и не пересоздаёт уже зарегистрированную. Создание нового контейнера не обнуляет прежние попытки. Отказ наблюдаемого провайдера не является отказом живого цикла издателя.

## Лёгкая проба издателя

Docker-проба собственного издателя запускает `python -S /opt/platform-ui/publisher-health.py AELEV_INFRASTRUCTURE_PLATFORM_UI_` и читает только UUID и подтверждённый heartbeat собственного журнала `/var/lib/aelev-status/outbox.sqlite` в режиме только чтения. Проверка из закреплённого `aelev-platform-ui-client==1.1.1` не импортирует издатель или приложение и не выполняет HTTP/TLS-подключений; отсутствующий, чужой, устаревший или некорректный сигнал отклоняется. Прежние предел свежести `2 × UI_INTERVAL_SECONDS + 40 × UI_TIMEOUT_SECONDS`, интервалы и таймауты сохраняются. Это живость цикла, а не готовность провайдера или подтверждение доставки; порядок обновления — в [руководстве](USER_MANUAL.md#лёгкая-проба-издателя).
