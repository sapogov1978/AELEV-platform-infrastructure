# Контейнерный CLI ограниченного восстановления — 21 октября 2026

## Проверенный объём

Упакован существующий `recovery.py`, не второй контроллер. Итоговый локальный образ `aelev/recovery-operator:cli-20261021` закреплён как `sha256:1f57f50448e4a9e80cda8479856e4069046b70dc8986c87fca994edbd21766fe`. Python 3.13.7/Bookworm и Docker CLI 28.5.1 взяты из прежних закреплённых образов; новых библиотек, служб, таймеров рабочего стенда или runtime-привилегий не добавлено. Единственное изменение канонического алгоритма — вынесение существующего блока `suspend` в вызываемую функцию без изменения его действий.

Адаптер принимает только `status`, `suspend`, `replace` с точными fingerprints и daemon ID. Сохранены исходные пути Docker в журнале; внутри контейнера используется отдельная привязка транспорта. Отрицательные проверки исключают неизвестные цели, чужую инкарнацию/daemon, неполную область, reset/enroll/once/install, ссылки на журнал и запись без хостового окна. Клиент Advance составляет только запросы девяти собственных ролей и дважды сверяет источники; инфраструктурные исходники не импортируются.

## Реальные проверки Mac/Docker Desktop

Изолированная временная директория показала отсутствие общей блокировки `flock` между хостом и контейнером: контейнер смог взять свой барьер при удерживаемом хостовом. Поэтому для записи реализовано согласованное окно обслуживания точного существующего LaunchAgent. Исходные plist и скрипт проверяются; таймер останавливается, хостовый барьер удерживается до сверки завершения, затем возвращается тот же таймер. Неопределённый результат сохраняет его выключенным. Внутри ВМ socket принадлежит `root:0`, режим `0660`; его группа определяется отдельно, CLI сохраняет UID владельца журнала. Runtime socket не получает.

Первый изолированный кандидат отказал из-за отсутствия группы socket; его журнал сохранён. Второй выявил ожидание EOF при `docker start -ai`: исправлен протокол одной ограниченной строки JSON, отдельно покрытый регрессией. Задержка удаления тестового предшественника наблюдалась по тому же ID без повторного запуска Docker daemon; последующий вариант сценария сохраняет остановленного предшественника до завершения передачи. Эти пробы не являлись замером производительности или изменением рабочих бюджетов.

Итоговая реальная проверка `runtime/recovery-cli-proof-20261021-a3` использовала отдельный журнал и временный пользовательский таймер, не рабочий ограничитель. Daemon `03298cf0-4750-4cec-9409-07352f13e2d3`; предшественник `2a2298cd41f6b17fb819142ffafc4ead68480e5d7e345035b51977352e7f5883`, замена `922ffd43534f940e35bc2805126fb03407ae77335e7540e9527e0f76311a54bb`. Тестовая история намеренно содержала две попытки: после передачи осталось две израсходованных и одна доступная, native count 0, политика `on-failure:1`. Повтор вернул прежнюю квитанцию без дополнительного запуска CLI. Точный таймер восстановлен; после проверки временный таймер и его тестовые цели сняты, журнал и квитанция сохранены. В реальном опыте менялась инкарнация одного образа; смена image ID дополнительно проверена модульно.

## Регрессии и границы

Второй итоговый прогон `runtime/recovery-cli-proof-20261021-a4` также завершён: предшественник `37d1189262330494494a2954aeb2e387d19742ddc960a5f8ce184c3d5f187fc5` сохранялся остановленным до передачи, замена `970d8c4d0779650a10caf7bb05f33f6f03afe8a7b280057477e9f82327e254fd`. Повтор снова не запускал дополнительный CLI; бюджет остался 2/3, тот же таймер восстановлен. После проверки оба тестовых контейнера и временный таймер сняты с сохранением журнала. Оба положительных опыта использовали итоговый закреплённый образ.

- Ограничитель, контейнерный адаптер и хостовое окно: 50 тестов прошли, один прежний необязательный fault-прогон пропущен; Ruff, Black и Mypy строгого режима прошли для кода и тестов.
- Advance: 876 тестов прошли, 79 пропущены, 16 subtests прошли; Ruff, Black и Pyright прошли. Внешние PostgreSQL/Kafka/GPU-проверки, пропущенные без соответствующих входов, не объявляются повторно выполненными.
- Клиентский запрос и хостовое окно ещё требуется включить в полный установщик. Автоматический хостовый адаптер этой проверки — macOS, не доказательство Linux/Windows или двух физических машин.
- Рабочий журнал ограничителя, его LaunchAgent, роли Advance, данные, PKI, offsets и команды очередей не переключались. Полный перенос, общая остановка/очистка и обработка 100 сайтов этим этапом не выполнены.

Нормативный интерфейс и ограничения находятся в [SPEC](../SPEC.md#контейнерный-оператор-восстановления), команды и восстановление — в [руководстве](../USER_MANUAL.md#контейнерная-передача-прежнего-бюджета).
