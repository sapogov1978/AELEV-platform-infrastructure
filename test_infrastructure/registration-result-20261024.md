# Первоначальная регистрация в существующем восстановлении

Дата: 2026-10-24. Объём отдельно одобрен владельцем: добавить публичную регистрацию точного контейнера и подготовку прежней пользовательской задачи новой станции. Рабочая установка Mac и её таймер не переключаются. [SPEC](../SPEC.md#контейнерный-оператор-восстановления) определяет поведение, [руководство](../USER_MANUAL.md#первоначальная-регистрация-новой-установки) — публичный вход.

## Реализовано

`register` принимает полный fingerprint, не имя-шаблон или произвольный скрипт. Обязательна явная opt-in метка владельца для нагрузки без отдельного guard. Начальная healthy-проба, daemon и вся переданная область сверяются до записи; дубликат ID/прежней роли не создаёт новый бюджет. Устойчивый PREPARED предшествует прежнему `automatic_enable`, история native-попыток сохраняется. Завершённый повтор не снимает позднее удержание, не переводит старую постороннюю регистрацию и не запускает остановленную цель.

Нативный вход готовит только новый собственный закрытый журнал и прежнюю пользовательскую задачу; известный журнал использует прежний барьер обслуживания. Начальный контекст закрепляется до действий, неизвестное состояние не перезаписывается. Повтор COMPLETE не включает отключённый таймер. Docker socket остаётся только у оператора, не у регистрируемой нагрузки. Новых зависимостей, фонового алгоритма или канала оповещений нет.

## Доказательства

- Связанный набор `test_recovery*.py`, `test_automatic_recovery.py`, `test_restart_intent.py`, `test_cancel_suspend.py`: **212 passed / 1 skipped за 2,07 с**. Пропущен отдельный явно включаемый прежний Docker fault-тест. Новые проверки включают 0/2/3/19 прежних попыток, потерянный ACK, защиту suspend/ручного stop, чужую инкарнацию, отсутствие opt-in/пробы, повтор и Linux/Windows-ветви хостовой координации. Планировщики в новых программных тестах подменены; это не фактическая установка systemd/Task Scheduler.
- Ruff, Black и строгий Mypy трёх производственных модулей пройдены. Python 3.13.7, Bookworm и Docker CLI 28.5.1 сохранены.
- Окончательный локальный артефакт `aelev/recovery-registration-operator:20261024-r2`, ID `sha256:719def3c91501b374574548fc3ad2351c32260aea1ed76c5adf70a30b9147390`, собран из текущих исходников и имеет `io.aelev.recovery.registration=1`. Его публикация в удалённый registry этим не подтверждена.
- Реальный `registration_sandbox.py` прошёл на этом артефакте: scope `aelev-registration-test-74d1fe2f8cfe`, daemon `03298cf0-4750-4cec-9409-07352f13e2d3`. Одноразовый процесс сначала сам аварийно завершился; Docker действительно выполнил одну native-попытку. Публичный контейнерный CLI сохранил её в новой регистрации, отключил native-повторы без смены процесса, а повтор оставил журнал побайтно прежним. После ручного stop прежний core-проход и повтор регистрации не подняли контейнер. Отдельный хостовый таймер не устанавливался, рабочий журнал не читался.

Предварительный артефакт прошёл тот же сценарий отдельно, но окончательная квитанция выше относится только к R2. Две ранние попытки выявили ошибки самой фикстуры: tmpfs-флаг не переживает Docker restart; затем сигнал без обработчика не дал требуемого аварийного выхода PID1. Применён собственный обработчик тестового процесса и один явно проверяемый сигнал. Эти отказы не выдаются за сбой продукта или успешную проверку. Все созданные оболочки удалены по точным UUID/ID/образу; постоянные volumes/сети и рабочие данные не подключались. Предварительный собственный recovery-образ удалён после проверки отсутствия ссылок контейнеров; окончательный R2 сохранён. Удалённый артефакт можно пересобрать из исходников, рабочие образы не удалялись.

## Границы

Доступ к socket в опыте имел только доверенный одноразовый оператор с отдельным синтетическим журналом. Утверждение quiesced истинно потому, что для этого журнала нет хостового писателя; общий flock между macOS и Docker не предполагается. Физические Linux/Windows, регистрация реальной GPU-нагрузки, пользовательская задача и внешняя доставка этого образа на новую станцию ещё не проверены. Текущий Mac, его задачи, зарегистрированные рабочие цели и их история не обновлялись. Общая цель готовности этим этапом не объявляется достигнутой.
