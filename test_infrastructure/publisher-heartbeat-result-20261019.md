# Лёгкие пробы издателей: установка и проверка — 19 октября 2026

## Результат

По отдельно согласованному объёму [ADR-0113](../docs/adr/20261012-0113-infrastructure-plan-stability.md) адресно обновлены десять издателей Platform UI, Keycloak, Kafka, MinIO, Prometheus, Grafana, Loki, Tempo, OTel Collector и Blackbox Exporter. После обновления все 18 работающих издателей, включая ранее исправленные, используют прямой `python -S …/publisher-health.py` и находятся в `healthy`. У десяти обновлённых издателей нет рестартов после установки; последние пять штатных проб каждого из 18 успешны. Медиана последних 50 проб обновлённой десятки по Docker — 0,989 с; это измерение на данном стенде, не норматив и не обещание задержки под произвольной нагрузкой.

Из исходного Docker-снимка изменились только десять согласованных инкарнаций издателей. Нативные провайдеры, SQL/etcd, очереди, миграции, рабочие роли, secret-файлы и бюджеты восстановления этой процедурой не менялись. Два временных контейнера вне ролей выкладки завершились за интервал наблюдения; они не выдаются за часть сравнения постоянных поставок.

## Что установлено

Каждый владелец закрепляет собственный неизменяемый `aelev_platform_ui_client-1.1.1-py3-none-any.whl`, SHA-256 `6137c8f99afcbf317f9313b4ea739490564c8fe3a68892a811d323b0e29fb61b`. Во всех девяти существовавших зависимостях lock изменился только с клиента 1.1.0 на 1.1.1; Keycloak получил этот пакет впервые, без иных новых зависимостей. Runtime-образы собраны отдельно из канонических контекстов владельцев; версии и digest базового Python/OS не менялись.

Проба извлекается из закреплённого wheel при сборке и читает только UUID и подтверждённый heartbeat собственного журнала в read-only режиме. Для каждого из десяти образов до установки проверены свежий сигнал, отказ чужому UUID и отсутствие импортов SSL, сетевого клиента, потоков, SQLAlchemy и драйвера PostgreSQL. Проверка выполнялась без сети и второго писателя на существующем томе.

У Keycloak сохранены собственный `/var/lib/keycloak-status/outbox.sqlite` и предел свежести 100 с при действующих настройках; тонкий адаптер вызывает только автономную проверку, не меняя механизм публикации. У остальных сохранён прежний предел 260 с. Интервалы, таймауты и число неудачных проб не увеличены. Издатель самой оболочки получил отдельный обязательный `AELEV_INFRASTRUCTURE_PLATFORM_UI_STATUS_IMAGE`; основной API и его образ не обновлялись. Правила принадлежат собственным [SPEC Keycloak](../keycloak/SPEC.md#лёгкая-проба-издателя) и [SPEC Platform UI](../platform-ui/SPEC.md#лёгкая-проба-издателя), а не этому отчёту.

## Сохранность и доставка

До обновления сохранены собственные env и согласованные SQLite-копии всех десяти журналов. В каждом env изменён только параметр образа издателя; UUID, физические тома и значения собственных переменных runtime сохранены. Проверка значений выполняется по именам: изменение порядка элементов списка ENV само по себе не является изменением конфигурации. Первичный операторский скрипт ошибочно считал такой порядок расхождением после успешного запуска; повторная сверка значений и состояния подтвердила результат без перенастройки процессов.

Это проверяемая совместимая пересборка, не утверждение о побитовом восстановлении прежнего недоступного образа.

## Проверки и ограничения

- Все десять независимых runtime-сборок и проверки новых образов на существующих read-only журналах успешны.
- Полные pytest-наборы собственных публичных деревьев: 435 passed. Использовано уже собранное закреплённое тестовое окружение с Python 3.13, Docker CLI и одинаковыми выбранными dev-версиями; собственные деревья и выбранные публичные wheels монтировались read-only, без сети, Docker socket, env или секретов. Это способ локальной проверки, не новая зависимость сборок или runtime от соседнего сервиса.
- Собственные checks-образы дополнительно проверены для Platform UI, Keycloak, Kafka и Prometheus. Устранены отсутствующий источник автономной пробы в checks Platform UI и неполный публичный контекст checks MinIO; секретные файлы в контекст не включены. Длительные оставшиеся checks-сборки на этапе установки Docker CLI остановлены только как временные задачи проверки и не выдаются за завершённые успешные сборки; их полные pytest-наборы выполнены указанным выше способом.
- Отдельная реальная BuildKit-проверка MinIO `test/Dockerfile.publisher-context` подтвердила, что из `secrets` в контексте виден только публичный `README.md`. Контекст смонтирован read-only без копирования в слои и без сети; ключи и сертификаты не считывались.
- Ruff и закреплённый Black прошли для 11 новых Python-файлов; строгий Mypy — для адаптера Keycloak. `poetry check --lock` прошёл у всех десяти владельцев. Общая инфраструктурная Compose-композиция проходит `config --quiet`.
- Platform UI сообщает две предупреждающие записи об устаревающих тестовых интерфейсах Starlette/httpx и AnyIO; ошибок тестов нет, зависимости ради этих предупреждений не менялись.
- Проверены Markdown, ссылки и `git diff --check`. Аварийные испытания нативных провайдеров, SQL/Kafka-интеграции и испытания HA в этот объём не входили и не запускались.

Во время параллельных сборок зафиксирована одна просроченная проба издателя Grafana; процесс не перезапускался и heartbeat оставался доступным. После завершения проверок и остановки временных сборок последние 90 проб всех 18 издателей успешны. Это не объявляет устранённой общую нехватку ресурсов стенда: таймауты и защитные пороги сохранены, а результат локальной живости не подменяет [готовность зависимости](../docs/api/health-readiness.md) или подтверждение доставки. Команды `delivery.py health` у пяти отправителей и нативные проверки провайдеров не входят в согласованный объём десяти издателей и здесь не выдаются за изменённые.
