# Подтверждение аварийного выхода — 25 октября 2026

## Причина

У трёх остановленных процессов сохранённая история Docker была полной, но `die` опубликован на 3,132 / 3,045 / 3,956 секунды позже `State.FinishedAt`. Прежний оператор принимал только разницу менее двух секунд, затем сдвигал начало поиска за недоказанный выход. Поэтому возникала постоянная защитная блокировка `AUTOMATIC_EXIT_UNCONFIRMED` при наличии события. Чистое воспроизведение на установленном неизменяемом скрипте подтвердило отказ для задержек больше двух секунд; рабочий журнал этим воспроизведением не менялся.

Причины самих выходов отдельны: Zone worker исчерпал ограниченные SQL-повторы с `ZONE_SCHEDULER_STORAGE_RETRIES_EXHAUSTED`, Base delta-consumer — с `STORAGE_SERVER_RESTARTING` / `STORAGE_CONNECTION_FAILURE`, Advance sender — с `INGESTION_LISTENER_STALLED`. Исправление доказательства восстановления не выдаётся за устранение всех причин нестабильности PostgreSQL или планирования потоков.

## Исправление и проверки

Один прежний оператор теперь требует единственное согласованное событие той же наблюдавшейся инкарнации в полностью покрытом интервале; совпадающие записи журнала и хвоста объединяются. Ожидание события не теряет нижнюю границу, а вся граница повторно проверяется перед командой. Произвольного увеличенного секундного допуска нет. Два разных `die`, неверный код, новая инкарнация, ручные управляющие действия и разрыв истории запрещают запуск. Старые уже сдвинутые окна и защитные блокировки не исправляются автоматически. Норма принадлежит [SPEC](../SPEC.md#контейнерный-оператор-восстановления); ADR-0155, транспорт и интерфейсы не изменены.

Полный набор `test_infrastructure` — **326 passed / 1 skipped**. Проверены оба источника событий, задержки до 20 секунд, ожидание до прихода события, сохранение интервала, дубликаты, разные выходы, неверный код, ручные действия до/после доказательства, новая инкарнация и запрет неявного исправления старого окна. Black, Ruff, строгий MyPy изменённого оператора и проверок пройдены. Пропущен явно включаемый Docker-тест конечного legacy-бюджета `test_real_unhealthy_recovery_is_finite`; для этого изменения отдельно выполнен реальный сценарий событий ниже.

Реальный `recovery_events_sandbox.py` проверил два собственных временных контейнера без сети, рабочих томов и credentials: многострочный exec не ломает поток, вытесненный из Docker `die` сохраняется в журнале, аварийный процесс стартует ровно один раз, ручной stop не отменяется, посторонние ID не сохраняются. Обе созданные оболочки удалены самим проверяющим скриптом по точным ID. Ускоренные интервалы применялись только в его отдельном процессе.
