## Устранённые ошибки самой проверки

Первоначальные прогоны завершались FAIL: временная CA не имела обязательного для строгой проверки `keyUsage`, операторский TLS 1.3 завершался ошибкой handshake, а неверный порядок снятия проектов оставлял подключённую тестовую сеть. Исправлены расширения только временной CA, выбор допустимого TLS 1.2 только операторским драйвером и порядок очистки: сначала временный центр, затем владелец. Пустая сеть первого прогона удалена после отдельной проверки точной метки проекта и отсутствия подключённых контейнеров; Docker daemon не перезапускался. Заключительные прогоны на свежесобранном отправителе прошли полную очистку и сравнение исходного инвентаря.

Использован уже установленный операторский Python 3.14.8 с Playwright 1.56.0/Chromium; это не смена версии Python сервиса. Экспортёр, отправитель и реальные CLI-команды клиента выполнялись на закреплённом Python 3.13.7; модульные проверки/линтеры/типы также проверялись на 3.13.7. Клиент примера и настройки продуктов не ограничивались TLS 1.2; ограничение касается только драйвера с установленным OpenSSL 3.6.5. Исключение самоподписанного TLS в Chromium относится лишь к временному loopback-стенду, не к рабочему браузеру/системному хранилищу доверия.

Сборки показывали прежнее предупреждение Docker InvalidDefaultArgInFrom: обязательный ARG без запасного образа. Фактические аргументы переданы с закреплённым SHA-256, обе сборки успешны; запасное значение не вводилось.

## Очистка и ограничения

Во всех заключительных тестах исходные 73 контейнера и 51 работающий контейнер сохранены; собственные временные контейнеры, сети, тома/тестовый архив, токены, PKI и производные файлы удалены. Отдельные образы `aelev/grafana-onboarding-checks:20261012` и `aelev/grafana-onboarding-sender:20261012` удалены после проверки точных digest и отсутствия потребителей; их можно восстановить документированной сборкой. Сохранённые рабочие образы не удалялись. Остаются исходники, [читаемый сквозной отчёт](onboarding-result.md) и [снимок панели](onboarding-result.png).

Не проверялись WAN/географические области отказа, рабочая PKI/SVID и автоматическая ротация, длительная нагрузка, исчерпание/потеря диска, независимое резервное восстановление, доставка журналов и трасс. Публикация независимо поставляемого образа отправителя в утверждённый registry остаётся отдельным открытым пунктом поставщика; локальный проверенный образ не выдаётся за опубликованный production-артефакт. Права Edit папки не являются изоляцией чтения рядов общего Prometheus между арендаторами.

## Повтор проверки

Команды сборки/сквозного теста и требования к удостоверениям находятся в [USER_MANUAL](../USER_MANUAL.md#10-изолированная-сквозная-проверка), собственная сборка checks — в [README](../PROVIDER_OPERATIONS.md#проверки). Для checks с новыми примерами выполнены:

```sh
docker run --rm --network none aelev/grafana-checks:local pytest -p no:cacheprovider
docker run --rm --network none aelev/grafana-checks:local ruff check prepare.py status_publisher.py examples test
docker run --rm --network none aelev/grafana-checks:local black --check examples test/onboarding.py test/test_onboarding_example.py
docker run --rm --network none aelev/grafana-checks:local mypy --strict examples/owner-metrics/grafana_api.py examples/owner-metrics/exporter.py test/onboarding.py test/test_onboarding_example.py
```

Имя проверочного образа заменяется своим отдельным tag из команды сборки; оно не является новым обязательным рабочим образом. Секретные env и файлы в checks не включаются. Полные параметры и безопасные границы повторного сквозного запуска описаны в руководстве, не заменяются запуском этих модульных проверок.

## Повтор перед отправкой в main

2026-10-12 повторно собран checks из текущих файлов; точные команды CI `ruff check .`, `black --check .`, `mypy .` и `pytest -p no:cacheprovider` прошли: 25 тестов, 10 Python-файлов без ошибок стиля/типов. Дополнительно успешны все 3 регрессии оркестрации слоя observability. Проверены 23 предназначенных для коммита файла, 354 локальные ссылки, 59 якорей и синтаксис 15 shell-блоков. Проверочный образ использовал прежний закреплённый Python 3.13.7 и lock и удалён после проверки точного SHA-256/отсутствия контейнеров; рабочие образы/контейнеры не менялись. Сквозной сценарий повторно в этом этапе не запускался: его подтверждение и границы сохранены в отдельном onboarding-result.md, SQL/модельные проверки переводчика к этому изменению не относятся.
