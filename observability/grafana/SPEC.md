# Grafana: спецификация самостоятельной поставки

Ревизия 3 собственного описания содержит ui_url группы и server из публичных PUBLIC_HOST/PORT этого владельца. Кнопка открывает уже существующий интерфейс в отдельной вкладке по [каноническому контракту](../../docs/api/platform-ui-injection.md#ссылки-на-собственные-интерфейсы); внутренняя проверка готовности и права не меняются. Описание передаётся как точные байты; каталога продуктов в транспортной библиотеке нет.

По [00-INFRA-20261106-0009-independent-observability-and-telemetry](../../docs/adr/00-INFRA-20261106-0009-independent-observability-and-telemetry.md) единственный Compose владельца определяет нативный процесс, собственные данные, удостоверения, сеть, производные конфигурации и явную подготовку тома без сети/секретов. Родитель только включает эту модель. HTTPS-источники данных конфигурируются опубликованными адресами; общей Docker-сети между странами нет. Панели конкретных потребителей принадлежат их владельцам и доставляются административно, не обнаруживаются инфраструктурой.

Присутствие собственного издателя, штатная подтверждённая отписка и потеря связи определяются только [каноническим UI-контрактом](../../docs/api/platform-ui-injection.md#присутствие-и-штатная-отписка) и 00-INFRA-20261106-0008-platform-ui-owner-injection. Отписка скрывает модуль без удаления журнала или изменения ревизии; отсутствие публикаций без отписки оставляет строку с потерей связи. Повтор и восстановление сохраняют владельца, UUID, последовательность и точные неподтверждённые байты.

UI-часть публикует собственный UUID с типом `INFRASTRUCTURE`, без функциональных разделов; состав — `server` и `publisher`. Источник `server` — только собственный HTTPS readiness, `publisher` — выполнение собственного цикла. Общее состояние ONLINE допустимо только при положительном подтверждении всех частей. Чужие endpoints, хранилища и модели не читаются.

Поставка имеет собственные образ, Poetry lock, рабочие/одноразовые удостоверения и постоянный журнал. Отсутствие UI не останавливает нативный процесс; отсутствие другого продукта не останавливает этот издатель. Секреты не попадают в env, Git или лог. JWT/mTLS, повтор точных байтов, исходное время и последовательность соответствуют [каноническому API](../../docs/api/platform-ui-injection.md). Журнал не удаляется при обычной остановке; потеря журнала не позволяет начать последовательность заново под прежним UUID.

По [00-INFRA-20261106-0007-workload-and-operator-identity](../../docs/adr/00-INFRA-20261106-0007-workload-and-operator-identity.md) единственная обычная человеческая identity Grafana — `platform-operator`. Grafana владеет отдельным confidential OIDC-клиентом, точным callback, PKCE S256, аудиторией и realm-ролью `grafana.operator`; её строгое сопоставление выдаёт организационную роль `Admin`, не серверное право Grafana Admin, и отклоняет прочие identity. Оператор видит все панели владельцев и управляет организацией, а издатели панелей по-прежнему используют отдельные ограниченные service accounts. Локальная форма, Basic Auth и анонимный доступ отключены; начальный локальный администратор сохраняется только как аварийный/bootstrap-механизм. Platform UI не передаёт Grafana свой token; повторный вход даёт общая SSO-сессия Keycloak.

Публичное доверие OIDC и выданный confidential client-secret имеют разные файловые интерфейсы: `OIDC_CA_FILE` монтируется read-only как публичный PEM, `OIDC_SECRET_ROOT` writable только одноразовой задаче и read-only постоянной Grafana. Это не расширяет trust и не передаёт закрытый CA key.

Первичный локальный оператор `local-publisher.py` использует тот же Grafana Authorization Code/PKCE flow через Keycloak и проверяет фактические login и организационную роль. Он допускается только с явным `local|test` и HTTPS loopback origins с проверкой доверенной CA; перенаправления ограничены двумя заданными origins. Пароль читается из отдельного файла `0600`, cookies остаются только в памяти, Basic Auth не включается. Для новой папки создаётся отдельная identity Viewer с правом Edit только этой папки и токеном на 24 часа; при явном запросе первоначального правила — отдельная Admin identity с токеном на 15 минут. `retire-provisioner` проверяет точные ID/имя/роль перед её удалением, сохраняя publisher. Это операторские credentials, они не монтируются в runtime. Локальный интерфейс не заменяет production PKI/MFA и не встраивает каталог потребителей.

Перед изменяющим запросом закрытая квитанция фиксирует намерение с fsync. Результаты и token-файлы сохраняются без вывода секретов; существующий output запрещает повторную выдачу. Потерянный ответ или прерванная выдача требует сверки точного намерения оператором. Только завершение уже начатого отзыва может подтвердить отсутствие точной временной identity через read-only GET; неоднозначный POST автоматически не повторяется.

Операционные команды, смысл параметров, подтверждаемые границы и тесты определены в [README](README.md). [USER_MANUAL](USER_MANUAL.md) описывает административное подключение владельца и воспроизводимый нейтральный пример: определения метрик/панелей остаются у владельца, пример не включён в нативную поставку и не создаёт каталог потребителей. Локальная PKI/один Docker host не доказывают production PKI/SVID, географическую отказоустойчивость и WAN.

## Устойчивый журнал и конечное восстановление

Образ собственного издателя закрепляет SQLite 3.53.4 из публичного образа транспортной библиотеки по digest, сохраняя Python 3.13.7, Alpine 3.22 и клиент Platform UI 1.1.2. Перед заменой единственный писатель останавливается, полный собственный том с WAL сохраняется и проверяется старым и новым движком на изолированных копиях; UUID, последовательность и неподтверждённые байты должны совпасть.

`AELEV_INFRASTRUCTURE_GRAFANA_UI_RESTART_POLICY` по умолчанию в примере равен `no`: новый экземпляр не получает автоматических попыток до проверки здоровья и регистрации либо передачи прежнего бюджета в [существующем ограничителе](../../USER_MANUAL.md#ограниченное-восстановление-по-unhealthy). У ещё не переведённых целей прежний ограничитель использует оставшийся бюджет `on-failure:N`, при исчерпании — `no`. После явного перевода на 00-INFRA-20261106-0010-bounded-recovery-and-process-control native-политика остаётся `no`, а тот же хостовый контроллер выполняет ограниченные по частоте повторные попытки с сохранением накопленной истории. Значение env остаётся `no` для безопасного создания следующей инкарнации и не пересоздаёт уже зарегистрированную. Создание нового контейнера не обнуляет прежние попытки. Отказ наблюдаемого провайдера не является отказом живого цикла издателя.

## Лёгкая проба издателя

Docker-проба собственного издателя запускает `python -S /opt/aelev/publisher-health.py AELEV_INFRASTRUCTURE_GRAFANA_` и читает только UUID и подтверждённый heartbeat собственного журнала `/var/lib/aelev-status/outbox.sqlite` в режиме только чтения. Проверка из закреплённого `aelev-platform-ui-client==1.1.2` не импортирует издатель или приложение и не выполняет HTTP/TLS-подключений; отсутствующий, чужой, устаревший или некорректный сигнал отклоняется. Прежние предел свежести `2 × UI_INTERVAL_SECONDS + 40 × UI_TIMEOUT_SECONDS`, интервалы и таймауты сохраняются. Это живость цикла, а не готовность провайдера или подтверждение доставки; порядок обновления — в [руководстве](USER_MANUAL.md#лёгкая-проба-издателя).
