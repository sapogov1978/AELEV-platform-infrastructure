# otel-collector: спецификация самостоятельной поставки

## Локальная живость и восстановление

Постоянные роли создаются с `restart=no`. Автоматическое восстановление явно зарегистрированного экземпляра выполняет только существующий хостовый контроллер по 00-INFRA-20261106-0010-bounded-recovery-and-process-control; регистрация/замена сохраняет прежнюю историю, ручную остановку и защитные запреты. Этот режим не является бесконечным независимым restart-циклом Docker и не меняет зависимости или предметные очереди.

Собственный нативный образ сохраняет точный upstream и его ОС, добавляя только статическую пробу из закреплённого `aelev-native-health-1.0.0.tar.gz`. Она проверяет только собственный loopback TLS/HTTP-listener с прежними клиентскими удостоверениями и CA/SAN; DNS, внешних обращений и чтения тела нет. Общий дедлайн — три секунды, корректный окончательный HTTP-ответ подтверждает живость независимо от готовности зависимостей. Прежний защищённый readiness остаётся источником прикладной готовности.



По [00-INFRA-20261106-0009-independent-observability-and-telemetry](../../docs/adr/00-INFRA-20261106-0009-independent-observability-and-telemetry.md) единственный Compose этого владельца определяет нативный процесс без профиля, собственные конфигурацию, сеть, удостоверения, данные и явную подготовку тома, где он существует. Родитель observability только включает его без поправок. Защищённые адреса зависимостей настраиваются в собственном env и не требуют общей Docker-сети между узлами. Принимает и обрабатывает техническую телеметрию стандартными конвейерами. Устойчивая очередь экспортёров не заменяет исходный архив delivery.

Идентичность постоянных данных задаётся неизменным DATA_OWNER, а не текущим именем Compose-группы. Одновременные писатели запрещены; штатные stop/down не удаляют данные или журнал UI. Подготовка использует публичный закреплённый артефакт внутри собственного образа, не общий runtime. Секреты и производные runtime-файлы находятся только внутри поставки владельца.

Присутствие собственного издателя, штатная подтверждённая отписка и потеря связи определяются только [каноническим UI-контрактом](../../docs/api/platform-ui-injection.md#присутствие-и-штатная-отписка) и 00-INFRA-20261106-0008-platform-ui-owner-injection. Отписка скрывает модуль без удаления журнала или изменения ревизии; отсутствие публикаций без отписки оставляет строку с потерей связи. Повтор и восстановление сохраняют владельца, UUID, последовательность и точные неподтверждённые байты.

UI-часть публикует собственный UUID с типом `INFRASTRUCTURE`, без функциональных разделов; состав — `server` и `publisher`. Источник `server` — только собственный HTTPS readiness, `publisher` — выполнение собственного цикла. Общее состояние ONLINE допустимо только при положительном подтверждении всех частей. Чужие endpoints, хранилища и модели не читаются.

Поставка имеет собственные образ, Poetry lock, рабочие/одноразовые удостоверения и постоянный журнал. Отсутствие UI не останавливает нативный процесс; отсутствие другого продукта не останавливает этот издатель. Секреты не попадают в env, Git или лог. JWT/mTLS, повтор точных байтов, исходное время и последовательность соответствуют [каноническому API](../../docs/api/platform-ui-injection.md). Журнал не удаляется при обычной остановке; потеря журнала не позволяет начать последовательность заново под прежним UUID.

Операционные команды, смысл параметров, подтверждаемые границы и тесты определены в [README](README.md). Локальная PKI/один Docker host не доказывают production PKI/SVID, географическую отказоустойчивость и WAN.

## Устойчивый журнал и конечное восстановление

Образ собственного издателя закрепляет SQLite 3.53.4 из публичного образа транспортной библиотеки по digest, сохраняя Python 3.13.7, Alpine 3.22 и клиент Platform UI 1.1.2. Перед заменой единственный писатель останавливается, полный собственный том с WAL сохраняется и проверяется старым и новым движком на изолированных копиях; UUID, последовательность и неподтверждённые байты должны совпасть.

`AELEV_INFRASTRUCTURE_OTEL_COLLECTOR_UI_RESTART_POLICY` по умолчанию в примере равен `no`: новый экземпляр не получает автоматических попыток до проверки здоровья и регистрации либо передачи прежнего бюджета в [существующем ограничителе](../../USER_MANUAL.md#ограниченное-восстановление-по-unhealthy). У ещё не переведённых целей прежний ограничитель использует оставшийся бюджет `on-failure:N`, при исчерпании — `no`. После явного перевода на 00-INFRA-20261106-0010-bounded-recovery-and-process-control native-политика остаётся `no`, а тот же хостовый контроллер выполняет ограниченные по частоте повторные попытки с сохранением накопленной истории. Значение env остаётся `no` для безопасного создания следующей инкарнации и не пересоздаёт уже зарегистрированную. Создание нового контейнера не обнуляет прежние попытки. Отказ наблюдаемого провайдера не является отказом живого цикла издателя.

## Лёгкая проба издателя

Docker-проба собственного издателя запускает `python -S /opt/aelev/publisher-health.py AELEV_INFRASTRUCTURE_OTEL_COLLECTOR_` и читает только UUID и подтверждённый heartbeat собственного журнала `/var/lib/aelev-status/outbox.sqlite` в режиме только чтения. Проверка из закреплённого `aelev-platform-ui-client==1.1.2` не импортирует издатель или приложение и не выполняет HTTP/TLS-подключений; отсутствующий, чужой, устаревший или некорректный сигнал отклоняется. Прежние предел свежести `2 × UI_INTERVAL_SECONDS + 40 × UI_TIMEOUT_SECONDS`, интервалы и таймауты сохраняются. Это живость цикла, а не готовность провайдера или подтверждение доставки; порядок обновления — в [руководстве](USER_MANUAL.md#лёгкая-проба-издателя).
