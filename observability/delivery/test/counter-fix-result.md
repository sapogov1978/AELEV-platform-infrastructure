# Проверка исправления счётчиков и управления Prometheus

Дата: 2026-10-18. Согласованный объём — транзакционные счётчики, ограниченная остановка собственного Prometheus, безопасная диагностика и адресное обновление приёмника и одного согласованного отправителя. Архитектура, транспорт, Python 3.13.7, Alpine 3.22, закреплённый Prometheus v3.5.0, удостоверения, сроки хранения и доменные процессы не менялись.

## Причина и регрессии

До исправления приём и готовность повторяли `SUM(length(body)+1024)` по `records`; центральный журнал занимал около 298 МиБ. Проверки превышали 15 секунд, появлялись таймауты и `BrokenPipeError`. Остановка дочернего Prometheus при давлении ожидала SIGTERM без общего ограниченного перехода к SIGKILL.

Теперь счётчики обновляются триггерами в транзакции исходной записи; получение состояния не ждёт локальную блокировку писателя. Первичное восстановление использует порядок существующего индекса `pending(projected,kind,sequence)` без сортировки тел во временный диск. Неуспешный первоначальный вариант с сортировкой был обнаружен на копии реального архива до выкладки; рабочий журнал им не изменялся. Остановка дочернего процесса ограничена 30 секундами до SIGKILL и ещё 5 секундами ожидания; Compose оставляет время для штатного завершения.

- Итоговые проверки в собственной закреплённой контейнерной среде: **62 passed**.
- Проверки Compose и наблюдаемости согласованного отправителя: **19 passed**.
- Ruff, Black, строгий mypy и `git diff --check`: без ошибок; проверены 5 документов, 31 локальная ссылка, якоря и ограждения блоков.
- Регрессии проверяют прежнюю схему, старого SQL-писателя, точные счётчики после отката, повтор UUID, конкурентный приём на границе ёмкости, отсутствие чтения `records` в статусе, отсутствие сортировки при восстановлении, безопасные причины отказа, TLS-границу и ограниченную остановку собственного дочернего процесса.

Нативный тестовый запуск macOS не использовался как доказательство TLS-совместимости поставки: местный генератор создал сертификаты без необходимого расширения, которые его OpenSSL отклонил. В контейнерной среде поставки все TLS-проверки прошли без отключения проверки сертификатов.

## Сохранность и восстановление

Перед заменой остановлены только два технических писателя. Их исходные тома затем подключались к проверочному процессу только для чтения. Полная замороженная копия DB/WAL восстановлена, из неё через SQLite backup API созданы проверенные снимки; миграция выполнена на отдельных копиях. `PRAGMA integrity_check` возвращает `ok`; хеш всех полей каждой исходной записи до и после миграции совпадает.

| Центральный архив | 210 336 | 23 427 | 431 924 799 | 0 | `5d13db3a6e028e9c44a74c72a1452f53fac53ba0db2554854aff8378721ebb21` |
| Отправитель | 50 571 | 50 571 | 322 901 800 | 3 | `5afa16409fe50c1083b2172ff1a8e6742c61805817ffd5eecf3ee92aba16f15e` |

Копии и отчёты находятся вне Git в собственном `runtime/counter-fix-backups-20261018/verified-archive/` и `verified-sender/`: `snapshot.sqlite3`, `frozen/`, `restore-check/`, `verification.json`. Доверенными являются только эти два проверенных набора; прерванные предварительные попытки не считаются резервной копией. Технические журналы прежних контейнеров сохранены в том же родительском каталоге с ограниченными правами. Это локальные копии на том же Mac, не независимое резервирование площадки.

Максимум из десяти последовательных чтений счётчиков на копиях через Docker Desktop: 51,465 мс для архива и 26,435 мс для отправителя. Это проверка устранения сканирования, не WAN-нагрузочный допуск.

## Адресная выкладка и живое состояние

Обновлены только `aelev-infrastructure-delivery-1` и `aelev-base-screening-telemetry-sender-1`, соответственно до `aelev/observability-delivery:1.0.1` и `aelev/observability-sender:1.0.1`, без зависимостей, пересборки при запуске и загрузки образов. Сохранены прежние тома, сеть, секреты и настройки. SHA-256 `/opt/aelev/delivery.py` в обоих живых контейнерах совпадает с проверенным исходником: `c633ef48f2ea13adb9a3ab6fdcf2d04b34e233ce1ecee87f7bd061fb5e74827d`.

Общий инфраструктурный Compose не разрешается из-за отсутствующей `AELEV_INFRASTRUCTURE_PUBLIC_EGRESS_GATEWAY_TELEMETRY_SENDER_IMAGE` у соседнего владельца. Его настройки не менялись; приёмник обновлён через канонический Compose delivery с явным прежним проектом `aelev-infrastructure`, без второго писателя или удаления контейнеров, отсутствующих в выбранной модели. У отправителя использован его собственный действующий проект.

Фактический приём и доставка проверены существующей историей, без добавления контрольных пакетов в рабочий архив. Задолженность отправителя уменьшилась с 50 571 до 50 356. В центральном снимке стало 211 554 записей, из них 24 154 ещё не спроецированы: количество применённых пакетов выросло с 186 909 до 187 400. Входящий поток продолжался; полное погашение задолженности этим снимком не утверждается. Собственный Prometheus восстановил WAL и перешёл в готовность.

Рабочая очередь не получала `PAUSE`, `RESUME`, `RESET`, миграции или изменения offsets. При сверке 57 остальных контейнеров за окно наблюдения изменился ID `etcd-2`; команды этой задачи адресовали только два согласованных контейнера и собственные одноразовые проверки. Причина параллельной замены не устанавливалась и в результат этого исправления не включена.

## Границы доказательства

Неподтверждённые пакеты не удалялись, `replay` не выполнялся. Старые образы и исходные журналы сохранены для совместимого отката; одноразовые проверочные контейнеры удалились после завершения. PKI площадки, WAN, независимая резервная копия и длительная нагрузка этой проверкой не закрываются. В образах остаётся прежняя SQLite 3.49.2; подтверждение исправления WAL-reset по ADR-0115 остаётся отдельным ранее открытым требованием, а ОС и зависимости без отдельного согласования не менялись. Коммит и push не выполнялись.
