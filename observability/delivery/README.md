# Telemetry Delivery

Устойчивая доставка технической телеметрии от отправителя владельца к центральному приёмнику инфраструктуры.

Согласованный Sender LTS 3.13.5 сохраняет Python 3.13.7, Alpine 3.22 и SQLite 3.53.4. [Отчёт допуска](../../docs/audit/sender-lts-candidate-20261114.json) закрепляет подписанный main digest, обе архитектуры, повторные 131 native TLS/durability checks на каждой CPU, TSDB, сырые findings и точные границы проверенных конфигураций. Owner rollout и площадочная приёмка остаются отдельными этапами.

## Основные возможности

- Постоянные журналы пакетов и проверяемые подтверждения.
- Повторная доставка logs, traces и metrics после недоступности.
- Диагностика задолженности и состояния критических циклов.
- mTLS и сопровождение одобренных сертификатов.
- Сохранное обновление и восстановление архивов.

## Запуск

После подготовки по [руководству](USER_MANUAL.md), из этого каталога:

```sh
docker compose config --quiet
docker compose up -d --no-build --pull never
```

Отправитель устанавливается на стороне владельца по [отдельному разделу](USER_MANUAL.md#отправитель-на-узле-владельца-телеметрии).

Владелец может включить отдельный контроль собственной квитанции продления в readiness через необязательный [`certificate_renewal`](SPEC.md). Проверка не требует доступа к сертификатам или хранилищу другой роли.

Продление локальных удостоверений поддерживает OpenSSL 3.0 через CSR прежнего ключа и проверку неизменного scope; процедура и барьеры публикации описаны в [спецификации](SPEC.md#продление-локальных-удостоверений).
