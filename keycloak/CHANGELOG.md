# Changelog

- 2026-11-07: новый локальный TLS private key также получает `0640` в настроенной runtime-группе вместо недоступного контейнеру host-only `0600`. Публичные сертификаты остаются `0644`; существующий TLS-материал bootstrap не изменяет.

- 2026-11-07: новые локальные файлы административного и SQL-паролей создаются с `0640` в группе оператора, совпадающей с настроенным runtime GID контейнеров. Существующие секреты, значения и режимы не изменяются; production secret manager обязан доставить тот же group-readable контракт.

- 2026-10-27: серверный TLS переведён с legacy self-signed `CA:TRUE` leaf на `CA:FALSE` под отдельным десятилетним локальным CA и 90-дневное автоматическое продление. Сертификат и ключ теперь монтируются единым owner-каталогом `secrets/https`, чтобы атомарная замена inode применялась после обычного controlled restart/recreate; `ca.crt` содержит перекрывающее публичное доверие.

- 2026-10-26: устранён и адресно установлен тупик предварительной проверки при потере `AUTH_SESSION_ID` и `KC_RESTART`: один исходный OIDC-запрос создаёт штатную попытку, после проверки контекста выполняется единственный POST пароля. Исходный запрос своей вкладки сохраняется с привязкой к `client_data`, без полей credentials; MFA, чужой контекст и сетевые отказы не обходятся. Пройдены 66 Python-, 31 браузерная и 8 настоящих сквозных проверок. БД, пользователи, пароли, сроки и история восстановления сохранены. [Протокол](test/login-cookie-recovery-result-20261026.md).

- 2026-10-23: по отдельному разрешению завершена установка издателя с SQLite 3.53.4. При отсутствии исходного image ID сохранена закрытая файловая система остановленного предшественника без содержимого mounts; прежний Python проверен побайтово, полный журнал прочитан обоими движками. UUID/PKI/данные сохранены, sequence 26083 → 26088, прежний бюджет 0/3 передан штатным replace. Сам Keycloak и его БД не обновлялись. [Протокол](../test_infrastructure/publisher-sqlite-result-20261023.md#завершение-издателя-keycloak-по-отдельному-разрешению) явно фиксирует параллельные восстановления других ролей, не подтверждает стабильность всего стенда.

- 2026-10-23: собственный издатель использует SQLite 3.53.4 при прежних Python/ОС/SDK и явную конечную restart-политику. Полный журнал проверяется до замены; UUID, последовательность и прежний бюджет сохраняются. Проверка сборки не подменяет фактическую установку.

- 2026-10-19: подключена автономная read-only проба heartbeat из клиента Platform UI 1.1.1 без импорта издателя и сетевых подключений. Сохранены собственные UUID, журнал, пороги и интервалы; нативный провайдер и его готовность не меняются.

- 2026-10-18: добавлен `migrate_password_files.py` для переноса прежних env-паролей без смены значений: штатное разрешение Compose, отдельные файлы владельца, проверка совпадения, закрытый отказ для ссылок/чужих путей/неоднозначных записей, фиксация каталогов и атомарный env. На текущем стенде перенос выполнен и тема восстановления формы активирована без изменения ролей, сроков и JWKS. Все три компонента здоровы, издатель публикует `ONLINE`; остальные 113 контейнеров не пересоздавались. Пройдены 60 Python-, 19 браузерных и 6 настоящих сквозных сценариев. Подробности, первичные отказы и ограничения — в [отчёте](test/login-recovery-result.md).

- 2026-10-17: собственная тема `aelev` обновляет обычную попытку входа штатным GET до первого POST credentials; просроченная форма не расходует первую отправку пароля. Не меняются сроки, проверки OIDC/PKCE и остальные шаги входа; сетевой отказ или смена контекста блокируют POST без автоматического повтора. Минимальный realm выбирает тему сразу, а собственные `login-theme`/`provision` идемпотентно обновляют только `loginTheme` существующего realm без замены нестандартной темы. Добавлены браузерные регрессии и отдельная проверка реального истечения с синтетическим realm.

- 2026-10-14: полный recovery bundle фактически восстановлен в отдельные новые PostgreSQL и status volumes; проверены manifest, realm, UUID/sequence издателя, health и HTTPS OIDC discovery. Добавлен безопасный `--data-only` для rehearsal без публикации в рабочую Platform UI. После закрытия файловой доставки паролей и независимого восстановления продукт получил `PRODUCTION_READY`; проверки внешней PKI/DNS/WAN остаются допуском площадки.

- 2026-10-14: административный и SQL-пароли удалены из постоянных Compose environment. PostgreSQL использует `POSTGRES_PASSWORD_FILE`, Keycloak переносит значения отдельных secret files только в память процесса, provisioner читает собственный файловый секрет. Добавлен полный проверяемый recovery bundle: логический dump PostgreSQL, SQLite backup журнала издателя, realm, TLS/OIDC и парольные файлы с SHA-256 manifest; восстановление закрыто отклоняет непустую БД, существующий журнал, другой UUID и несовпадающий realm. Локальный запуск сохраняется на тех же образах и Compose.
