Кандидат исправления: ровно `GF_DATABASE_QUERY_RETRIES=5` в owner recipe. [Официальная настройка](https://grafana.com/docs/grafana/latest/setup-grafana/configure-grafana/#query_retries) описывает retries при locked SQLite; [закреплённый upstream 12.1.0](https://github.com/grafana/grafana/blob/v12.1.0/pkg/services/sqlstore/session.go) задаёт retryable-error filter, конечное число attempts и backoff. [Database config](https://github.com/grafana/grafana/blob/v12.1.0/pkg/services/sqlstore/database_config.go) подтверждает query default 0 и transaction default 5. Выбор предела 5 — продуктовая настройка, а не требование документации. Это candidate для следующей реальной qualification, а не доказанная гарантия отсутствия любых SQLite locks.

Scope проверен совместно с 00-INFRA-0009/0010 и inherited ADR-0115: собственный локальный volume, тот же image, неизменные endpoints/healthcheck, нативный transaction retry и recovery budget; перехода на WAL, общего SQLite volume или другого database backend нет. Прогноз до правки — 10–15 минут, затем 20–40 минут root qualification; полный gate/публикация остаются отдельными.
