# ADR-0065: Первый production-допуск classifier crawler

> **Происхождение standalone-редакции.** Источник: `docs/adr/20260930-0065-initial-production-classifier-admission.md`; SHA-256: `5331a723af47bc04dfed32aab8dc6836b1feb8b5e92cc886aea952de6c4033ce`; основание включения: цепочка замены. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Частично заменён ADR-0129: допуск classifier не применяется и не хранится в `base-screening`, но сохраняется у владельца модельной стадии
- **Дата:** 2026-09-30
- **Основание:** A5, A10, A12, ADR-0049, ADR-0057, ADR-0060, ADR-0063
- **Заменяет:** ADR-0062

## Контекст

ADR-0062 правильно определил classifier как асимметричный инструмент отрицательного отсева, но безусловно сохранял production-порог `10001` до неопределённого будущего критерия репрезентативности. Это превратило разумную предосторожность в бессрочную блокировку: оператор уже накопил естественные решения, четыре локально исполняемых и дообучаемых кандидата измерены на одном неизменяемом корпусе, но ни один выпуск не мог быть введён даже как ограниченный первый baseline.

Сравнение проведено на корпусе `68e97203-4451-5643-b50a-16ee8428320d` с digest `sha256:15e4185046017da1badff4f98791ce580da1bd74d5c4d5104ba1eedbb8553529`. Корпус содержит 168 документов из независимых семейств: `TRAIN` — 10 положительных и 98 отрицательных семейств, `VALIDATION` — 2 положительных и 21 отрицательное семейство, `HOLDOUT` — 3 положительных и 22 отрицательных семейства. Положительная проверка остаётся малой, поэтому она не обосновывает автоматическое принятие источников или окончательный выбор модели на все будущие данные, но позволяет ввести контролируемый отрицательный отсев с наблюдаемым откатом.

На одном корпусе сравнивались `Qwen3-Embedding-0.6B`, `paraphrase-multilingual-MiniLM-L12-v2`, `multilingual-e5-base` и `xlm-roberta-base` с отдельными нативными обёртками. MiniLM заняла первое место: при пороге `3622` она не отклонила ни одного положительного `HOLDOUT`-семейства, правильно отклонила 20 из 22 отрицательных семейств, дала 90,91% recall отрицательных семейств и снизила семейную операторскую нагрузку на 80%. Qwen также не дал наблюдавшихся ложных отказов, но правильно отклонил 14 отрицательных семейств; E5 и XLM-R дали по одному ложному отказу.

Зафиксированные в training job показатели времени MiniLM были искажены конкуренцией нескольких тяжёлых контейнеров за ресурсы. Отдельный offline serving-тест точного выпуска на 32 уже раскрытых `HOLDOUT`-входах длиной до 4000 символов дал 2,597 документа в секунду, p95 502 мс и p99 573 мс на одном экземпляре. Этот тест характеризует inference, но не обещает пропускную способность всего сетевого crawler и не отменяет горизонтальное масштабирование.

## Решение

Первым production classifier утверждается `paraphrase-multilingual-minilm-l12-v2-linear-binary-v2` на базе `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2@sha256:eaa086f0ffee582aeb45b36e34cdd1fe2d6de2bef61f8a559a1bbc9bd955917b` и калиброванной головы job `b7b5f333-18a1-58ff-a146-52c5139c4ea8`. Точное решение сравнения имеет id `daad648b-55b3-5855-8145-fee94f1b404b` и digest `sha256:2cb822de7441dad1455b1f12674920caefdd3adae2bf3f780066041bab843efa`.

Production-действие остаётся строго односторонним: `automatic_decision=true` разрешено только для `SUBJECT_MISMATCH` при confidence не ниже `3622`. Любой `SUBJECT_MATCH`, меньшая уверенность, ошибка, несовпадение версии или недоступность runtime означают воздержание и `RECHECK`; classifier не принимает источник автоматически.

Допуск хранится как отдельное неизменяемое решение `classifier-production-admission.json`. Оно ссылается на точные corpus, selection, job, trainer, base model, порог и serving-бенчмарк. Исторический результат `COMPARISON_SHADOW_RANKED` и его артефакты не переписываются: release worker может собрать production bundle из него только при полном совпадении с допуском, а categorical runtime повторно проверяет digest допуска, manifest, shadow-порог и `safetensors`.

MiniLM становится рабочим baseline, а не вечным победителем. Новые self-hosted и локально дообучаемые кандидаты продолжают проходить тот же model-agnostic корпусный цикл как challengers. Замена active release требует нового неизменяемого сравнения и допуска; результат нового эксперимента не меняет текущий runtime сам по себе.

После каждого пополнения естественных операторских решений новый корпус создаёт новый цикл. Любой подтверждённый ложный production-отказ является основанием немедленно отключить автоматические решения возвратом порога `10001` или отключением classifier config, сохранить случай как защитный контрпример и выпустить новый калиброванный release до повторного допуска.

## Рассмотренные альтернативы

1. Продолжать ждать неопределённого количества положительных решений. Отклонено: это не задаёт проверяемой точки принятия решения и сохраняет уже две недели фактической блокировки.
2. Автоматически принимать и отклонять сайты. Отклонено: три положительных `HOLDOUT`-семейства недостаточны для безопасного положительного допуска, а граница crawler не требует автоматического принятия.
3. Выбрать Qwen как более крупную модель. Отклонено для первого выпуска: при одинаковом корпусе она сняла меньше отрицательных семейств и потребовала существенно больше памяти.
4. Утвердить MiniLM как ограниченный baseline с точным порогом, аудитом и возможностью отката. Принято.

## Последствия

Положительные:

- crawler впервые получает исполняемый classifier вместо постоянного `NOT_CONFIGURED`;
- наиболее уверенные отрицательные случаи снимаются автоматически, а редкие и положительные случаи остаются оператору;
- утверждение полностью воспроизводимо по точным данным, артефактам и digest;
- дальнейшие эксперименты не блокируют текущую работу и не могут незаметно заменить active release.

Отрицательные:

- текущая положительная проверка мала и не даёт строгой статистической верхней границы редкого ложного отказа;
- порог `3622` специфичен для точной головы и корпуса и не переносится на следующий выпуск;
- production runtime требует отдельного CPU/RAM бюджета, иначе конкуренция с trainer и translator искажает задержку.

## Критерии проверки

- release bundle собирается только при полном совпадении production admission с сохранёнными corpus, selection, job и evaluation;
- runtime принимает admitted shadow-порог только при совпадении manifest, `safetensors`, bundle lock и digest admission;
- уверенный `SUBJECT_MATCH` всегда возвращает `automatic_decision=false`;
- `SUBJECT_MISMATCH` ниже порога, ошибка или недоступный runtime маршрутизируются в `RECHECK`;
- точный MiniLM runtime проходит healthcheck, аттестацию реальным запросом и атомарную активацию bundle;
- API состояния показывает exact active release и его bundle digest;
- откат не требует изменения данных корпуса или исторического решения сравнения.

## Миграция и откат

Release worker читает `AELEV_CRAWLER_CLASSIFIER_PRODUCTION_ADMISSION_PATH`, собирает content-addressed bundle, materializer экспортирует его, а точный MiniLM sidecar проходит аттестацию до перевода bundle в `ACTIVE`. После активации worker crawler получает конфигурацию версии `4.0.0` с exact `model_ref`, `bundle_digest` и Unix socket.

Для немедленного fail-closed отката переменная `AELEV_CRAWLER_CLASSIFIER_CONFIG` очищается или указывает на конфигурацию с недоступным exact release, после чего crawler возвращает неоднозначные случаи в `RECHECK`. Для функционального отката без остановки runtime выпускается новый admission с порогом `10001`; исторический bundle и его аттестация не удаляются.
