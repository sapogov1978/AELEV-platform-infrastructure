# ADR-0109: Операторский перевод через штатную Kafka-очередь

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261011-0109-operator-translation-through-kafka.md`; SHA-256: `f6c9aa0412bca18e86a20e0254e243a21617a245b51629c8d5cfa458b569b9b8`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по явному подтверждению оператора; частично заменён [ADR-0110](20261011-0110-translator-diagnostic-openapi-groups.md) только в размещении `GET /v1/status` в группе OpenAPI
- **Дата:** 2026-10-11
- **Основание:** A5, A10, A12, ADR-0001, ADR-0017, ADR-0096, ADR-0108
- **Частично заменяет (Supersedes):** [ADR-0096](20261009-0096-consumer-agnostic-scalable-translator.md) и [ADR-0108](20261011-0108-loopback-operator-http.md) только в запрете операторскому HTTP API принимать текст и возвращать перевод; частные пробы, межсервисная Kafka-граница и прочие требования сохраняются

## Контекст

Оператору нужен проверяемый Swagger-вход: исходный язык, целевой язык, обычная или приоритетная очередь и текст; ответ должен содержать настоящий перевод. Оператор явно подтвердил только собственный операторский вход через Kafka и отдельное право, не синхронный межсервисный API модели.

## Критерии выбора

- Задание проходит тот же consumer, устойчивую очередь, worker, модель и outbox, что и остальные задания.
- API не вызывает модель и не вставляет задания напрямую в БД.
- Нет новых постоянных контейнеров, topics, consumer groups, таблиц или контрактных событий.
- Чтение не предоставляет права отправки текста; операторское право проверяет сам владелец.
- Ожидание, размер входа и одновременная нагрузка ограничены; timeout не выдаётся за отмену или успех.

## Рассмотренные альтернативы

1. Прямой сетевой вызов MADLAD: отклонён, поскольку обходит очередь, сохранность и вычислительные ячейки.
2. Запись HTTP-задания непосредственно в очередь PostgreSQL: отклонена, поскольку обходит канонический Kafka-вход.
3. Новый сервис-мост или отдельная consumer group для каждого HTTP-запроса: не нужны; результат доступен внутри собственного хранилища владельца после подтверждённой публикации outbox.
4. Операторский POST через штатную очередь и ограниченное чтение своего результата: принято.

## Решение

Только операторский listener при явном `AELEV_INFRASTRUCTURE_TRANSLATOR_API_TRANSLATION_ENABLED=true` предоставляет `POST /v1/translate` с `source_language`, `target_language`, `queue` (`normal` или `priority`) и `text`. При `false` POST отсутствует в маршрутах и схеме; обычная HTTPS/mTLS-диагностика и Kafka-перевод не требуют IdP. Шаблон поставки использует `false`, без автоматического включения. Приватный HTTP listener сохраняет пять прежних операций чтения и не принимает перевод. В Swagger ровно три группы: `default` для health/readiness и `/v1/components`, `translator` для `/v1/status` и включённого операторского перевода, `metrics` для `/metrics`.

POST требует подписанного access token собственного публичного OIDC/PKCE-клиента и отдельной client role `operator-translate`. `operator-read`, удостоверение mTLS, права оболочки и машинного издателя не заменяют это право. Публичный клиент не имеет service account, implicit или password grant. В локальном режиме действует loopback-исключение ADR-0108; удалённый режим сохраняет HTTPS/mTLS, а POST дополнительно проверяет OIDC. Вход чужих сервисов остаётся только через Kafka.

Каждый POST — новое намерение оператора с новым UUID. API создаёт неизменяемые байты `TranslationRequested v1`, закреплённую ссылку модели, SHA-256 исходного текста и псевдонимизированную ссылку на actor; проверяет существующий экспортированный контракт и публикует один запрос с идемпотентным Kafka producer и `acks=all` в выбранный topic. Тот же POST не перепубликуется приложением автоматически. Другие клиенты сохраняют свои правила детерминированной идентификации. Повторный POST является новым намерением, а не HTTP-идемпотентным повтором прежнего.

API читает только результат созданного им запроса из своей PostgreSQL после `translation_outbox.state=PUBLISHED` и `published_at`, то есть после Kafka ACK результата. Проверяются `request_id`, digest точных исходных байтов, корреляция, языки, digest текста и выпуск модели. API не принимает чужой идентификатор для чтения результата, не раскрывает каталог заданий и не создаёт второй канонический источник. `SUCCEEDED` возвращает перевод; доказуемая ошибка результата возвращает 422, неверный результат — 502, неподтверждённая доставка — 503, истечение ожидания — 504. При перегрузке 429 выдаётся до публикации.

Предел текста — 12 000 символов, JSON — 262 144 байта, включая запрос без `Content-Length`. Обязательные собственные env задают время ожидания и число одновременно ожидающих запросов; отсутствующие или недопустимые значения останавливают запуск. Разрыв HTTP, 503 или 504 не отменяет уже опубликованное задание и не разрешает сообщить, что оно не было доставлено. Ответ ошибки содержит технический код и UUID, если намерение уже создано. Исходные тексты, переводы, JWT и пароли не попадают в обычные журналы.

## Последствия

Оператор проверяет настоящий путь перевода, выбирает приоритет и получает ответ без новой инфраструктуры. Цена — удержание ограниченного числа HTTP-запросов и дополнительные запросы к собственной БД; высокая очередь может превысить HTTP-срок. Вычисление после отключения браузера продолжается. Повторная отправка является новым заданием и может повторить вычисление. Сохранённые операторские задания следуют прежней политике данных, а учебные записи живой проверки не удаляются из рабочих Kafka-журналов ради очистки.

## Критерии проверки

- Приватный listener не имеет POST; модель не становится сетевым API.
- Нет токена — 401; только `operator-read` — 403; собственный `operator-translate` допускает перевод, но сам по себе не допускает чтение.
- Проверяются оба topic, ограничение входа и конкурентности, неподтверждённый ACK, timeout и точное соответствие результата.
- Настоящий Swagger проходит оба класса очереди; собственная БД подтверждает 100/0, `SUCCEEDED` и `PUBLISHED`.
- Прежние чтение, Compose, модель, схемы, данные и остальные контейнеры сохраняются.

## Миграция и откат

Добавить собственные `API_TRANSLATION_ENABLED`, `API_TRANSLATION_TIMEOUT_SECONDS` и `API_TRANSLATION_MAX_IN_FLIGHT`. Для включения установить `true`, доставить CA IdP также в HTTPS-поставку, собрать собственный образ и выполнить существующий `translator-api-provision`. Задача создаёт две отдельные client roles и назначает их только явно настроенному существующему `API_OPERATOR_USER`; прочие пользователи не получают новое право. Затем адресно обновить только `translator-api`. Миграций БД, новых topics и изменений экспортированных схем нет. Для отключения установить `false` и адресно пересоздать API; отдельно можно отозвать `operator-translate`. Для отката реализации вернуть прежний API-образ. Уже принятые задания завершаются штатными ролями, данные и журналы не удаляются.
