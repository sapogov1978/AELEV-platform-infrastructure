# ADR-0045: Только авторитетные данные IANA и ICANN для каталога и содержимого зон

> **Происхождение standalone-редакции.** Источник: `docs/adr/obsolete/20260828-0045-authoritative-zone-data-only.md`; SHA-256: `2204e9519f4f68cd3a9ca75195140fe89808ab14f11f6952087e30efd5fb2ea4`; основание включения: цепочка замены. - **Статус:** Заменён [ADR-0048](../20260831-0048-authoritative-domain-address-provenance.md)
- **Дата:** 2026-08-28
- **Основание:** A1, A3, A5, A6, A9, ADR-0038

## Контекст

Открытый AXFR-вход Internetstiftelsen был допущен как поставщик делегаций
`.se` и `.nu`. Реальный прогон показал, что такой отдельный путь не даёт
достаточного основания считать полученный набор достоверным входом проекта и
создаёт несогласованный с официальным ICANN CZDS контур zone file. Он также
наполнил frontier нерелевантными сайтами и породил ложные предложения feeds.

## Решение

1. Официальные IANA endpoints, выполняемые в рамках функций ICANN, являются
   единственным источником состава корневых TLD и сведений об их делегации и
   менеджерах.
2. ICANN CZDS является единственным способом получения полного содержимого
   доступных проекту gTLD zone files. Каждая зона требует точного действующего
   `ZoneAccessGrant`, совместимых учётных данных и соблюдения минимального
   интервала получения.
3. Открытые AXFR-провайдеры не входят в поставляемый каталог и не активируются
   как `SystemDiscoverySource`. Добавление иного поставщика zone file требует
   нового ADR и проверки авторитетности, прав, полноты и происхождения.
4. Common Crawl, Certificate Transparency и собственный Web-граф остаются
   независимыми источниками адресов публичного Web, но не считаются источниками
   состава зоны и не подтверждают существование доменной делегации.
5. Ошибочные Internetstiftelsen source, запуски, техническое состояние зон и
   порождённые `.nu` предложения удаляются из активного PostgreSQL-контура.
   Неизменяемые исходные снимки не становятся активным источником и не
   используются повторно.
6. Официальный `icann/czds-api-client-python` используется как reference
   implementation протокола, но не как runtime-зависимость: это CLI-пример, а
   не библиотека, и он не владеет гарантиями проекта по точным разрешениям,
   частоте, gateway, checkpoint, digest и восстановлению.

## Последствия

- оператор видит один официальный путь получения zone file и не сравнивает
  несогласованные реестры;
- `.se` и `.nu` остаются строками официального каталога IANA, но без доступного
  ICANN-разрешения отображаются как зоны без подключённого содержимого;
- глобальное покрытие Web не зависит только от CZDS, поскольку Common Crawl и
  Certificate Transparency продолжают независимо добавлять адреса во frontier;
- тестирование `.com` использует только выборку из реально полученного
  разрешённого ICANN zone file.

## Критерии проверки

- каталог системных входов не содержит Internetstiftelsen;
- поставляемый каталог AXFR-провайдеров отсутствует;
- без CZDS credentials или точного разрешения zone file не получается;
- IANA, Common Crawl и Certificate Transparency продолжают работать независимо;
- в PostgreSQL нет crawler source, запусков, checkpoint, batch, availability и
  предложений, принадлежащих удалённому источнику или порождённых `.nu` обходом.
