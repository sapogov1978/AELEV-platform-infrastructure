# ADR-0108: Локальный HTTP для операторских интерфейсов с собственной авторизацией

Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по явному подтверждению оператора; частично заменён [ADR-0109](20261011-0109-operator-translation-through-kafka.md) только в запрете операторского перевода, [ADR-0111](20261011-0111-owner-operator-access-modes.md) только в запрете дополнительной собственной операторской роли нативного продукта и [ADR-0117](20261012-0117-loopback-http-embedded-ui.md) в запрете HTTP для внедряемого UI на точном loopback; остальные ограничения действуют
- **Дата:** 2026-10-11
- **Основание:** A10, A12, ADR-0017, ADR-0082, ADR-0101
- **Частично заменяет (Supersedes):** ADR-0101 только в обязательности HTTPS для внешних операторских ссылок на loopback; встраиваемые разделы, публикация метаданных и удалённые соединения сохраняют HTTPS

## Контекст

У корпоративного компьютера нет разрешения устанавливать собственный корень доверия и клиентское удостоверение. Операционный Swagger переводчика с обязательным mTLS завершается до HTTP, поэтому работающий контейнер не даёт оператору доступной страницы. Домена пока нет. Оператор разрешил ограниченное исключение для локального HTTP, но не отключение авторизации или обход корпоративных правил браузера.

## Критерии выбора

- Нет изменений системного доверия и новых постоянных контейнеров.
- Один сервисный Compose остаётся каноническим для обоих способов запуска.
- HTTP недоступен через опубликованный сетевой интерфейс за пределами loopback.
- Операторские запросы проверяются владельцем; токены оболочки не используются.
- Доменный обмен, удалённая безопасность и канонические данные не меняются.

## Рассмотренные альтернативы

1. Установка собственного корня и клиентского сертификата на корпоративную станцию: запрещена оператором.
2. HTTP на произвольном адресе, анонимный API или отключение проверки TLS IdP: отклонены.
3. Отдельный прокси или передача токена оболочки: не требуется и нарушает границу владельца.
4. Явный локальный HTTP на loopback и собственный публичный OIDC-клиент с PKCE: принято.

## Решение

Внешние `ui_url` и `swagger_url` технического UI-контракта могут использовать HTTP только с точным hostname `localhost`, `127.0.0.1` или `::1`. Имена поддоменов, сокращённые/целочисленные IP, иные сетевые адреса, учётные данные, фрагменты и неоднозначные URL запрещены. Это ссылки для отдельной вкладки, не разрешение HTTP iframe, проксирования, автоматического обнаружения или изменения издательского JWT/mTLS. Loopback относится к компьютеру браузера; для другого сервера требуется маршрутизируемый HTTPS-адрес.

Переводчик выбирает локальный режим явным `http` в собственном `API_PUBLIC_URL`. Он разрешён только при `ENVIRONMENT=local`, публикации обоих портов на loopback и собственном OIDC с проверенным HTTPS-доверием IdP. HTTPS остаётся прежним mTLS-режимом; ошибка TLS никогда не включает HTTP. Для локального Swagger не устанавливается серверное доверие или клиентский сертификат браузера. Статические страницы и схема доступны без токена, но каждая из пяти операций чтения требует подписанный access token с точными issuer, audience, authorized party, сроком и собственной ролью `operator-read`. Нет HTTP-входа перевода или административных команд.

Владелец поставляет отдельную идемпотентную задачу `provision`, создающую только собственный публичный OIDC-клиент с точным callback и origin, обязательным PKCE S256, без implicit/password grant и service account. Право чтения назначается явно настроенному существующему оператору; неизвестный чужой клиент не перезаписывается. Административные секреты не получает runtime. Swagger хранит токен только в памяти открытой страницы, не передаёт его оболочке и не сохраняет в URL или браузерном хранилище.

## Последствия

Локальный HTTP не шифрует трафик и предназначен только для доверенной локальной среды. Он не становится продукционным способом связи географически разнесённых узлов и не обходит запрет браузера на HTTPS IdP. Для удалённого доступа сохраняются утверждённые сертификаты, HTTPS и обычные права. Новых сервисов, версий Python/ОС и Kafka-контрактов нет.

## Критерии проверки

- HTTP на удалённом/неоднозначном адресе, вне `local` и при широком host bind не запускается.
- URL разделов iframe остаются только HTTPS; внешние loopback-ссылки валидируются API и браузером.
- Без токена операции дают 401, чужой/просроченный JWT — 401, отсутствие права — 403; недоступное доверие закрывает доступ.
- Настоящие Swagger, возврат PKCE и операция чтения проверяются без клиентского сертификата Swagger.
- Обычная и корневая композиции используют те же роли; очереди и прочие контейнеры сохраняются.

## Миграция и откат

Сначала обновляются API/образ оболочки, затем переводчик. Оператор задаёт HTTP loopback origin и OIDC, запускает собственный `provision`, увеличивает ревизию описания и адресно пересоздаёт API/издатель без удаления томов. UUID и sequence сохраняются. Для отката сначала возвращаются HTTPS origin и большая ревизия совместимым издателем, затем прежние образы. Сброс метаданных и передача сертификата издателя браузеру запрещены.
