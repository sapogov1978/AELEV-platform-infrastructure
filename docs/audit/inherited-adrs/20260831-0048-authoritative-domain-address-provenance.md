# ADR-0048: Авторитетное происхождение доменных адресов Discovery

> **Происхождение standalone-редакции.** Источник: `docs/adr/20260831-0048-authoritative-domain-address-provenance.md`; SHA-256: `dceb15d48b91aadb7b70a59ee66b3c864e2b3890f6630d991d15f1f60acbb7b3`; основание включения: цепочка замены. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Частично заменён [ADR-0136](20261015-0136-base-screening-authoritative-frontier-only.md): Base Screening не расширяет frontier ссылками сам, а экспертная стадия возвращает фактически наблюдённые домены временным zone file через Zone Ingestion; авторитетность первичного входа IANA/CZDS и запрет внешних каталогов сохраняются; прежняя общая терминология частично заменена [ADR-0152](20261019-0152-retire-discovery-registry-umbrella.md), остальные действующие решения сохраняются
- **Дата:** 2026-08-31
- **Основание:** A1, A3, A5, A6, A9
- **Заменяет:** ADR-0045 и правила первичного заполнения адресами из ADR-0038,
  ADR-0039, ADR-0043 и ADR-0044

## Контекст

Прежние решения разрешили Certificate Transparency, Common Crawl, поисковым
системам и внешним каталогам идентичности независимо добавлять доменные адреса
во frontier. Это ошибочно смешало авторитетный перечень делегаций с внешними
индексами, сертификатами и утверждениями третьих лиц. Такие наборы могут
содержать временные, удалённые, ошибочные или специально тестовые имена и не
являются источником истины о составе доступной проекту зоны.

Discovery должен уметь исследовать Web, но исследование начинается с точного
авторитетного происхождения и затем расширяется только наблюдаемыми ссылками.
Найденный таким способом сайт не получает предметной роли автоматически: даже
техническое или тестовое окружение может оказаться полезным и проходит ту же
содержательную оценку, что и любой другой адрес.

## Решение

1. IANA является единственным источником состава корневых TLD и официальных
   сведений об их делегации и менеджерах.
2. ICANN CZDS является единственным источником полного перечня прямых доменных
   делегаций в доступных проекту gTLD. Получение требует точного действующего
   `ZoneAccessGrant`, совместимых полномочий и соблюдения минимального интервала.
3. Первичный frontier доменных корней создаётся только из прямых делегаций
   разрешённого zone file. Сам каталог TLD адресов сайтов не создаёт.
4. После первичного чтения frontier расширяется только по URL, фактически
   наблюдённым в полученных документах: обычным ссылкам, sitemap, canonical,
   JSON-LD, RSS/Atom и явно опубликованным API или наборам данных. Переход может
   вести на другой домен; точное происхождение и родительский документ
   сохраняются.
5. Certificate Transparency, Common Crawl, Web Search, Wikidata и другие
   внешние индексы, реестры либо каталоги не добавляют и не подтверждают
   доменные адреса. Их специальные системные источники, автоматические worker и
   обогащение `P856` выводятся из исполняемого контура.
6. Если страница такого внешнего проекта встречена по ссылке внутри
   разрешённого Web-графа, она является обычной frontier-целью. Её название,
   известность, техническое назначение или прежнее присутствие во внешнем
   каталоге не повышают и не понижают оценку.
7. Прежние source versions, checkpoints, доказательства и происхождение
   сохраняются как история. Активные источники получают новую конечную версию
   `RETIRED`, их незавершённые запуски отменяются, а порождённые только ими цели
   закрываются кодом `UNAUTHORIZED_ADDRESS_SOURCE_RETIRED`. История не может
   снова активировать адрес.

## Последствия

- полнота первичного покрытия ограничена зонами, реально доступными учётной
  записи проекта через CZDS;
- поддомены и новые домены появляются только как наблюдаемое продолжение
  авторитетно начатого исследования;
- внешний индекс не может незаметно подменить источник доменного адреса;
- потеря внешнего поискового API, CT log или Common Crawl никак не влияет на
  работу Discovery;
- потенциально полезные тестовые и технические сайты не исключаются по имени,
  если они обнаружены разрешённым путём.

## Критерии проверки

- каталог `SystemDiscoverySource` содержит только официальный вход IANA;
- SEARCH worker получает только `IANA_TLD_LIST_V1` и
  `ICANN_CZDS_ZONE_V1`;
- без разрешённого CZDS zone file первичный доменный frontier не пополняется;
- URL другого домена, найденный на исследованной странице, сохраняется с
  родительским URL и допускается к обычной оценке;
- CT, Common Crawl, Web Search и Wikidata не имеют активных source versions,
  запусков или автоматического сетевого worker;
- прежние адреса этих механизмов не удалены, но не получают lease.
