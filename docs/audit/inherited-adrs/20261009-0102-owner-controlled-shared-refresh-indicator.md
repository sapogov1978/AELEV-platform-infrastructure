# ADR-0102: Единый индикатор получения данных под управлением открытого раздела

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261009-0102-owner-controlled-shared-refresh-indicator.md`; SHA-256: `92f95274747972f0eaf77fbb3bd52c0380318508db7c21f9726d9d14fe949232`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по явному уточнению оператора: индикатор один, любой сервис управляет им через инъекцию
- **Дата:** 2026-10-09
- **Основание:** A10, ADR-0082, ADR-0101
- **Частично заменяет (Supersedes):** ADR-0101 только в ограничении браузерных сообщений оформлением и языком; изоляция, владение, авторизация и запрет доменных команд сохраняются

## Контекст

Общий индикатор, отражающий только опрос API оболочки, не показывает получение данных открытым сервисным UI. Отдельные индикаторы в каждом разделе дублируют общую область управления. Оператор потребовал один индикатор в шапке с возможностью управления со стороны любого сервиса, без зашитого перечня участников.

## Критерии выбора

- один визуальный индикатор и один активный источник;
- владелец сам сообщает начало, успех и ошибку своих запросов;
- нет опроса предметного API оболочкой, передачи токенов или данных;
- неверный источник и устаревшее сообщение не управляют индикатором;
- смена раздела не наследует чужое время успешного получения.

## Рассмотренные альтернативы

1. Показывать только получение метаданных оболочкой. Отклонено по уточнению оператора: сервисные страницы не могут управлять индикатором.
2. Добавить отдельные индикаторы или опрос предметных API в оболочке. Отклонено: дублирование либо нарушение границы владельца.
3. Один индикатор со сменяемым источником и техническими сообщениями открытого iframe. Принято.

## Решение

На странице состояния источником индикатора является собственный API оболочки. При открытии внедрённого раздела источником становится UI его владельца; фоновый опрос метаданных оболочкой не перезаписывает показания этого источника. Интерфейс одинаков для любого владельца, без перечня продуктов. До сообщения нового раздела состояние и интервал неизвестны: оболочка не подставляет своё успешное время или интервал.

Браузерный контракт дополняется `AELEV_UI_REFRESH` по [канонической спецификации](../api/platform-ui-injection.md): версия, последовательность, фаза получения, время успешного ответа и интервал. Оболочка проверяет точные `event.source` текущего iframe и `event.origin` объявленного раздела, типы и порядок сообщений. Передаются только технические сведения, не команды, ошибки с содержимым ответа, пользовательские данные или токены. Ошибка и загрузка сохраняют прежнее подтверждённое время успеха; время владельца не заменяется временем приёма оболочкой.

Режим обновления определяется источником. Для 60 секунд единый индикатор сообщает обновление раз в минуту; для другого интервала показывает его действительное значение. Это не гарантирует точную минутную доставку при сетевой задержке и не меняет свежесть сообщения технического состояния из ADR-0101. Закрытие или смена раздела прекращают его право управлять индикатором.

## Последствия

Один индикатор служит любому подключённому сервису без изменения образа оболочки. Владельцам нужно добавить отправку технических сообщений; существующие страницы не объявляются автоматически подключёнными и продолжают работать без этого расширения. При отсутствии сообщения показывается неизвестное состояние, не ложная актуальность. Канонические данные и административные действия остаются у владельца.

## Критерии проверки

- ровно один индикатор на странице;
- загрузка, успех, ошибка и восстановление от произвольного UI;
- сохранение времени успеха при отказе и получение времени именно от владельца;
- отказ чужому origin, другому iframe, неверной версии и старой последовательности;
- смена раздела сбрасывает прежние показания, фоновые ответы оболочки не перехватывают индикатор;
- интервал отображается из сообщения источника; прежнее оформление/язык и авторизация не нарушены.

## Миграция и откат

Расширение добавочно: прежние сообщения `AELEV_UI_READY` и `AELEV_UI_CONTEXT` не меняются. Каждый владелец отдельно внедряет `AELEV_UI_REFRESH` в собственный UI; тест с произвольной страницей не подтверждает подключение реальных владельцев. Старые оболочки игнорируют неизвестный тип, отдельные UI остаются работоспособными. Данных в канонических хранилищах и Kafka-контрактах миграция не требует.
