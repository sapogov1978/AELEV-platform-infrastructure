# ADR-0141: Операторская разметка обучает модели только своего сервиса

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261016-0141-service-local-operator-training-data.md`; SHA-256: `072e5f2652663635b0954f2f60067d6e51827f51ace908a2d8c6de74a84bfb4d`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по явному уточнению оператора от 2026-10-16
- **Дата:** 2026-10-16
- **Основание:** A5, A10, A12, ADR-0082, ADR-0129, ADR-0140
- **Частично заменяет (Supersedes):** ADR-0084 и ADR-0085 только в разрешении использовать общий человеческий корпус для моделей разных сервисов; исторические результаты и ограничения качества сохраняются

## Контекст

Оператор отменил прежнее указание использовать разметку одного сервиса для обучения моделей других сервисов. Совпадение темы, URL, исходного текста, человека или архитектуры модели не переносит владение человеческим решением. Исторический общий эксперимент не является источником обучения нового самостоятельного Advance Screening.

## Критерии выбора

- единственный канонический владелец человеческого решения и воспроизводимое происхождение корпуса;
- отсутствие чтения чужой БД, общего обучающего журнала и скрытого переноса меток через Kafka;
- сохранение истории без выдачи чужого решения за собственное.

## Рассмотренные альтернативы

1. Объединять решения всех сервисов по теме. Отклонено явным решением оператора.
2. Скопировать чужие решения в свою БД и сменить владельца. Отклонено: копирование не меняет происхождения.
3. Обучать модели только на пригодных операторских решениях, принятых внутри их сервиса. Принято.

## Решение

Данные операторского обучения принадлежат сервису, в котором принято решение, и используются только моделями этого сервиса. Импорт, реплика, общая тема, общий оператор или переименование полей не дают другой модели права использовать эти метки. Передача материала по предметному контракту не передаёт обучающую метку: принимающий сервис может получить только собственное новое решение человека по этому материалу. Ответ модели, решение предыдущей стадии и ожидаемый ответ программного теста не являются человеческой разметкой получателя.

Корпус и манифест обучения фиксируют владельца меток и точные идентификаторы собственных решений. Неизвестный либо чужой владелец закрыто запрещает обучение; техническая готовность и положительные метрики не обходят эту проверку. Машинные прогнозы не создают человеческие метки. Внутри одного сервиса пригодная история не отбрасывается только из-за версии модели; требования точного критерия, семейств, независимой проверки и человеческого приоритета сохраняются.

Advance Screening использует только собственный `stage_operator_decision`, связанный с действующим человеческим решением собственного задания. Материал Base Screening остаётся допустимым Kafka-входом, но его маршрут и операторский вердикт не попадают в обучающие метки Advance Screening. Исторический общий корпус из 251 решения не переносится в новую модель. Данные не удаляются и не переименовываются ради миграции; старые выпуски остаются историческими, их допуск не расширяется.

Для первого выпуска оператор явно принимает решения по сохранённым входящим заданиям самого Advance Screening. При подтверждённом отсутствии модели интерфейс предлагает ручное действие для `PENDING/RETRY` без результата, включая нулевую попытку; автоматического переноса всего входа в `REVIEW` нет. Принятие или отсев записываются собственным журналом, человеческое принятие создаёт существующий `OPERATOR_ACCEPT`. Запись не содержит выдуманных модели, вероятности или машинной оценки. Пауза worker и независимая публикация сохраняются; число собственных решений является объёмом разметки, не допуском модели.

## Последствия и критерии проверки

Один сервис не получает холодный старт за счёт чужого журнала. Проверки подтверждают собственный источник, наличие владельца в корпусе и манифесте, отказ от чужого или неизвестного владельца и отсутствие прироста меток от входной передачи либо машинного ответа. Подготовка первого выпуска требует собственных пригодных данных и не разрешает выдуманную разметку.

## Миграция и откат

Межсервисные схемы не меняются. Новые корпуса содержат явный `label_owner`; старый незавершённый корпус без доказанного происхождения не обучается автоматически. Исторические корпуса и артефакты не переписываются и не удаляются. Откат не разрешает возобновить межсервисное обучение.
