# ADR-0066: Допуск classifier только для проверенных предметных профилей

> **Происхождение standalone-редакции.** Источник: `docs/adr/20260930-0066-profile-scoped-classifier-admission.md`; SHA-256: `f560a10ea8db2bb54a098ad86d4517165e81058764fc50d84322d43ced1429da`; основание включения: цепочка замены. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Частично заменён ADR-0129: профильный допуск не принадлежит `base-screening`, но сохраняется у владельца модельной стадии
- **Дата:** 2026-09-30
- **Основание:** A5, A10, A12, ADR-0057, ADR-0060, ADR-0065

## Контекст

ADR-0065 закрепил точные corpus, selection, job, модель и порог первого MiniLM-выпуска, но первоначальный исполняемый admission не перечислял предметные профили, представленные в корпусе. Поскольку classifier получает профиль как часть входа, технически тот же порог мог примениться после переключения оператора с прикладной области на логистику, недвижимость или другую ещё не проверенную предметную область. Результат такого переноса не измерялся и не имеет права автоматически отклонять материал.

Корпус первого допуска содержит двенадцать точных `profile_ref`, включая локализованные версии проверенной политики. Эти ссылки вычисляются из сохранённых запросов корпуса и могут быть проверены без повторного чтения сайтов.

## Решение

Каждый production admission classifier обязан перечислять отсортированный непустой набор точных `admitted_profile_refs`, в точности совпадающий с множеством профилей его неизменяемого корпуса. Bundle, release lock и runtime повторно закрепляют тот же набор.

Runtime выполняет inference для любого корректного профиля, чтобы сохранить диагностический ответ, но устанавливает `automatic_decision=true` только когда `profile_ref` входит в допущенный набор и одновременно выполнены остальные условия exact release. Для нового, изменённого или ещё не проверенного профиля ответ содержит `profile_admitted=false`, а crawler обязан выбрать `RECHECK` независимо от predicted label и confidence.

Усиление admission создаёт новый content-addressed bundle из тех же неизменяемых corpus, selection, job, артефактов головы и словаря. Предыдущий bundle переводится в `SUPERSEDED` только после аттестации нового runtime. PostgreSQL разрешает несколько исторических bundle одной selection, job, corpus и lexicon, сохраняя уникальность digest и единственного состояния `ACTIVE`.

## Рассмотренные альтернативы

1. Считать один порог универсальным для любой предметной политики. Отклонено: измерение одной предметной области ничего не доказывает для другой.
2. Запрещать inference для неизвестного профиля технической ошибкой. Отклонено: диагностический ответ полезен для будущей разметки, а безопасное воздержание уже является штатным результатом.
3. Ограничить автоматическое действие точными профилями корпуса и сохранить inference для остальных. Принято.

## Последствия

- смена предметной области не наследует право автоматического отказа от прежней политики;
- новая локализация профиля остаётся в `RECHECK`, пока не войдёт в новый корпус и admission;
- несколько bundle могут ссылаться на одни неизменяемые обучающие артефакты, но одновременно активен только один;
- `profile_admitted` становится обязательной частью categorical response версии `4.0.0` без изменения бинарных labels.

## Критерии проверки

- admission без непустого отсортированного набора SHA-256 `profile_ref` отклоняется;
- release worker сверяет этот набор с точными запросами корпуса;
- bundle, release lock и runtime имеют один и тот же набор;
- уверенный `SUBJECT_MISMATCH` неизвестного профиля возвращает `automatic_decision=false`;
- attestor проверяет `profile_admitted` и формулу автоматического решения;
- новый admission может создать новый bundle из прежних неизменяемых артефактов, а его активация сохраняет предыдущий bundle как `SUPERSEDED`.

## Миграция и откат

Alembic `20260930_0030` снимает прежние ограничения «один bundle на corpus/selection/job/lexicon», не удаляя существующие строки, и сохраняет уникальность `bundle_digest` и частичный уникальный индекс единственного `ACTIVE`. Admission schema `1.1.0` перечисляет двенадцать профилей первого корпуса. До активации нового bundle прежний runtime следует считать небезопасным для автоматических решений и отключить через `AELEV_CRAWLER_CLASSIFIER_CONFIG`; откат после активации также выполняется fail-closed отключением config, а не возвратом неполного admission.
