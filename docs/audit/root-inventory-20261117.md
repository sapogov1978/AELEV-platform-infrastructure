Внутренний root lifecycle использовал другую inventory, чем глобальный gate. Исправление сохраняет весь текущий список для preflight чужих писателей и owner cleanup; у каждого контейнера отдельно читает типизированный `HostConfig.AutoRemove`. Только `verify_preserved` допускает исчезновение явно временного baseline container. Постоянные running/exited контейнеры, networks, volumes и images по-прежнему обязательны. Новые собственные временные объекты по-прежнему входят в cleanup; auto-remove не позволяет оставить активный task или обойти чужой writer.

[Docker `--rm`](https://docs.docker.com/reference/cli/docker/container/run/#clean-up---rm) задаёт естественное удаление после выхода, [inspect](https://docs.docker.com/reference/cli/docker/container/inspect/) позволяет прочитать только ID/lifetime без env/logs. Batch projection получает максимум три read-only refresh после исчезновения между list/inspect; неверный bool, чужой/повторный/отсутствующий ID или неполная projection закрыто отклоняются. Snapshot не объявляется атомарным. Пул сети описан отдельно в [Docker bridge networks](https://docs.docker.com/engine/network/drivers/bridge/); рабочие endpoints, прежние сети и daemon ради повтора не менялись.
