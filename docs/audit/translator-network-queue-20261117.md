# Translator: сетевая очередь и ограниченный перевод — 17 ноября 2026

Две финальные native `linux/arm64` проверки одной и той же оснастки прошли: normal queue с контролируемым HTTPS fixture без ИИ и priority queue с выпущенным provider v0.2.1 и signed worker `03191fa`. [JSON receipt](translator-network-queue-20261117.json) закрепляет exact images, runtime/test hashes и hashes закрытых первичных файлов. [Сценарий и воспроизведение](../../translator-service/test/network-queue-qualification.md) описывают независимые SQL/Kafka/provider endpoints и пределы доказательства.

В обоих случаях реальный consumer принял Kafka v2 CloudEvent, реальный worker выполнил одну попытку и сохранил один checkpoint, SQL outbox сохранил результат. Первый publisher завершился с кодом 73 **после настоящего Kafka delivery ACK, до записи PUBLISHED**. Обычный outbox повторил те же bytes; затем точный повтор входного события ещё раз опубликовал прежний результат без нового вычисления. Получены три byte-identical wire records. У контролируемого fixture счётчик обращений равен одному. В live проверен один compute lease; полная test queue после его получения переведена в PAUSE, RESUME не выполнялся.

Такой crash point проверяет разрыв между Kafka ACK и отдельной SQL-транзакцией, который не устраняется одной настройкой producer idempotence — [Kafka delivery semantics](https://kafka.apache.org/39/design/design/#message-delivery-semantics). Worker/provider не имеют общего volume, клиенты используют опубликованные ports из разных bridge networks. SQL подтвердил TLS и точный client DN `/CN=queue-owner`; `verify-full` сохраняет [CA и hostname verification](https://www.postgresql.org/docs/17/libpq-ssl.html). Kafka broker/controller и runtime clients требуют mTLS; normal/priority/outbox используют собственные сертификаты и явные ACL, без runtime superuser.

Live request взят из целого `request.input.policy.subject_area` сохранённого реального задания: 286 символов, `en → ru`, без обрезки или замены синтетическим примером. Сохранены original-file hash, policy reference и job reference. Ответ за 5 360 ms сохранил модальность возможности, весь перечень областей и три класса исключений; добавлений, потери отрицания или исключения при ручном сравнении не обнаружено. `MACHINE_TRANSLATION_UNVERIFIED` остаётся в ответе. Private quality review закрепляет request SHA-256 `d79f668790bdd20ab884df8c1cf264db0bc019dae52c17591df20d10bf7e9318` и result SHA-256 `44036ed920a09b7f02c3d09cebfe8410e3149d31ad42a38d8d4e51eae595a7cf`. Это проверка конкретной пары, а не независимая лингвистическая аттестация или исполнение текущей политики через Policy Management.

Прогноз до реализации был 60–90 минут для driver и 20–30 минут для отдельного live request; corrective scopes объявлялись отдельно. Сохранены неудачные прогоны оснастки: AutoRemove race до effects; анонимный controller при включённых ACL; ошибочный формат source digest; неверное имя Confluent enum; ожидание DN без slash; неподдерживаемый target code первого live input. Последний запрос отклонён provider до model dispatch. Ошибки не превращены в PASS и не потребовали изменений продуктового runtime, стека или релизов. Финальные normal/live receipts имеют одинаковые четыре test-source hashes, которые не менялись во время этих прогонов.

Прошли 23 существующих provider transport regression tests, Black/Ruff и strict mypy четырёх файлов. Эти регрессии запускались в host Poetry environment Python 3.13.16; native продуктовая цепочка отдельно проверила Python 3.13.7, SQLite 3.53.4 и Psycopg 3.3.9 в exact core/worker images. Core image собран штатным target `translator-core-runtime` без изменения dependencies; он остаётся локальным QA-артефактом, без автоматического переноса worker security admission на API/consumer/outbox.

Оба финальных cleanup сохранили 207 исходных постоянных контейнеров и удалили свои containers, networks, SQL/Kafka/TLS volumes. API credential монтировался read-only только в provider; request/result, PKI и raw logs остаются вне Git. Рабочий deployment, его очереди и identities не переключались. Локальный режим работы не отменён: новых push, cloud CI jobs или публикаций нет.
