# Побочный эффект full-local build на общем Engine — 17 ноября 2026

Полный локальный gate был запущен на общем Docker Desktop Engine с отдельным project/env/PKI namespace. Namespace изолировал контейнеры, volumes и network names, но canonical `full_local build` по-прежнему использовал общие 32 mutable image tags. Сборка переназначила эти ссылки; первоначальные image IDs перестали разрешаться через image API. Проверка Docker baseline начиналась **после** build, поэтому не обнаруживала этот более ранний побочный эффект. Это ошибка scope приёмки; сохранность прежнего image cache не подтверждена и не объявляется успешной. На стандартном пуле подсетей Engine также не хватило места для первой новой Kafka network, поэтому полный functional gate остался BLOCKED.

Все 207 исходных постоянных контейнеров сохранили ID, Image, status, StartedAt, restart count, отсортированные mounts и networks. Рабочие процессы не переключались/не перезапускались; прежние queues, identities и canonical volumes не удалялись. Смена tag не равна смене уже запущенного container image, но влияет на возможность будущего нового создания роли. До выяснения точного artifact/handoff прежние working incarnations не удаляются.

Попытка вернуть старые aliases остановилась на read-only preflight **до первого tag**: старые IDs отсутствовали в доступной image inventory. Read-only проверка тем же containerd client 2.2.5 и дискового OCI store нашла часть старых metadata blobs, однако полного closure нет. В частности, индексы прежних SPIRE runtime, certificate-delivery, installer и SPIRE sender отсутствуют; часть других native filesystem/attestation blobs тоже отсутствует. Пересборка с новым digest либо подстановка нового образа под прежний ID не считается восстановлением. Временный partial OCI import под собственным `aelev/recovery-validation-20261117:postgresql` не прошёл platform completeness и не изменял исходный PostgreSQL tag; это FAIL diagnostic, не admission/restore proof.

Для двух работающих SPIRE images сохранены закрытые read-only rootfs exports общим размером 733 520 384 bytes. Start time/image ID проверены до/после. Они сохраняют доступные бинарные файлы и не являются полными OCI image backups; mounted canonical volumes/credentials/state не экспортируются. [Docker export](https://docs.docker.com/reference/cli/docker/container/export/) явно исключает volumes. Private receipt `old-spire-rootfs-backups.json` SHA-256 `cb48fa8ac3a965214c3420098f36be8112f744114cac3735767ffca0ba24bf0c` расположен вне checkout в `~/.local/share/aelev/evidence/infrastructure-integration-20261116/image-alias-recovery-20261117/`. Rootfs archives, metadata и package tools не коммитятся.

Исправление full gate закрыто проверяет collision всех source/local-build references **до driver install/build**. Код `BUILD_IMAGE_REFERENCE_COLLISION_CLEAN_ENGINE_REQUIRED` требует отдельного чистого Engine и не меняет чужие aliases. Наличие unrelated tags и pull-only immutable inputs разрешено. В новый [source builder](../api/owner-build.md) tag/push вообще не передаются; его отдельный [настоящий PMS build/replay](owner-source-build-20261117.md) прошёл без изменения именованных references своего baseline.

Перед guard/correction объявлен прогноз 15–20 минут. Инцидент и неудачные diagnostics сохраняются отдельно от успешного native source build; full clean-room, software/site admission и image-cache restoration не закрываются этим документом. Для дальнейшего полного прогона готовится отдельный тестовый Engine с собственным storage, а не изменение рабочих ports/aliases, restart daemon или удаление старых network/volumes. [Docker image tag](https://docs.docker.com/reference/cli/docker/image/tag/), [containerd image store](https://docs.docker.com/engine/storage/containerd/) и [OCI layout](https://github.com/opencontainers/image-spec/blob/v1.1.1/image-layout.md) объясняют используемые механизмы; рамки сохранности определяет продукт.
