# Аудит документации, диаграмм и Production Readiness

- **Дата среза:** 2026-11-06
- **Область:** активный исходный код и документация Platform Infrastructure; `obsolete/**`, runtime, секреты и внешние площадки исключены.
- **Критерий продукта:** самостоятельные сборка, конфигурация, безопасный запуск, отказные режимы, сохранение состояния, наблюдаемость, восстановление, документация и воспроизводимые проверки закрыты в поддерживаемом профиле.
- **Критерий площадки:** PKI/KMS, DNS, firewall, WAN, реальные failure domains, ресурсы, backup target, подпись/admission образов, RPO/RTO и доставка тревог проверяются отдельно. Статус продукта не является разрешением запуска на конкретной production-площадке.

## Метод

Проверены граф Graphify, 17 uppercase `INDEX.md` как агентские карты композиции и владельцев, обязательные архитектурные документы, 15 владельческих README/SPEC/USER_MANUAL/`architecture.mmd`, три межвладельческие диаграммы, публичные API, 15 нормативных `00-INFRA-*` ADR, архив 132 неизменяемых унаследованных решений, TASKS/CHANGELOG и доказательные отчёты. Автоматический gate проверяет наличие и табличный формат агентских карт, отсутствие активных lowercase `index.md`, полный комплект документов, структуру Mermaid, локальные ссылки, официальный раздел каждого сервисного руководства, формат и состав нормативных ADR и присутствие каждого владельца в этой матрице. Достаточной считается диаграмма, которая показывает границу владельца, нативный процесс, технические входы/выходы, постоянное состояние при его наличии и публикацию технического состояния; подробные команды и отказные инварианты остаются в SPEC и USER_MANUAL.

## Закрытые пробелы и остаточный риск

До этого аудита наличие 18 диаграмм проверялось, но не существовало машиночитаемого требования к полному комплекту README/SPEC/USER_MANUAL, официальным upstream-ссылкам, общей матрице готовности и отделению инфраструктурных решений от consumer-истории. Пробел закрыт `tools/check_documentation.py`, сервисными разделами официальных руководств, 15 нормативными `00-INFRA-*` ADR и этим реестром. Все 132 унаследованных файла сохранены побайтно в [аудиторском архиве](inherited-adrs/INDEX.md); для каждого зафиксировано, переписан ли инфраструктурный инвариант или исходное consumer-решение исключено из нормативного набора.

Повторный аудит выявил более высокий межвладельческий критерий: прежние владельческие доказательства и core quickstart не воспроизводят весь продукт из чистого состояния одним проверяемым контуром. Добавлены `full-local.json`, сохраняющий owner-local bootstrap, fail-closed preflight, генератор release BOM, исполняемый gate одиннадцати функций, evidence schema/verifier, ручной GitHub-hosted workflow и [единый runbook](../operations/clean-room-reproduction.md). Структурно gate теперь покрывает OIDC/UI, Kafka, PostgreSQL, MinIO, egress, telemetry, provider-neutral translation, SPIRE identity lifecycle, его observation/durable-delivery/outage-recovery/Grafana projection и bounded recovery; отчёты выводятся вне source tree, а Docker baseline сверяется до/после.

Фактический полный прогон на точном release commit ещё не получен. После устранения архитектурной утечки Translator его 223 модульные проверки и конфигурационные contract tests проходят: provider implementation/model/lock/downloader/runtime отсутствуют, один приватный запрос содержит только текст и языки, а Compose сохраняет image-owned запуск и healthcheck. Канонический provider теперь выделен с сохранённой Git-историей в отдельный private-репозиторий [`sapogov1978/AELEV-translation-provider`](https://github.com/sapogov1978/AELEV-translation-provider); локальные source/type/UDS/Docker проверки и независимый CI проходят. Provider release [42248923795](https://github.com/sapogov1978/AELEV-translation-provider/actions/runs/42248923795) выпустил Linux amd64 image `sha256:4a820a13e6a03188589c09d14e52b5f2d05e9359d7df847bad768966016e9ec9` с проверенными весами, SBOM, provenance и Cosign signature на GitHub-hosted runner. Exact image затем прошёл [quality run 42257002684](https://github.com/sapogov1978/AELEV-translation-provider/actions/runs/42257002684): 20/20 синтетических cases через opaque UDS, 18 byte-exact baseline и два отдельно рассмотренных digest-bound эквивалентных варианта. Независимый worker release [42259587979](https://github.com/sapogov1978/AELEV-platform-infrastructure/actions/runs/42259587979) выпустил и подписал `ghcr.io/sapogov1978/aelev-platform-infrastructure-translator-worker@sha256:e006ab2466b6455d6a928e8aa9aa12fc023ac9a7e3c5897082508249b422f912` с SBOM и provenance. Это закрывает внутренний дефект, источники поставки и provider quality gate, но не заменяет общий прогон.

Текущий локальный preflight закрыто останавливается до запуска: оба подписанных image digest уже выпущены и закреплены в manifest, но активный `translator-service/.env` намеренно не перезаписан, одноразовое SPIRE approval не предоставлено, 39 owner-local paths ещё не подготовлены и два старых pull-reference остаются mutable. На чистом checkout `init` подготавливает owner-local входы, но не подразумевает approval и не допускает tag вместо digest. GitHub-hosted clean-room run [42261642805](https://github.com/sapogov1978/AELEV-platform-infrastructure/actions/runs/42261642805) уже доказал выдачу одноразового runner и успешный host-neutral `init`, после чего fail-closed остановился до build на `403 permission_denied: read_package`: provider package ещё не предоставил этому репозиторию Actions read access. Поэтому успешные image releases и зелёные статические suites доказывают только часть процедуры, но не являются PASS evidence полного профиля.

Поэтому отдельные программные продукты сохраняют указанные выше scoped-выводы, но репозиторий как полный воспроизводимый `full-local` продукт сейчас имеет статус `IN_PROGRESS / BLOCKED`, не `PRODUCTION_READY`. Положительный вывод возможен только после нового clean-room прогона точного release commit и повторного аудита его evidence. После этого допуск конкретной площадки всё равно отдельно закрывает открытые пункты владельческих `TASKS.md`.
