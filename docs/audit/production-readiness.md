- **Дата среза:** 2026-11-11
- **Статус:** опубликованный [`full-local` 1.1.3](https://github.com/sapogov1978/AELEV-platform-infrastructure/releases/tag/v1.1.3), source `610e7c0f6ceabff855fd20cfc2760ad866518d67`, допущен [CI 26/26](https://github.com/sapogov1978/AELEV-platform-infrastructure/actions/runs/42984726705), [полным clean-room 12/12](https://github.com/sapogov1978/AELEV-platform-infrastructure/actions/runs/42984835085) и независимым verifier из извлечённого source bundle. Все 27 assets повторно скачаны и сверены по SHA-256/размеру. Эта документальная фиксация сохраняет release source; установка и допуск конкретной площадки остаются отдельным этапом.
- **Область:** активный исходный код и документация Platform Infrastructure; `obsolete/**`, runtime, секреты и внешние площадки исключены.
- **Критерий продукта:** самостоятельные сборка, конфигурация, безопасный запуск, отказные режимы, сохранение состояния, наблюдаемость, восстановление, документация и воспроизводимые проверки закрыты в поддерживаемом профиле.
- **Критерий площадки:** PKI/KMS, DNS, firewall, WAN, реальные failure domains, ресурсы, backup target, подпись/admission образов, RPO/RTO и доставка тревог проверяются отдельно. Статус продукта не является разрешением запуска на конкретной production-площадке.

Повторная [сверка перед 1.0.0](release-1.0.0.md) дополнительно проверяет самостоятельность нормативных источников, scope API, сохранённые SDK-документы и release assets. Для выпуска 1.0.0 прежний допуск b1e2ee1 является исторической базой: новый exact source commit обязан пройти собственные CI/full-local/verifier и публикацию проверенных ZIP/lock/BOM/evidence по [процедуре выпуска](../operations/release.md). Доказательство опубликованного 1.0.0 находится в его `release-admission.json`; без него переноса статуса с 0.2.0 нет.

## Метод

Проверены граф Graphify, 17 uppercase `INDEX.md` как агентские карты композиции и владельцев, обязательные архитектурные документы, 15 владельческих README/SPEC/USER_MANUAL/`architecture.mmd`, три межвладельческие диаграммы, публичные API, 15 нормативных `00-INFRA-*` ADR, архив 132 неизменяемых унаследованных решений, TASKS/CHANGELOG и доказательные отчёты. Автоматический gate проверяет наличие и табличный формат агентских карт, отсутствие активных lowercase `index.md`, полный комплект документов, структуру Mermaid, локальные ссылки, официальный раздел каждого сервисного руководства, формат и состав нормативных ADR и присутствие каждого владельца в этой матрице. Достаточной считается диаграмма, которая показывает границу владельца, нативный процесс, технические входы/выходы, постоянное состояние при его наличии и публикацию технического состояния; подробные команды и отказные инварианты остаются в SPEC и USER_MANUAL.

## Закрытые пробелы и остаточный риск

До этого аудита наличие 18 диаграмм проверялось, но не существовало машиночитаемого требования к полному комплекту README/SPEC/USER_MANUAL, официальным upstream-ссылкам, общей матрице готовности и отделению инфраструктурных решений от consumer-истории. Пробел закрыт `tools/check_documentation.py`, сервисными разделами официальных руководств, 15 нормативными `00-INFRA-*` ADR и этим реестром. Все 132 унаследованных файла сохранены побайтно в [аудиторском архиве](inherited-adrs/INDEX.md); для каждого зафиксировано, переписан ли инфраструктурный инвариант или исходное consumer-решение исключено из нормативного набора.

Сверка перед 1.0.0 показала недостаточность одной структурной проверки: в активных API и нормативных ссылках оставались документы потребителя. Они заменены собственными инфраструктурными контрактами и архитектурой; исходные API сохранены побайтно в отдельном архиве. Новый gate отвергает возврат предметных семейств и внешних consumer-нормативов, а исторические SDK-документы допускает только при неизменном digest и отдельной текущей нейтральной точке входа. Канонические Kafka schemas и runtime не переписаны вслед за документацией.

Повторный аудит выявил более высокий межвладельческий критерий: прежние владельческие доказательства и core quickstart не воспроизводят весь продукт из чистого состояния одним проверяемым контуром. `full-local.json` закрепляет owner-local bootstrap, fail-closed preflight, release BOM, исполняемый gate двенадцати функций, evidence schema/verifier, ручной GitHub-hosted workflow и [единый runbook](../operations/clean-room-reproduction.md). Gate покрывает OIDC/UI, Kafka, PostgreSQL, MinIO, egress, telemetry, сохранение очереди Translator без провайдера, health/UDS exact provider/worker images без inference, SPIRE identity lifecycle, его observation/durable-delivery/outage-recovery/Grafana projection и bounded recovery; отчёты выводятся вне source tree, а Docker baseline сверяется до/после.

Полный [run 42489907582](https://github.com/sapogov1978/AELEV-platform-infrastructure/actions/runs/42489907582) программной версии `b7a6b4b9957ce36a97161f6064b4eb7245f118d4` завершился `PASS` 2026-11-08 в 16:02:37 Europe/Belgrade. Все 11 обязательных функций, `source_dirty=false`, clean baseline и cleanup подтверждены; все 26 jobs repository CI той же версии прошли. Сохранённый [пакет evidence](clean-room-b7a6b4b/RESULT.md) прошёл повторную независимую проверку после ужесточения BOM metadata: чужие schema/profile/release и dirty source отклоняются даже при корректно пересчитанном хеше.

Адресная [матрица](clean-room-completion-plan.md) перед полной приёмкой закрыла PostgreSQL fault targets 1/2/3 с физическим восстановлением, реальную telemetry/Grafana доставку, Translator queue/restart/Kafka outage, SPIRE identity/observation и bounded recovery. Выявленные дефекты bootstrap/test drivers исправлены без изменения native SQL safety, fencing или DCS таймеров; runtime не обновлялся для лечения неподтверждённой гипотезы. Все исторические отчёты и 132 унаследованных ADR сохранены.

Повторный полный run `42494484872` commit `0662a28` вновь выявил PostgreSQL pair-loss timeout первоначального ведущего 1, поэтому единичный прежний PASS не был принят как устойчивое закрытие. Сохраняемый fencing audit и детерминированный initial-1 без switchover воспроизвели отказ в двух из трёх попыток `42500787300`: последовательные проверки ждали недоступный первый DCS endpoint, подтверждение ограждения теряло native-аренду, guarded return возвращал peer, и цикл повторялся. Исправление выбирает доступный DCS endpoint свежими linearizable запросами в прежнем retry budget; для возврата сохраняются две последовательные свежие проверки разных endpoints/members, cluster/revision/lease guards, TLS, native safety и прежние бюджеты. Отдельно root test driver стал ждать штатный Docker-fencing return до прежнего deadline вместо немедленного terminal failure; готовность по-прежнему требует настоящего healthy процесса.

Версия `b1e2ee164f8e9a94ce248c64233d808d43771a78` прошла initial-1 3/3 в `42522896912`, root/Kafka/initial-1 в `42522896648`, все 26 jobs CI и новый полный [run 42524864122](https://github.com/sapogov1978/AELEV-platform-infrastructure/actions/runs/42524864122), завершившийся 2026-11-08 в 22:59:46 Europe/Belgrade. Независимый verifier и повторная проверка репозиторного архива подтвердили 11/11, чистый source/Docker baseline и cleanup. [Текущий пакет evidence и расследование](clean-room-b1e2ee1/RESULT.md) сохраняют исходные байты; первый полный PASS, неудачные попытки и 132 унаследованных ADR не переписываются. Комплект документации содержит входы и путь оператора; manifest, preflight/BOM и исполняемые acceptance-проверки подтвердили функциональное воспроизведение из чистого состояния по этой цепочке.

Для каждого следующего runtime-выпуска обязательны собственные CI, чистые BOM и полная приёмка; документальная фиксация уже проверенной версии не создаёт новый runtime-выпуск. Допуск конкретной площадки отдельно закрывает открытые пункты владельческих `TASKS.md`: PKI/KMS/SVID, DNS/firewall/WAN, реальные failure domains, capacity, независимый backup/PITR, RPO/RTO, подпись/admission и доставку alert. Выбранные provider/worker digests теперь входят в обязательный состав, но provider по-прежнему не становится владельческой строкой Translator; реальный OpenAI inference требует доступного API balance и отдельного bounded smoke.
