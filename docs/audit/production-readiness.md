## Метод

Проверены граф Graphify, 17 uppercase `INDEX.md` как агентские карты композиции и владельцев, обязательные архитектурные документы, 15 владельческих README/SPEC/USER_MANUAL/`architecture.mmd`, три межвладельческие диаграммы, публичные API, 15 нормативных `00-INFRA-*` ADR, архив 132 неизменяемых унаследованных решений, TASKS/CHANGELOG и доказательные отчёты. Автоматический gate проверяет наличие и табличный формат агентских карт, отсутствие активных lowercase `index.md`, полный комплект документов, структуру Mermaid, локальные ссылки, официальный раздел каждого сервисного руководства, формат и состав нормативных ADR и присутствие каждого владельца в этой матрице. Достаточной считается диаграмма, которая показывает границу владельца, нативный процесс, технические входы/выходы, постоянное состояние при его наличии и публикацию технического состояния; подробные команды и отказные инварианты остаются в SPEC и USER_MANUAL.

## Закрытые пробелы и остаточный риск

До этого аудита наличие 18 диаграмм проверялось, но не существовало машиночитаемого требования к полному комплекту README/SPEC/USER_MANUAL, официальным upstream-ссылкам, общей матрице готовности и отделению инфраструктурных решений от consumer-истории. Пробел закрыт `tools/check_documentation.py`, сервисными разделами официальных руководств, 15 нормативными `00-INFRA-*` ADR и этим реестром. Все 132 унаследованных файла сохранены побайтно в [аудиторском архиве](inherited-adrs/INDEX.md); для каждого зафиксировано, переписан ли инфраструктурный инвариант или исходное consumer-решение исключено из нормативного набора.

Повторный аудит выявил более высокий межвладельческий критерий: прежние владельческие доказательства и core quickstart не воспроизводят весь продукт из чистого состояния одним проверяемым контуром. Добавлены `full-local.json`, сохраняющий owner-local bootstrap, fail-closed preflight, генератор release BOM, исполняемый gate одиннадцати функций, evidence schema/verifier, ручной GitHub-hosted workflow и [единый runbook](../operations/clean-room-reproduction.md). Структурно gate теперь покрывает OIDC/UI, Kafka, PostgreSQL, MinIO, egress, telemetry, сохранение очереди Translator без провайдера, SPIRE identity lifecycle, его observation/durable-delivery/outage-recovery/Grafana projection и bounded recovery; отчёты выводятся вне source tree, а Docker baseline сверяется до/после.

Полный [run 42489907582](https://github.com/sapogov1978/AELEV-platform-infrastructure/actions/runs/42489907582) программной версии `b7a6b4b9957ce36a97161f6064b4eb7245f118d4` завершился `PASS` 2026-11-08 в 16:02:37 Europe/Belgrade. Все 11 обязательных функций, `source_dirty=false`, clean baseline и cleanup подтверждены; все 26 jobs repository CI той же версии прошли. Сохранённый [пакет evidence](clean-room-b7a6b4b/RESULT.md) прошёл повторную независимую проверку после ужесточения BOM metadata: чужие schema/profile/release и dirty source отклоняются даже при корректно пересчитанном хеше.

Адресная [матрица](clean-room-completion-plan.md) перед полной приёмкой закрыла PostgreSQL fault targets 1/2/3 с физическим восстановлением, реальную telemetry/Grafana доставку, Translator queue/restart/Kafka outage, SPIRE identity/observation и bounded recovery. Выявленные дефекты bootstrap/test drivers исправлены без изменения native SQL safety, fencing или DCS таймеров; runtime не обновлялся для лечения неподтверждённой гипотезы. Все исторические отчёты и 132 унаследованных ADR сохранены.

Повторный полный run `42494484872` итогового commit `0662a28` прошёл root lifecycle и Kafka, затем воспроизвёл PostgreSQL pair-loss timeout с fault target 1: узлы 1/2 остановлены, узел 3 остался репликой, etcd 2/3 и fencer healthy; fencer зафиксировал `NO_LEADER_LEASE`. Статус всего продукта возвращён в `IN_PROGRESS` до установления механизма и новой адресной/полной приёмки. Для следующего отказа diagnostic сохраняет ограниченную последовательность собственного fencing audit до cleanup; `postgresql-natural` повторяет сценарий без подготовительного switchover, чтобы он не маскировал исходное состояние. Для каждого следующего release commit обязательны его собственные CI, чистые BOM и полная приёмка; архивный PASS не подменяет новый прогон. Допуск конкретной площадки отдельно закрывает открытые пункты владельческих `TASKS.md`: PKI/KMS/SVID, DNS/firewall/WAN, реальные failure domains, capacity, независимый backup/PITR, RPO/RTO, подпись/admission и доставку alert. Выбор реализации перевода остаётся открытым, а compute/provider отсутствует в обязательном составе и владельческой строке Translator.
