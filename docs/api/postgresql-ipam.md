# PostgreSQL: явная IPAM-конфигурация собственной сети

После проверки прежнего SAN/NAT исправления и native HA evidence добавляется только opt-in `postgresql/compose.ipam.yml`. Прогноз до code и host checks — 30–45 минут; actual network/TLS/native qualification выполняется отдельно менеджером. Base recipes, images, ports, TLS, SQL/etcd commands и public SDK не меняются. Без выбора overlay прежняя модель сохраняется.

При выборе `compose.runtime.yml` и затем `compose.ipam.yml` оператор обязан передать `AELEV_INFRASTRUCTURE_POSTGRESQL_NETWORK_SUBNET` и `AELEV_INFRASTRUCTURE_POSTGRESQL_NETWORK_GATEWAY`. Профиль добавляет только `networks.postgresql.ipam.config` с этими `subnet`/`gateway`. Имя существующей сети по-прежнему задаёт `AELEV_INFRASTRUCTURE_POSTGRESQL_NETWORK`; у independently placed проекта собственные network/volume names и собственный daemon. Overlay не объявляет shared cross-host сеть, не меняет endpoints на Compose DNS и не создаёт отдельный backend.

Профиль принадлежит девяти существующим ролям: etcd-1/2/3, postgresql-1/2/3, postgresql-status-publisher, postgresql-status-provision и database-provisioner. Пустые service mappings сохраняют их поля. Каждая роль уже подключается к `postgresql` в runtime recipe; catalog IDs/kinds остаются прежними. Независимый `postgresql-fencer` с `compose.fencing-ssh.yml` использует свой profile и не выбирает этот overlay. Прежние recipes не начинают требовать новых переменных.

Private deployment planner проверяет gateway внутри CIDR, отсутствие пересечений с полной сетью площадки и соответствие действительных etcd peer certificate SAN фактическим исходящим/NAT адресам. Compose IPAM declaration не является доказательством маршрута, SAN, текущей сети или readiness. Existing `prepare-tls.py` принимает начальные `NODE_N_ETCD_PEER_CLIENT_IPS`; смена согласованных адресов требует отдельного checked certificate generation, а не отключения hostname/peer checks. Ни CIDR, ни gateway, ни issuer policy не выбираются профилем автоматически. Existing keys/certificates не переписываются этим overlay.

Host green сравнивает полную actual Compose CONFIG модель до/после: допустима только IPAM-разница. Проверяются default bytes без overlay, отсутствие/пустота каждого required input, прежние role definitions и два independently named проекта. Только effect-free CONFIG, без Engine/контейнеров/сетей. Native owner up затем должен создать сеть штатно через этот recipe; fixture-only `docker network create` не подменяет автоматизацию платформы.
