# Подготовка owner workspace, версия 1

`procedure=owner-prepare` дополняет [node execution](node-execution.md) по [00-INFRA-0021](../adr/00-INFRA-20261117-0021-pinned-owner-workspace-preparation.md). Команда `python3.13 -m tools.owner_prepare prepare|status --request PRIVATE_JSON --request-sha256 RAW_SHA256` создаёт или сверяет отдельный private каталог владельца. Один request выбирает один role/workspace, без предположения о соседстве других экземпляров. Это подготовка файлов перед [owner-compose](owner-compose.md), а не установка/готовность всего продукта.

Request содержит ровно `schema_version=1`, `executor_root`, `executor_files`, `owner_root`, `owner_files`, `catalog`, `role`, `workspace`, `env_file`, `inputs`. Source roots/manifests и role имеют тот же контракт, что у owner-compose. Все recipes выбранной роли должны находиться внутри её catalog owner prefix. `inputs` содержит ровно absolute private `env_file → raw SHA-256`; outer node request дополнительно связывает definition. Env — regular UTF-8-compatible bytes без NUL, от 1 byte до 1 MiB; helper не печатает, не интерполирует и не меняет его содержимое. Все input/source проверки выполняются до workspace effects.

`workspace` — absolute path без symlinks, вне обоих source roots и не их ancestor. Parent уже существует у оператора с private permissions; его может создать прежний node-artifact receiver. Новый workspace получает только manifest public files owner prefix, `.env` и private `.owner-workspace.json`. Manifest snapshot нормализует public modes и проверяет hashes заново. Public `.env`/receipt collision запрещён. Удалённый target готовит собственные файлы: [Docker mount относится к daemon host](https://docs.docker.com/engine/storage/bind-mounts/), не к controller.

Private attempt находится на том же filesystem. Fsync всех файлов/каталогов и полная provisional verification предшествуют rename; helper writers сериализованы flock. Неудачный attempt остаётся закрытым для разбора, прежние directories не удаляются. Существующий workspace допускает только точную сверку receipt/public files/env/modes; новое содержимое, чужой каталог и обнаруженный drift не исправляются автоматически. Новые owner-managed generated outputs вне manifest не считаются pinned source; выдача/проверка PKI и runtime configuration остаются их владельческими процедурами. Helper не получает права на canonical domain data.

`status` не создаёт directory, lock или credentials. При вызове через node execution fresh status использует новый observation UUID; historical successful `prepare` не доказывает отсутствие последующего drift. Поэтому controller обязан выполнить fresh status перед owner-compose, а не опираться только на cached preparation receipt. Рецепты и env для дальнейшего Compose используют подготовленный workspace и проверенный `.env`; image/release admission и readiness остаются отдельными.

Public `OWNER_CONFIGURATION_PREPARED` содержит только raw SHA-256 `workspace_sha256`, `public_files_sha256`, `environment_sha256`. Первый связывает role, workspace path, file hashes/modes и env hash. Это другая область, чем resolved-service `configuration_sha256` owner-compose. Node projection требует все три hashes и исключает raw/private fields; malformed success даёт RESULT_UNKNOWN. Workspace verification не вызывает Docker, ОС/package installer, PKI issuance, inference, runtime start или RESUME. Ошибка возвращает exit 2 с фиксированным code; raw диагностика остаётся private.

Существующий стек, source generations, действующие owner env, keys, recovery history и роли не меняются. Официальные механизмы и заранее объявленный прогноз приведены в ADR; local/SSH native proof не считается physical-distribution или full-inventory admission.
