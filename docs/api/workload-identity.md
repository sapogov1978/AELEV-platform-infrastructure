# Удостоверения рабочих нагрузок

Технический контракт [SPIRE](../../spire/SPEC.md) по [00-INFRA-20261106-0007-workload-and-operator-identity](../adr/00-INFRA-20261106-0007-workload-and-operator-identity.md) и [00-INFRA-20261106-0007-workload-and-operator-identity](../adr/00-INFRA-20261106-0007-workload-and-operator-identity.md). Он не передаёт предметные решения и не заменяет Kafka. Выдача использует стандартный SPIRE, получение — SPIFFE Workload API; собственный протокол CA не вводится.

## Операторская регистрация

Отдельная операторская задача принимает JSON версии 1. Обязательны `owner=infrastructure-spire`, `schema_version=1`, `environment=local|test|production`, `trust_domain`, `resource_owner`, `operation_id`, `node_id`, `spiffe_id`, `actor`, `server_address`. UUID операции и узла канонические, identity находится строго под `spiffe://<trust_domain>/<resource_owner>/`. Необязательны `server_port` (8081), `svid_ttl_seconds` (300), до четырёх `dns_names` и `policy_mountpoints` (по умолчанию `["identity.json"]`). Последнее — 1–4 уникальных basename вида `[a-z][a-z0-9-]{0,62}.json`, обязательно включая `identity.json`; `owner.json`, `current.json`, пути и private-key filenames запрещены. Exporter создаёт только пустые read-only точки nested mount и сохраняет существующие consumer bytes/inode; содержимое/имена задаёт потребитель, не инфраструктурный каталог. Список сохраняется в точном bootstrap plan и входит в request digest. Остальные поля запрещены. Ограничения значений и фиксированные selectors определяет [SPEC провайдера](../../spire/SPEC.md#владение-и-полномочия).

`authorize` фиксирует точное намерение до нативного действия, возвращает фазу и digest запроса, сохраняет однократный начальный token только в закрытом состоянии/пакете установки. Повтор с тем же UUID и другими байтами отклоняется. Потеря ответа при создании entry проверяется по его стабильному ID; неоднозначная выдача token не повторяется новым правом. `revoke` устойчиво запрещает дальнейшую авторизацию тем же намерением и удаляет entry; `inspect` читает фазу без выдачи. Удалённая извне завершённая entry не восстанавливается.

Операторский Unix socket и bootstrap-пакет не доступны runtime потребителя. Bootstrap содержит `plan.json`, `bundle.crt`, `join-token`, не CA private key. Право первоначального подключения действует 600 секунд и не продлевается повтором. После штатной регистрации обновление использует node SVID, не этот token.

`export-bootstrap` принимает тот же точный запрос только для уже завершённого `authorize`. Под общей операторской блокировкой он сверяет digest намерения, действующую точную native entry, исходные node/identity/область, прежние token и trust bundle и первоначальный срок. Неизвестное, незавершённое, отозванное, изменённое либо истёкшее право не выдаётся заново. Экспорт не вызывает `token generate`, `entry create/update/delete` и не продлевает срок; отзыв не восстанавливается.

Результат отдельного установочного CLI содержит безопасные `phase=EXPORTED`, `operation_id`, `node_id`, `resource_owner`, `request_digest`, `expires_at`, `export_volume` и `export_directory=package`. Это ссылка на закрытый публичный результат оператора, не доступ потребителя к каноническим регистрациям. Внутри находятся три исходных bootstrap-файла, маркер владельца и `receipt.json` версии 1 с исходной областью/сроком и SHA-256 трёх файлов; ключ CA, аудит и node state не включаются. Token и байты пакета не возвращаются через stdout или журнал. Повтор до истечения срока сохраняет те же байты и не перезаписывает дрейф; квитанция фиксируется последней. Пакет передаётся только доверенным операторским каналом как исходное полномочие, не через открытый URL. Квитанция проверяет целостность, но не заменяет аутентификацию этого канала и не обещает отмену уже переданной копии.

Агентский установщик с `--exported-bootstrap --bootstrap-operation <UUID>` принимает пакет из `/run/input` без канонического состояния сервера. Проверяются исходные UUID/срок, хеши, обычные файлы без ссылок, закрытые права `0700` каталога/`0600` файлов и связь плана с узлом/владельцем; затем работает прежняя native-аттестация SPIRE. После 600 секунд нужен новый явно одобренный bootstrap, не автоматический повтор выдачи. Успешный экспорт сам по себе не означает готовность агента или вычислителя.

## Файловая доставка `spire-file-v1`

Агент имеет отдельный собственный временный volume. Получатель монтирует его только для чтения; это публичный результат технического адаптера, не чтение канонического хранилища SPIRE. Один volume обслуживает одну точную identity. Указатель `current.json` содержит:

Volume также содержит пустую обычную точку подключения `identity.json` с первоначальным mode `0444`. При необходимости получатель подключает собственный файл политики read-only поверх этой точки, сохраняя весь SVID volume read-only. SPIRE не читает и не создаёт содержимое политики; существующий обычный файл не изменяется. Небезопасная точка (ссылка, каталог либо специальный файл) закрыто запрещает подготовку. Пустой файл не является допустимой политикой или новым регистрационным правом; формат и проверку фактической политики определяет получатель.

| Поле | Семантика |
|---|---|
| `owner`, `schema_version` | `spire-svid-delivery`, целое `1` |
| `state` | `READY` либо `UNAVAILABLE` |
| `environment`, `spiffe_id` | Точные среда и URI SAN получателя |
| `updated_at` | UTC-время последней проверки; получатель допускает возраст не более 20 секунд |
| `expires_at`, `serial` | Фактический срок и серийный номер сертификата в состоянии READY |
| `generation` | 64 строчных hex-символа; каталог `generations/<generation>` |
| `tls_sha256`, `bundle_sha256` | SHA-256 точных байтов `tls.pem` и `bundle.pem` этого поколения |
| `material_digest` | Стабильный digest полученного материала; не разрешение или оценка доверия |
| `code` | Безопасный код отказа в состоянии UNAVAILABLE; закрытые ключи и native stderr не возвращаются |

`tls.pem` объединяет конечный private key и цепочку, `bundle.pem` содержит доверенные CA. Доставщик сначала сохраняет проверенные файлы поколения, затем атомарно заменяет указатель. Получатель запрещает symlink/path traversal, проверяет хеши, реальный сертификат, ключ, exact SPIFFE identity, срок и среду; HTTPS дополнительно проверяет DNS hostname и identity собеседника. Новое соединение использует свежий контекст; уже установленные соединения не переаттестовываются автоматически. Отрицательное или устаревшее состояние не разрешает возврат к прежнему сертификату, HTTP или локальному CA.

Удаление регистрации запрещает новые выдачи, но не аннулирует криптографически уже выданный X.509-SVID до истечения TTL. Немедленная изоляция требует отдельного сетевого/авторизационного барьера. Потеря node state либо простой дольше срока agent SVID требуют новой явной первоначальной авторизации: бессрочный bootstrap и автоматическое восстановление отозванного права запрещены.

## Владение и совместимость

Операторский параметр `--native-restart-policy no` является необязательным сохраняемым выбором runtime-установки, не новым предметным полномочием. Установщик хранит точные роли в собственном `native_restart_no_roles`, сохраняет уже наблюдаемый `no` и не возвращает native retry budget при повторе или замене отсутствующей инкарнации. Команды авторизации/отзыва/экспорта не принимают этот runtime-параметр. Recovery attempts/holds и включение прежнего host controller остаются отдельными операциями владельца; новые автоматические права флаг не выдаёт.

Операторский экспорт установленного провайдера является публичной технической проекцией конфигурации, не выдачей нового права: общий Compose получает ссылки на существующие собственные образы, тома и сети, а также сохранённые конечные политики рестартов по [SPEC SPIRE](../../spire/SPEC.md#публичная-композиция-установленного-провайдера). Закрытые ключи, пакеты первоначального подключения, регистрации и административные полномочия не экспортируются; источники истины остаются у провайдера. Перестроение проекции не восстанавливает отозванный доступ и не обнуляет журнал восстановления.

Имя физического Compose-проекта не является identity или владельцем установки. Оператор продолжает принимать прежний логический проект и проверяет текущего координатора запуска по собственным runtime-меткам; смешанный или неоднозначный перенос закрыто отклоняется. Такая смена размещения не переименовывает регистрации, тома или журнал и не разрешает повтор первоначальной выдачи.

Техническое наблюдение и резервное восстановление не являются выдачей нового права: отдельная ограниченная проекция здоровья SPIRE имеет срок 15 секунд, собственные HTTPS-пробы соответствуют [общему контракту](health-readiness.md), доставка — [контракту телеметрии](telemetry.md). Состав, собственные identities наблюдения, сохранение задолженности и проверка актуальности отзывов при восстановлении определены в [SPEC провайдера](../../spire/SPEC.md#наблюдение-и-восстановление). Эти интерфейсы не дают потребителю доступ к регистрациям или ключам CA.

Потребитель сам формирует и хранит описание своих ресурсов, точные identities и привязку файловой доставки; исходники инфраструктуры не перечисляют приложения. Новые обязательные поля или изменение семантики требуют новой версии. Добавленные необязательные диагностические поля не отменяют проверки обязательных. Производственные исходные полномочия, внешний issuer, маршрутизируемые адреса, доверие площадки и средства защищённого аудита поставляет владелец инфраструктуры, не приложение.
