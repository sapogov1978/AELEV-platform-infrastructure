# PostgreSQL node-fencer installation, version 1

Одна source-pinned owner operation `postgresql-fencing-node-install` с действиями `plan`, `task`, `status` устанавливает bounded node launcher и выполняет существующую инициализацию. Это одноразовая operation, не новый runtime/node service. Установка Linux/Python/Docker/SSH и account/privilege policy остаётся явно предоставленной возможностью целевого узла. Images, старые launcher/fencing modules, native safety и история не меняются.

До code проверены `FENCING_SSH.md`, `fencing-node.py`, target `fencing_node.initialize`, node-execution и прежний HA proof. Совместный scope включает owner operation, точный executor allowlist/catalog descriptor и отдельный typed-task adapter потребителя. Прогноз owner/envelope/code/host checks90–120мин; integration60–90мин, manager native40–60мин. Все прежние Compose/SPIRE template/refusal ветки сохраняются, generic commands/environment/handler selection не добавляются.

## Definition

Защищённый JSON содержит ровно `schema_version=1`, `executor_root`, `executor_files`, `owner_root`, `owner_files`, `catalog`, `role`, `image`, `node_configuration_file`, `capability_file`, `credentials`, `runtime_public_keys`, `inputs`. Source roots/manifests и private input hashes проходят прежние проверки node-execution/owner SDK. `role` фиксирован как `platform-infrastructure/postgresql-fencing-node-install`; public descriptor — `postgresql/fencing-node-installation.json`. `image`, launcher node.json image и public descriptor helper image обязаны совпадать; DRP дополнительно сверяет selected fencer image. Изменяемый тег/иной digest не допускается.

`node_configuration_file` — absolute private источник прежнего launcher node.json с `secrets_volume`: schema1, cluster/node/Engine, exact image, отдельные state/credentials volumes, три явных etcd endpoints и timeout. `credentials` содержит ровно `etcd-ca.crt`, `etcd-client.crt`, `etcd-client.key` → absolute source paths. `runtime_public_keys` — непустой список разных absolute source paths с ED25519 public keys; private SSH/issuer keys не являются входом. `inputs` содержит точные SHA-256 всех указанных private файлов, включая node/config capability JSON. На входе regular single-link files0600, owner UID, bounded bytes и отсутствие symlinks/unknown fields обязательны.

`capability_file` содержит ровно `schema_version=1`, `cluster`, `node`, `daemon_id`, `platform`, `installation_root`, `ssh_user`, `authorized_keys_file`, `authorized_keys_sha256`, `host_key_sha256`. Cluster/node/Engine должны совпасть с launcher config; platform — native Linux CPU. Root и authorized_keys destination заранее одобрены владельцем платформенного узла. `authorized_keys_sha256` привязывает исходный exact public key file; `host_key_sha256` — доверенный public SSH host key fingerprint, не TOFU. Target basename — authorized_keys; его private parent, root ownership и неизменность проверяются до записи. Файл может содержать прежний административный public key: его строки сохраняются побайтно. Процедура не меняет sshd_config/account/sudoers и не расширяет authority.

## Actions and receipts

Installation/authorized_keys paths запрещают control characters до effects: quoting аргументов не делает LF/CR безопасными внутри отдельной OpenSSH authorized_keys строки. Final boundary correction forecast5–10мин; legacy generic node path contract не расширяется.

`plan` проверяет source/inputs, fixed scope, native Engine/image, preexisting targets и границы без установки. `task` требует Linux/root, создаёт только свежую собственную installation namespace и absent explicitly labelled volumes, копирует exact source launcher/config/собственные etcd credentials, вызывает прежний `fencing-node.py --initialize` и проверяет существующий node status. Только затем добавляются fixed `restrict,command=...` public-key строки. Команды/arguments из input не принимаются; paths принадлежат approved scope. `status` проверяет текущие files/binding/labels/key authorization и не завершает partial installation автоматически.

Fresh empty installation допустима; preexisting unknown/partial/foreign targets и незавершённый intent требуют handoff. Ранее существовавшие volumes без own installation receipt не усыновляются. Exact completed repeat сохраняет files/timestamps, foreign authorized-key lines и текущее node history/budget, не вызывает initialize повторно. Fresh `plan/status` не подменяют durable task receipt. Interrupted/unknown effects оставляют reconciliation barrier; новая operation UUID не разрешает слепой повтор. Удаление/сброс ledger и RESUME отсутствуют.

Безопасная проекция — `OWNER_NATIVE_PLANNED`, `OWNER_TASK_COMPLETED`, `OWNER_ROLE_ABSENT` либо `RESULT_UNKNOWN` с configuration_sha256; подробные initialization/status/source/Engine/image/binding hashes остаются в private receipt. Нет keys/raw SSH/Docker output в публичном ответе. Собственный native health/readiness fencer проверяется после установки отдельно.

## DAG and verification

Три явных setup tasks и действительный etcd quorum предшествуют выбранному экземпляру `postgresql-fencer`. Его SSH/mTLS health предшествует SQL starts, native quorum — DB provision/migrations. Administrative installer bindings и runtime forced keys разделены. Существующие runtime placements сохраняются. Local cached SSH test-tool image9315… — только qualification adapter существующей node capability, с exact RootFS/Config и свежими keys/configs; его старый встроенный launcher не доказывает новую установку.

Host gates: bounded/source/role/image/path/UID/label/unknown-field refusals, fresh/repeat, foreign-key/partial/stale preservation, concurrency/signals/unknown result, старые executor/catalog guards. Manager native gate: public install реально создаёт отсутствовавшие launcher/config/binding, fresh admin/runtime identities разделены, initialize/status и повтор сохраняют history, downstream блокируется при uncertainty. Никакого нового HA fault/security/release цикла для неизменённых cef0751 bytes.
