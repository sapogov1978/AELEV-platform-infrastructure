# gRPC

gRPC не используется для межсервисных доменных команд, запросов или событий. Единственный разрешённый транспорт доменной коммуникации — Kafka.

Распределённые вычислительные компоненты одной поставки Advance Screening по [ADR-0153](../adr/20261020-0153-distributed-advance-installation.md) остаются внутри одного владельца. Их ограниченный HTTPS/mTLS-канал не является межсервисным исключением и не разрешает другой стадии обращаться к чужой модели, корпусу или хранилищу. Канонические решения и Kafka-публикация остаются у управляющей части; [текущая степень реализации](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/services/discovery-engine/advance-screening/deployment/README.md) отдельно ограничивает применение нового режима.

Тот же собственный канал передаёт неизменяемый план обучения, этапы и точные намерения допуска/отката без общего файлового хранилища. Он привязан к удостоверению установки, job ID, digest и известному установленному профилю; повтор не создаёт второй запуск, потеря связи не снимает удержание. Вычислитель не получает SQL/Kafka-полномочия управляющей части и не выдаёт себе допуск качества. Точные ограниченные маршруты определены в [описи владельца](https://github.com/sapogov1978/discovery-research-platform/blob/8d1a663319ac15d8729cf1422858f37d57096c75/services/discovery-engine/advance-screening/ENDPOINTS.md#внутренние-маршруты-распределённого-вычислителя).

Допустимы только:

- доступ сервиса к собственному хранилищу;
- стандартные технические SPIRE Server/Agent и SPIFFE Workload API по [ADR-0154](../adr/20261020-0154-spire-workload-identity-provider.md) и [контракту удостоверений](workload-identity.md), без доменных команд, каталога приложений и доступа потребителя к административному API;
- ограниченный HTTPS/mTLS-вызов технического `/v1/fetch` независимого [Public Egress Gateway](../../services/infrastructure/public-egress-gateway/SPEC.md) по [ADR-0114](../adr/20261012-0114-infrastructure-public-egress-gateway.md): публичное внешнее назначение, индивидуальное разрешение и поток байтов, без доменного решения, чужого канонического хранилища или замены Kafka RPC;
- техническая HTTPS-инъекция описаний UI и состояния по [ADR-0101](../adr/20261009-0101-provider-injected-platform-ui.md), ограниченные браузерные сообщения оформления и индикатора по [ADR-0102](../adr/20261009-0102-owner-controlled-shared-refresh-indicator.md) и [контракту оболочки](platform-ui-injection.md), без доменных данных и команд;
- взаимодействие Execution Brain с внешней внешний площадкой;
- технические точки проверки работоспособности и готовности оркестратора, которые не передают доменные данные и не изменяют состояние другого сервиса.
- стандартный OTLP технической телеметрии внутри собственной технической поставки по [ADR-0100](../adr/20261009-0100-durable-owner-telemetry-delivery.md); устойчивый межузловой вход использует [HTTPS и явное подтверждение](telemetry.md), не переносит доменные команды и не заменяет Kafka или защищённый аудит.

Введение доменного межсервисного gRPC требует нового ADR, который явно заменит [ADR-0001](../adr/20260727-0001-kafka-only.md). До такого решения определения доменных сервисов Protobuf в проекте не создаются; стандартные сообщения OTLP не являются таким определением.
