# Архитектура Platform UI

Platform UI — универсальная оболочка навигации и технического состояния по [00-INFRA-20261106-0008-platform-ui-owner-injection](../adr/00-INFRA-20261106-0008-platform-ui-owner-injection.md). Нормативные детали находятся в [SPEC владельца](../../platform-ui/SPEC.md) и [публичном контракте инъекции](../api/platform-ui-injection.md), схема — в [architecture.mmd](../../platform-ui/architecture.mmd).

Владелец публикует описание, порядок и монотонное техническое состояние через собственную machine identity. Приёмник хранит только производную read-only проекцию и собственный технический журнал. В оболочке нет каталога конкретных приложений; добавление владельца не требует изменения исходников, env или образа оболочки.

UI владельца остаётся отдельным origin со своим OIDC-клиентом, PKCE, сессией, ролями, данными и командами. Sandbox и проверка точных `origin`/`source` ограничивают browser bridge. Между окнами передаются только разрешённые язык, оформление и технический refresh state; bearer/refresh-токены и предметные данные не передаются. Shell не проксирует предметные API.

Штатный withdrawal скрывает модуль без удаления его журнала или сброса UUID/sequence. Отсутствие свежего heartbeat оставляет присутствующую строку с `connection=LOST`; оно не доказывает остановку сервиса. Владелец отдельно сообщает `ONLINE`, `OFFLINE` или `UNKNOWN`; живой publisher и успешный HTTP GET не доказывают готовность его провайдера.

Presentation CSS версионирован и закреплён digest; опубликованные байты не переписываются. [Текущий SDK-контракт](../../platform-ui/SDK.md) отделён от исторической документации сохранённого пакета. Предметные подписи и смысл показателей определяет приложение-владелец, а общие технические примитивы — Platform UI.

Установка, trust, issuer rotation, подготовка operator identity, backup и восстановление описаны в [руководстве провайдера](../../platform-ui/PROVIDER_OPERATIONS.md). [Правила supply chain](../security/supply-chain.md) определяют доказательства сборки образа; локальная PKI и single-node проекция не доказывают допуск production-площадки.
