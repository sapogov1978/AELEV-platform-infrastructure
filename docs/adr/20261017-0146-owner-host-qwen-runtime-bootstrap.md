# ADR-0146: Автоматическая установка собственного Qwen runtime на хосте

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261017-0146-owner-host-qwen-runtime-bootstrap.md`; SHA-256: `817f6fd5c9864df227da0ae619ad93df58ef3ff8e9da598d59e79079a297847b`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по явному требованию оператора; размещение только на одном хосте частично заменено [ADR-0153](20261020-0153-distributed-advance-installation.md), а обязательность знания Qwen основным runtime и UI частично заменена [ADR-0167](20261028-0167-service-owned-replaceable-model-modules.md); аппаратные ветви допускаются отдельно по результатам проверки
- **Дата:** 2026-10-17
- **Основание:** A5, A10, A12, ADR-0082, ADR-0141, ADR-0143
- **Частично заменяет (Supersedes):** ADR-0143 только в обязательности исполнения модели внутри Linux-контейнера: допускается собственный нативный вычислительный процесс, устанавливаемый пакетом владельца. Модель, происхождение, разметка, LoRA, допуск, предметные границы и Kafka не меняются.

## Контекст

Для Apple M4 подтверждён существенно более быстрый нативный путь Metal. Dockerfile обычного Linux-контейнера Docker Desktop не исполняет команды в macOS. Оператор явно потребовал автоматическую установку на хосте, определение macOS/Linux/Windows и GPU и выбор правильной установки без участия ИИ. Корпоративные ограничения, отсутствие административных прав и запрет вмешательства в чужие службы сохраняются.

## Критерии выбора

- один обычный запуск установщика на самом хосте, без ручного выбора аппаратной ветви;
- закреплённые Qwen3-8B, архив движка и проверяемый пакет Docker;
- собственные непривилегированные процессы, секреты и состояние без универсального канала выполнения команд на хосте;
- отсутствие неявной подмены GPU на CPU и ложного допуска модели.

## Рассмотренные альтернативы

1. Предоставить контейнеру привилегированный доступ или универсальный host-shell/SSH. Отклонено: неоправданные полномочия и область последствий.
2. Объявить Linux-контейнер Docker Desktop нативным Metal-исполнителем. Отклонено: неверная граница исполнения.
3. Один начальный нативный установщик, Docker-пакет с проверкой происхождения и собственная пользовательская служба. Принято.

## Решение

Advance Screening поставляет собственный установщик `host-runtime`: POSIX shell для macOS/Linux и PowerShell для Windows запускают нативный Python 3.13. Dockerfile готовит проверяемые исходники и скрипты; CMake собирает закреплённый движок для фактического хоста. Автоматизация не означает, что первый запуск можно выполнить внутри неподготовленного контейнера вместо хоста. Установщик сам определяет ОС и GPU, не принимает подмену ОС параметром и отклоняет запуск из контейнера или удалённый Docker context.

Apple Silicon с Metal выбирает Metal, NVIDIA с проверяемым драйвером и достаточной памятью на Linux/Windows — CUDA, отсутствие GPU — CPU. Неизвестная или неподдерживаемая GPU не вызывает молчаливого CPU-отката: CPU требует явного выбора. Поддержка ветви в коде не является её аппаратной аттестацией. Нативные компиляторы, CUDA toolkit и драйвер — явные prerequisites; установщик использует разрешённые пользовательские Homebrew/WinGet операции там, где это возможно, но не обходит MDM, UAC или отсутствие прав и не устанавливает драйвер от имени администратора. Docker daemon и посторонние приложения не перезапускаются.

Модельный процесс принадлежит только Advance Screening и слушает только loopback с собственным ключом из защищённого файла, не из аргумента или env. Docker Desktop на macOS/Windows использует `host.docker.internal`; работоспособность маршрута проверяется отдельно. Linux использует собственный Unix socket с файловыми правами и ограниченным прокси внутри того же владельца, без `network_mode: host` и без LAN-listener. Это внутренний вычислительный компонент одной поставки, не общий модельный сервис или новый межсервисный HTTP-контракт. БД, Kafka, OIDC, gateway identities и корпус ему не выдаются.

Штатный запуск выполняется от текущего пользователя через LaunchAgent, `systemd --user` или ограниченную задачу входа Windows. Установщик проверяет владельца каталога и службы, digest исходников, весов и исполняемого файла, сохраняет предыдущую конфигурацию и не удаляет веса или историю выпусков. Изменение, занятый порт, недостаток памяти и неполная GPU-выгрузка не становятся успешным запуском. Контроль памяти нативного процесса не объявляется Linux cgroup или жёстким пределом всей GPU/хоста; критическое давление останавливает только собственный дочерний процесс.

Готовность runtime отделена от допуска модели и состояния очереди. Установка не выполняет `RESUME`, не переписывает решения и не реализует обучение LoRA. Независимый эксперт получает собственную поставку, данные и адаптеры по ADR-0144; он не подключается к службе, ключам или каталогу Advance Screening.

## Последствия и критерии проверки

- установка и повторный запуск не требуют ИИ, ручного копирования команд или изменения чужих настроек;
- выбор ОС/GPU, проверка происхождения, отказ для чужого каталога/службы и аппаратные ошибки покрываются программными проверками;
- фактические macOS/Metal, Linux/CUDA и Windows/CUDA измеряются и допускаются отдельно;
- соединение контейнера, полный GPU offload, безопасная остановка и перезапуск пользовательской службы проверяются на выбранном хосте;
- без разрешённых системных prerequisites автоматизация закрыто останавливается с причиной, не обещает установку на произвольной корпоративной машине без прав.

## Миграция и откат

Поставка добавочная; рабочие Compose, Process Control, БД и Kafka не меняются. Установка по умолчанию запускает только новую собственную пользовательскую службу; `--no-start` готовит артефакты без её регистрации. Новые выпуски сохраняются рядом со старыми. При отказе установки прежние данные и выпуски не удаляются; возврат прежней конфигурации выполняется с остановкой только собственной службы и проверкой её исходных digest. Это не откат модели на MiniLM/TF-IDF и не разрешение обойти модельный допуск.
