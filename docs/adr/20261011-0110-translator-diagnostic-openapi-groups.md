# ADR-0110: Общая диагностика translator-service в группе default

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261011-0110-translator-diagnostic-openapi-groups.md`; SHA-256: `0cb891aca886680ea75a936840ec93fee9781086bce66d7c5b068ce0cb01f526`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по явному требованию оператора
- **Дата:** 2026-10-11
- **Основание:** A10, ADR-0096, ADR-0109
- **Частично заменяет (Supersedes):** [ADR-0109](20261011-0109-operator-translation-through-kafka.md) только в размещении `GET /v1/status` в группе OpenAPI; операторский вход, транспорт, права и прочие требования сохраняются

## Контекст

`GET /v1/status` возвращает техническое состояние собственной очереди и управления, а не выполняет перевод. Оператор потребовал показывать его рядом с другими диагностическими GET. Принятое решение ADR-0109 сохраняется как история; это уточнение касается только оформления документации API.

## Критерии выбора

- Техническая диагностика отделена от операторских операций перевода и экспорта метрик.
- Пути, ответы, права доступа и Kafka-граница остаются прежними.

## Рассмотренные альтернативы

1. Оставить состояние очереди рядом с переводом: не соответствует требованию оператора.
2. Перенести только его метаданные OpenAPI в `default`: принято.

## Решение

Порядок объявленных групп остаётся `default`, `translator`, `metrics`. `default` содержит `GET /healthz`, `GET /readyz`, `GET /v1/components` и `GET /v1/status`; `translator` содержит только явно включённый операторский `POST /v1/translate`; `metrics` содержит `GET /metrics`. Частная схема по-прежнему не содержит POST. Метаданные диагностики одинаковы на частном и операторском listener.

Общая группа не усиливает гарантии endpoint: `/v1/status` показывает собственную очередь и управление, а не доказывает готовность модели, продвижение работы или здоровье всех зависимостей. Реализация, ответы, HTTP-статусы, OIDC/mTLS, Kafka, настройки и данные не меняются.

## Последствия

- Положительное: все диагностические GET собраны в одном разделе; группа перевода не содержит диагностических операций.
- Ограничение: клиенты, группирующие методы по OpenAPI tags, должны обновить эту группировку; сетевой API остаётся совместимым.

## Критерии проверки

- Модульные проверки подтверждают состав групп для частной и операторской схемы, включая защищённый операторский вход.
- Настоящий Swagger показывает `/v1/status` в `default`; прежние авторизованные GET остаются доступны.

## Миграция и откат

Собрать образ владельца и адресно обновить только `translator-api` его Compose. Новая подготовка OIDC, миграции БД и удаление данных не требуются. Для отката вернуть предыдущий API-образ; пути и ответы сохраняются. Этот документ частично уточняет действующий ADR-0109, а не заменяет его целиком: остальные решения ADR-0109 остаются активными.
