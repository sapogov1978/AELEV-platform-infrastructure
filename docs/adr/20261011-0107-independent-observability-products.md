# ADR-0107: Самостоятельные продукты и слой оркестрации наблюдения

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261011-0107-independent-observability-products.md`; SHA-256: `f84a0c2184756e297cb1d84d712d30bf6f888a6cafd2a11d3253ab09a518995f`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по подтверждению оператора разделить самостоятельные поставки и сохранить слой observability
- **Дата:** 2026-10-11
- **Основание:** A5, A10, A12, ADR-0082, ADR-0090, ADR-0100, ADR-0103, ADR-0104, ADR-0105
- **Частично заменяет (Supersedes):** ADR-0099 только в части обязательной единой поставки нативных процессов; ADR-0104 только в части общего `observability-configuration-init`. Неосведомлённость о потребителях, защищённый транспорт, сохранность телеметрии, независимость издателей и остальные решения сохраняются.

## Контекст

Отдельные Compose продуктов запускали только издателей состояния, а нативные процессы, конфигурация и общая инициализация находились у родителя. Самостоятельный запуск поэтому не соответствовал общему. Оператор подтвердил перенос внутрь владельцев и сохранение observability как слоя запуска всего комплекса.

## Решение

Каждый из семи продуктов имеет единственный канонический Compose с нативным процессом без профиля, собственными конфигурацией, env, секретами, сетью, данными, издателем и тестами. Для шести постоянных томов существуют отдельные явные `*-configuration-init`, работающие без сети и секретов только со своим томом. Blackbox Exporter постоянного тома не имеет. Издатели включаются профилем `ui`, их административная подготовка — одноразовым `run --rm`, не общим `up` профиля provision.

`observability/compose.yml` только включает семь канонических файлов; верхний корень инфраструктуры включает этот слой. В env слоя только имя общей группы и имя включаемого env. Последовательный операторский помощник вызывает подготовку каждого владельца, не хранит шаблоны процессов или настройки потребителей. Панели и предметные правила принадлежат наблюдаемому владельцу; Grafana хранит только рабочие доставленные копии.

Технические операции подготовки и проверки маркера тома распространяются как публичный версионированный wheel `aelev-observability-tools` с SHA-256 в собственном lock каждого продукта. Библиотека принимает декларацию одного владельца и не содержит каталога продуктов или адресов. Общего runtime-образа нет: каждый продукт собирается из своего каталога с собственными закреплёнными артефактами.

Связи между продуктами используют конфигурируемые опубликованные HTTPS/mTLS или TLS gRPC адреса, а не общую Docker-сеть. Локальные aliases host-gateway не заменяют маршрутизацию между странами: при разнесении оператор задаёт реальные адреса, SAN, доверие, bind и firewall. Один экземпляр каждого продукта по умолчанию не означает высокую доступность. Доменные Kafka-контракты и технический контракт доставки телеметрии не меняются.

## Миграция и откат

Перед переключением снимаются прежние контейнеры без удаления томов. Публичные настройки распределяются по собственным префиксам продуктов; подготовленные конфигурации и рабочие удостоверения перемещаются внутрь владельцев. Имена томов, маркеры, identities, UUID, последовательности, исходный журнал, нативные версии, ОС и Python сохраняются. `DATA_OWNER` сохраняет записанную идентичность тома независимо от имени Compose-группы. Чужой или непустой немаркированный том не принимается. Старый общий init больше не используется; прежние определения и связанные тесты архивированы в ближайшем obsolete.

При откате сначала останавливаются новые писатели; совместимый прежний выпуск получает те же данные и удостоверения. Одновременное включение самостоятельной и общей группы поверх одних томов запрещено. `down --volumes`, смена UUID и обнуление журналов не являются миграцией.

## Проверка

Проверяются собственная сборка без соседних исходников, точное равенство самостоятельной и включённой Compose-модели, обязательность env, проверка маркеров, сохранение независимо доставленных файлов, реальные TLS readiness и публикации каждого владельца. Запуск и остановка выполняются из Compose владельца. Проверяется защищённая связность продуктов через опубликованные порты; локальная проверка не выдаётся за межстрановой нагрузочный тест, production PKI или восстановление резервной копии.
