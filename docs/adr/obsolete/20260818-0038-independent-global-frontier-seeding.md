# ADR-0038: Независимое глобальное заполнение фронтира

> **Происхождение standalone-редакции.** Источник: `docs/adr/obsolete/20260818-0038-independent-global-frontier-seeding.md`; SHA-256: `887220ef7482b5e3fc80cd08a07415c96ded8a2b9a2886b8fdc3fb504ef5f09f`; основание включения: цепочка замены. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Заменён [ADR-0039](20260824-0039-system-discovery-inputs-and-evidence-review.md)
- **Дата:** 2026-08-18
- **Основание:** A1, A3, A5, A6, ADR-0037

## Контекст

ADR-0037 разрешил Discovery & Registry самостоятельно исследовать весь публичный Web без предварительной доменной allowlist. Один коммерческий поисковый API не обеспечивает эту обязанность: его индекс, ранжирование, квоты, цена и доступность принадлежат внешнему поставщику. Потеря Brave, Google, Bing или другого провайдера не должна лишать систему глобального обнаружения.

Перебор публичных IP-адресов также не является достаточным источником. Один IP может обслуживать множество доменов, TLS требует имени для SNI, API и документация находятся на неизвестных поддоменах и путях, а облачные адреса меняются. Семантической единицей исследования остаётся URL с происхождением.

## Решение

`search-crawler` является ролью независимого глобального заполнения фронтира, а не клиентом одного поисковика. Обязательный production-путь объединяет:

1. доступные zone files через ICANN CZDS и отдельные реестры доменных зон;
2. публичные журналы Certificate Transparency для доменов и поддоменов;
3. Common Crawl URL Index, Web Graph и архивные метаданные;
4. государственные, регуляторные и отраслевые реестры;
5. ссылки, sitemap, JSON-LD, canonical и `sameAs`, найденные собственным исследовательским обходом.

Brave, Google, Bing и другие коммерческие поисковые API допускаются только как необязательные адаптеры повышения покрытия. Ни один из них не входит в обязательное основание готовности роли и не является единственной исходной точкой.

### Устойчивое получение

Каждый адаптер хранит собственную версию источника, checkpoint, точную ревизию внешнего набора, происхождение URL и состояние повтора. Полная историческая загрузка отделена от инкрементального обновления. Повтор той же ревизии идемпотентен; новая ревизия не удаляет прежнее происхождение.

Zone data и Certificate Transparency создают кандидаты доменных имён, но не доказывают существование пригодного сайта или право его регулярного использования. Common Crawl подтверждает наличие архивного снимка, но свежая страница всё равно проходит исследовательское чтение и политику ADR-0037.

### Область сканирования

Система не выполняет слепой перебор IP-пространства и не ищет скрытые панели. Для доменного кандидата разрешены DNS-проверка, HTTPS и ограниченные публичные точки `robots.txt`, корневая страница, объявленные sitemap, well-known ссылки и ссылки из полученного документа. Приватные, служебные и metadata-адреса блокируются public-egress gateway.

Глобальность означает отсутствие заранее конечного списка доменов. Каждый конкретный запрос ограничен бюджетом, per-host rate limit, глубиной и числом ссылок. Планировщик повышает приоритет по пробелам покрытия стран, языков, классов источников и типов данных, но не исключает долгосрочный backfill.

### Платные источники

CZDS zone file, коммерческий индекс или иной источник, требующий соглашения или credentials, проходит обычный допуск точной ревизии. До получения полномочий он остаётся кандидатом; отсутствие платного адаптера не блокирует независимые бесплатные пути.

## Критерии проверки

- новый домен попадает во фронтир из Common Crawl без поискового API;
- домен и поддомен попадают из zone data и Certificate Transparency с точным происхождением и checkpoint;
- повтор ревизии не создаёт вторую цель и не теряет доказательство;
- прерванная массовая загрузка продолжается с устойчивого checkpoint;
- отключение всех коммерческих поисковых ключей не останавливает глобальное заполнение;
- найденный домен проходит ADR-0037 и не становится регулярным источником автоматически;
- массовый источник соблюдает общий бюджет и не обходит public-egress gateway.

## Последствия

Discovery & Registry получает независимое и проверяемое покрытие, но должен обрабатывать крупные внешние наборы, изменения зон и постоянно растущие CT logs. Нужны отдельные метрики покрытия, отставания, стоимости и качества.
