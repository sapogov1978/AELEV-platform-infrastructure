# ADR-0041: Управляемый каталог зон и техническое состояние в PostgreSQL

> **Происхождение standalone-редакции.** Источник: `docs/adr/obsolete/20260824-0041-postgresql-zone-catalog-and-operator-control.md`; SHA-256: `a18f9b22d55bbe025f14a3db75d993df42ac78e2aeb513d35aac4ec83703a9a6`; основание включения: цепочка замены. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Заменён ADR-0045
- **Дата:** 2026-08-24
- **Основание:** A1, A3, A5, ADR-0039
- **Заменяет:** ADR-0040

## Контекст

ADR-0040 смешал три разных объекта: полный перечень TLD корневой зоны, доступность содержимого отдельной зоны и технический прогресс разбора zone file. В результате оператор видел только `.se` и `.nu`, хотя официальный файл IANA содержит полный текущий перечень. Технические checkpoints и порции были помещены в Neo4j, а полный вспомогательный zone file — в постоянное MinIO. Ни графовая модель, ни бессрочное объектное хранение для этого состояния не нужны.

## Решение

1. `https://data.iana.org/TLD/tlds-alpha-by-domain.txt` является единственным источником состава текущего каталога корневых TLD. Закрытый системный вход синхронизирует его автоматически каждые 86 400 секунд. Оператор может запросить немедленную синхронизацию.
2. PostgreSQL Discovery & Registry хранит текущий управляемый каталог зон, доступность способа получения, операторское включение, точную ревизию, checkpoints и журнал обработанных порций. Эти данные не являются вершинами предметного графа.
3. Все текущие TLD отображаются одинаково. `.se` и `.nu` не имеют специального статуса: для них лишь известен публичный способ получить zone file от Internetstiftelsen. IANA подтверждает существование TLD, но не предоставляет список делегаций внутри него.
4. Оператор может включить или выключить TLD из текущего IANA-каталога. Включение зоны без подключённого способа получения сохраняет намерение, но не создаёт слепой AXFR. Произвольный server или URL нельзя добавить через HTTP: список сетевых назначений остаётся конфигурацией выпуска по ADR-0039.
5. Полный zone file является временным входом одного исполнения. Worker пишет его в ограниченный spool, вычисляет SHA-256, обрабатывает до конца порциями и удаляет файл. PostgreSQL сохраняет digest, URL получения, размер, позиции и счётчики, но не тело zone file. MinIO для zone data не используется.
6. Зоны с доступным способом получения запускаются независимо и с ограниченной параллельностью. Сбой одной зоны не отменяет зафиксированный прогресс другой. Идемпотентный глобальный фронтир не получает дубликат цели.
7. Старые zone/TLD-узлы Neo4j остаются историческими данными прежнего решения, но новые записи туда не создаются и операторский API их не читает.

## Последствия

- оператор видит полный каталог IANA, а не две зоны одного поставщика;
- PostgreSQL становится единственным владельцем текущего управления и технического прогресса зон;
- MinIO не растёт от вспомогательных zone files;
- после аварии во время разбора точная ревизия может быть загружена повторно; digest запрещает продолжить под тем же revision при изменившемся содержимом;
- наличие TLD не выдаётся за наличие полного списка доменов внутри него.

## Критерии проверки

- синхронизация IANA создаёт строку для каждого TLD и не сбрасывает ручное включение;
- расписание IANA равно 86 400 секундам, доступна ручная команда обновления;
- API и UI позволяют искать, включать и выключать зоны;
- зона без способа получения отображается как `NO_PROVIDER` и не вызывает AXFR;
- zone catalog, availability, checkpoint и batch находятся в PostgreSQL;
- новый zone run не создаёт `ZoneDataCheckpoint`, `ZoneDataBatchRecord` или `TldCatalogEntry` в Neo4j и не сохраняет zone file в MinIO;
- две доступные зоны получают независимую работу в одном запуске.
