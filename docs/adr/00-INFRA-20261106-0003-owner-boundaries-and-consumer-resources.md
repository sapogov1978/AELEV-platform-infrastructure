# 00-INFRA-20261106-0003-owner-boundaries-and-consumer-resources — Границы владельцев и ресурсы потребителей

- **Статус:** Принят
- **Дата:** 2026-11-06
- **Происхождение:** неизменяемые ADR-0003, ADR-0006 и ADR-0103 из [архива выделения](../audit/inherited-adrs/INDEX.md)

## Контекст

Инфраструктурный продукт должен предоставлять общие технические возможности любой предметной области и не становиться владельцем ресурсов конкретного приложения.

## Ключевые решения

- Каждый инфраструктурный сервис имеет единственного владельца исполняемой конфигурации, данных, журналов и жизненного цикла.
- Инфраструктура публикует только общие технические возможности и стабильные контракты.
- Базы, schemas, Kafka topics, buckets, OIDC clients, grants, dashboards, policies, адреса и иные ресурсы конкретного приложения принадлежат потребителю.
- Потребитель создаёт свои ресурсы через публичные административные интерфейсы, но не получает право изменять внутреннее состояние провайдера.
- Между владельцами передаются контрактные сообщения или непрозрачные ссылки; общий файловый каталог, сокет, база или изменяемый том не являются интерфейсом.

## Последствия

- Репозиторий остаётся domain-neutral и не содержит каталога приложений.
- Удаление или остановка потребителя не останавливает инфраструктуру и не удаляет общие данные.
- Конкретные примеры потребителя допускаются только как явно нейтральные тестовые fixtures.

## Проверка и откат

Boundary-gate запрещает предметные runtime-идентификаторы и соседние source imports. Тесты проверяют отсутствие application resources в корневой композиции. Откат документации не переносит владение ресурсами и не разрешает совместных писателей.

## Официальные основания

- [Microsoft guidance по bounded contexts](https://learn.microsoft.com/en-us/azure/architecture/microservices/model/domain-analysis) описывает разделение моделей и ответственности владельцев.
- [Docker Compose include](https://docs.docker.com/reference/compose-file/include/) сохраняет собственный project directory включаемого поддомена.
- [Docker Compose services](https://docs.docker.com/reference/compose-file/services/) описывает явные технические интерфейсы сервисов, networks, volumes и secrets.
