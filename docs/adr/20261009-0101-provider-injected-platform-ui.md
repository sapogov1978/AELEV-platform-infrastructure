# ADR-0101: Универсальная оболочка с разделами и состоянием от владельцев

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261009-0101-provider-injected-platform-ui.md`; SHA-256: `f23aa88230bd268756a5ab09d6a22e133c496cf48bf9c6780c78725258dbaf1e`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Частично заменён [ADR-0102](20261009-0102-owner-controlled-shared-refresh-indicator.md) в ограничении браузерных сообщений оформлением и языком, [ADR-0105](20261010-0105-publisher-presence-and-graceful-withdrawal.md) в присутствии строк и штатной отписке, [ADR-0108](20261011-0108-loopback-operator-http.md) в HTTPS для внешних операторских ссылок на loopback, [ADR-0115](20261012-0115-owner-local-embedded-sqlite.md) только в утверждении о восстановлении всех данных приёмника повторной публикацией, [ADR-0117](20261012-0117-loopback-http-embedded-ui.md) в HTTPS для внедряемого UI на точном loopback и [ADR-0161](20261027-0161-owner-declared-platform-navigation-order.md) в неоговорённом порядке функциональной навигации; остальные требования действуют
- **Дата:** 2026-10-09
- **Основание:** A5, A10, A12, ADR-0017, ADR-0082, ADR-0095, ADR-0100
- **Частично заменяет (Supersedes):** ADR-0095 в части запрета встраивания и ограничения оболочки зашитым перечнем инфраструктуры; запрет обнаружения Docker/Kubernetes, исходного каталога потребителей и передачи чужих токенов сохраняется

## Контекст

Оператор уточнил основную ответственность `platform-ui`: контейнер страниц, общие стили и принципы отображения. Сервис сам предоставляет название, разделы и техническое состояние. Перечень продуктов в исходниках оболочки и сборка из соседних деревьев противоречат этой ответственности. При этом прежний автоматический каталог Docker и общий доступ к предметным API возвращать нельзя.

## Критерии выбора

- добавление владельца не изменяет исходники, env или образ оболочки;
- владелец сохраняет UI, данные, авторизацию и административные действия внутри своей границы;
- инъекция, просмотр и состояние имеют проверяемую идентичность, ограничения и происхождение;
- географическое разнесение не требует общей файловой системы или Docker-сети;
- поставка оболочки отдельно собирается, использует обязательные настройки и HTTPS.

## Рассмотренные альтернативы

1. Зашитая инфраструктурная панель. Отклонено по уточнению оператора: оболочка заранее знает участников.
2. Исполнение присланного JavaScript в основном окне. Отклонено: модуль получает DOM и токены оболочки.
3. Универсальное описание предметных форм с выполнением команд оболочкой. Отклонено: оболочка становится вторым владельцем предметного поведения.
4. Самостоятельные UI в изолированных междоменных `iframe`, технические описания и состояние от авторизованного владельца. Принято.

## Решение

`platform-ui` содержит только навигацию, оформление, вход и представление технических описаний. В его исходниках, примерах и тестах нет перечня конкретных потребителей. Каждый владелец публикует версионированное описание и отдельно обновляет техническое состояние по [контракту инъекции](../api/platform-ui-injection.md). Это технический интерфейс представления, не доменный транспорт: команды, данные и канонические хранилища через него не проходят. Kafka-домен и устойчивая телеметрия ADR-0100 не меняются.

API оболочки проверяет JWT, точные issuer/audience, сроки и собственные роли. Публикация дополнительно требует mTLS. Модуль принадлежит субъекту издателя; другой субъект не меняет его описание или состояние. Повтор ревизии идемпотентен только при тех же байтах, старые и конфликтующие ревизии отклоняются. Технические метаданные и журнал изменений сохраняются в собственной SQLite с WAL/FULL; перед подтверждением изменение фиксируется. Эта рабочая копия производна от декларации владельца и восстанавливается повторной публикацией. Она не является исходным каталогом потребителей или владельцем их данных.

Отсутствующее/просроченное сообщение состояния означает `UNKNOWN`, не синтетический `OFFLINE` и не доказанную работоспособность. Оболочка не опрашивает сервисы, Prometheus или Docker ради обнаружения. Название и состояние неизвестного модуля не создаются из встроенного списка.

Содержимое раздела исполняется на другом HTTPS origin в ограниченном `iframe`. Основное окно не передаёт токены, пользовательские данные или команды. Сообщения `postMessage` проверяют точные origin/source и разрешают только версию контекста оформления и язык. Сервис самостоятельно организует свой вход и разрешает выбранный origin оболочки в CSP. Версионированный публичный CSS-артефакт оболочки задаёт технические правила оформления; владелец подключает его явно и закрепляет digest. Источники соседней библиотеки не копируются в сборку.

Одна поставка содержит nginx с HTTPS и собственный Python API, отдельные настройки и один постоянный том. Одноразовая задача из профиля `provision` создаёт только собственный OIDC-клиент/роли оболочки; чужие клиенты не перечисляются. Каждый издатель получает полномочия в своей задаче развёртывания. Доверие, endpoint и собственные секреты задаются явно; удалённые узлы используют те же файлы, без абсолютных путей автора. Локальная PKI не заменяет продукционный допуск ADR-0017.

## Последствия

Появляется небольшой технический API приёма вместо встроенной панели. Без инъекций оболочка пуста, но работоспособна. Подключение конкретного UI выполняется владельцем отдельно; этот ADR не объявляет существующие UI уже подключёнными. Компрометация издателя ограничена его модулями и содержимым отдельного origin.

## Критерии проверки

- сборка из отдельного каталога и отсутствие запасных настроек;
- настоящий OIDC-вход, JWT/mTLS-отказы и запрет изменения чужого модуля;
- инъекция, идемпотентность, конфликт, состояние и переход в `UNKNOWN`;
- изоляция браузерного раздела и отсутствие передачи токена;
- перезапуск с сохранением технической копии;
- очистка созданного тестом с сохранением исходных ресурсов, затем отдельный рабочий запуск.

## Миграция и откат

Старые зашитая панель, зависимости соседнего UI-kit и корневые OIDC-описания оболочки заменяются собственной поставкой. Нельзя автоматически импортировать прежний Docker-каталог или выдавать новую роль старым издателям. Изменённое решение оформляется здесь; прежние ADR остаются историческими. При откате сохраняются том и декларации владельцев; прежний образ не считается реализацией нового контракта. Полные production PKI/ротация, внешнее размещение, резервное восстановление и допуск цепочки поставки проверяются отдельно.
