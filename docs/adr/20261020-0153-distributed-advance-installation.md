# ADR-0153: Согласованная установка двух частей Advance Screening

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261020-0153-distributed-advance-installation.md`; SHA-256: `e177f535c0c5f8a8154bbc52cdf61882cd94cb68c96f1620fac99c2573e122c4`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по явному согласованию пользователя от 2026-10-20
- **Дата:** 2026-10-20
- **Основание:** A5, A10, A12, ADR-0082, ADR-0113, ADR-0143, ADR-0146, ADR-0150
- **Заменяет (Supersedes):** ADR-0146 только в части обязательного размещения вычислителя на том же физическом хосте и запрета защищённого удалённого endpoint. Остальные ограничения сохраняются.

## Контекст

Управляющая Docker-поставка Advance Screening и её вычислитель могут находиться на разных физических компьютерах. Локальный heartbeat-файл, Unix socket, `host.docker.internal` и каталоги обучения не являются межмашинным интерфейсом. Подготовка всех собственных ресурсов должна выполняться установщиками, а не последовательностью ручных правок.

## Критерии выбора

- две самостоятельные согласованные установки одного владельца;
- постоянные собственные Docker volumes для конфигурации, удостоверений, моделей и журналов;
- отсутствие административных ключей, Docker socket и универсального shell в рабочих ролях;
- сохранение identities, данных, допуска и команд процессов при повторе;
- начальное доверие и проверка готовности без ручной послепусковой правки конфигурации.

## Рассмотренные альтернативы

1. Общий диск или удалённый Docker context. Отклонено: не задаёт безопасный интерфейс вычислений.
2. Открытый HTTP endpoint без собственной identity. Отклонено: не проверяет подлинность и происхождение.
3. Две установки одного владельца с ограниченным HTTPS/mTLS-каналом. Принято.

## Решение

Управляющая и вычислительная части принадлежат только Advance Screening. Это не новый прикладной сервис или общий LLM endpoint. Управляющая часть владеет заданиями, решениями, корпусом, допуском и Kafka outbox. Вычислительная часть получает только ограниченные вычислительные задания и сохраняет собственные веса, адаптеры и технические результаты; БД, Kafka, gateway credentials и права предметной публикации ей не выдаются.

Локальный режим совместим с ADR-0146. Для разных машин используется ограниченный HTTPS endpoint с взаимным TLS, проверкой hostname и точной identity установки, digest модели, движка и адаптера и свежести состояния. Открытый HTTP, отключение TLS-проверок, перенаправления, универсальный proxy и удалённые shell/Docker-команды запрещены. Состояние получается по защищённому каналу, а не с общего диска. Потеря связи не становится тематическим отказом сайта.

Установщики получают адреса, доверие и разрешённые deployment-полномочия один раз, автоматически подготавливают ресурсы через штатные инструменты провайдеров и согласуют конечные настройки. Неизвестный сертификат из сети сам по себе не становится доверенным. Административные входы не попадают в рабочие volumes; каждая роль видит только собственные необходимые credentials. Конфигурация, identities, веса и журналы сохраняются в собственных Docker volumes. Пауза очереди, собственность меток и независимый допуск LoRA не меняются.

Драйверы и корпоративные ограничения не обходятся. NVIDIA, Metal и CPU являются отдельными проверяемыми ветвями. MLX не объявляется NVIDIA trainer из-за добавления сети; новый обучающий исполнитель требует собственных закреплённых зависимостей и проверки. TODO реального обучения по ADR-0150 сохраняется. Успешный старт контейнера не заменяет проверку соединения и вычисления на фактическом оборудовании.

## Последствия

Положительные: две физические установки не требуют общих файлов, секреты и владелец остаются раздельными, параметры согласуются автоматически. Отрицательные: нужны проверка сети, сроков удостоверений, совместимости, прерывания и повтора установки. Недоступный образ, отсутствующее полномочие или ресурс закрыто останавливают соответствующий этап.

## Критерии проверки

- установка и повтор не требуют ручной правки `.env` или копирования конечных ключей;
- конфигурация и identities переживают пересоздание контейнеров;
- неправильное доверие, hostname, identity, digest, просроченное состояние и чужой клиент отклоняются;
- разрыв связи сохраняет очередь и ограничивает повторы;
- проверка изолированных узлов не выдаётся за испытание отсутствующего GPU;
- незавершённые этапы установки и обучения не обозначаются успешными.

## Миграция и откат

Существующие локальные descriptors и службы сохраняются. Удалённая поставка добавляется без переключения рабочего стенда и без RESUME. Смена адреса не меняет выбранный выпуск. Откат возвращает предыдущую совместимую конфигурацию без удаления volumes, данных и истории. Реализованные и проверенные этапы указываются отдельно от нормативной цели полной установки.
