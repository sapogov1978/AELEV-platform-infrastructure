# ADR-0075: Сравнение дообученной MiniLM с действующим выпуском и многоязычный TF-IDF

- **Статус:** Частично заменён ADR-0129: MiniLM, TF-IDF и обучение исключены из `base-screening`, но сохраняются у самостоятельных последующих стадий
- **Дата:** 2026-10-04
- **Основание:** A5, A10, A12, ADR-0057, ADR-0063, ADR-0069; решение сравнивать новую голову MiniLM с действующим выпуском
- **Заменяет (Supersedes):** требование минимум двух разных trainer для следующего выпуска ADR-0065 и унаследованного цикла ADR-0059; ограничение английским языком новых TF-IDF-допусков ADR-0068; требование ADR-0066 допускать весь набор профилей корпуса для нового автоматического admission. Исторические допуски и остальные ограничения сохраняются.

## Решение

Проверка документа и выбор нового выпуска — разные процессы. Рабочий каскад состоит из локализованных буквальных признаков, быстрого TF-IDF и более дорогой MiniLM; воздержание последнего этапа поступает оператору. Перевод исходного документа на английский для классификации не выполняется. Перевод карточки остаётся только вспомогательным материалом оператора.

Для нового цикла достаточно одного выбранного MiniLM trainer. До обучения закрепляются точный действующий bundle и ранее использованные семейства документов. Новая голова и действующий выпуск сравниваются на одних исходных HOLDOUT-документах с одним извлечением замороженных MiniLM-признаков; действующий выпуск не обучается повторно и не изображается вторым trainer. Изменение политики сравнения не разрешает повторное открытие уже раскрытого HOLDOUT.

Кандидат допускается только при технической пригодности, отсутствии наблюдавшихся ложных автоматических отказов, отсутствии регрессии в целом, по каждому классу и наблюдаемому языку и измеримом увеличении правильно снятых отрицательных семейств. Требуется не менее трёх свежих независимых HOLDOUT-семейств каждого класса. Точные и почти одинаковые документы из прежних испытаний не считаются свежими. Порог определяется до HOLDOUT только по VALIDATION. Нехватка данных, нарушение ресурсов, регрессия или отсутствие улучшения сохраняют действующий выпуск и явно показывают причину; вторую архитектуру модели система не требует.

TF-IDF обучается на исходных Unicode-текстах TRAIN, калибруется на VALIDATION и проверяется одновременно с новым выпуском. Языки не задаются английским списком в коде: автоматический отсев разрешается отдельно для проверенной пары точного профиля и базового языка. Неизвестный язык, отсутствие обоих классов или независимого покрытия, смешанный язык, положительный результат и недостаточная уверенность обязательно доходят до MiniLM. Исторический английский допуск не расширяется и не переписывается; следующий выпуск имеет собственные данные и область допуска.

Результат сравнения и точный допуск принадлежат PostgreSQL crawler. Автоматический выпуск не наследует admission прежней головы: создаются новые неизменяемые сравнение, проверенные артефакты, допуск и атомарный bundle. Materialization, проверка реально работающего runtime по точному TRAIN-запросу и сохранение предыдущего выпуска обязательны. Новая версия политики может автоматически менять только привязку к выпуску при неизменных критериях и неизменной исходной версии; человеческие решения сохраняются. Временное бинарное разрешение ADR-0070 не продлевается автоматически и не становится допуском качества.

## Проверки и миграция

Для нового автоматического допуска MiniLM набор `admitted_profile_refs` является проверенным подмножеством профилей неизменяемого корпуса: каждой допущенной области нужны оба класса и минимум три независимых семейства каждого класса в VALIDATION и свежем HOLDOUT. Это частично заменяет требование ADR-0066 о равенстве всему набору корпуса только для admission `1.2.0`; исторический допуск сохраняется. Новый TF-IDF дополнительно проверяется не менее чем на 100 отдельных HOLDOUT-документах в целом; область языка требует собственного независимого покрытия обоих классов. TF-IDF не переносит смысл английских обучающих примеров на другой язык автоматически.

Новая политика сравнения имеет отдельную версию. Старые задания, корпуса, результаты и допуски остаются неизменными; завершённое старое задание не запускается заново. Проверки охватывают один trainer с двумя версиями головы, свежесть семейств, регрессию, неизвестный результат после HOLDOUT, многоязычный отсев без переводчика, обязательную передачу MiniLM и сохранение operator history. Смена выпуска не меняет Kafka, межсервисные контракты, предметное знание или ограничения внешнего потребителя.
