# ADR-0112: Закреплённая Index-Translate 9B вместо MADLAD

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261011-0112-index-translate-9b.md`; SHA-256: `67a981ae0e6899d066019e1d3406f0539c486d880bd64dbefc7861fdc51d6835`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Частично заменён [ADR-0124](20261013-0124-provider-owned-translation-execution.md) в обязанности клиента выбирать `translator_ref`; выбор модели и внутреннее закрепление исполнения сохраняются
- **Дата:** 2026-10-11
- **Основание:** A5, A10, A12, ADR-0087, ADR-0096, ADR-0109
- **Частично заменяет (Supersedes):** [ADR-0087](20261008-0087-infrastructure-translator-service.md) и [ADR-0096](20261009-0096-consumer-agnostic-scalable-translator.md) только в выборе MADLAD и его Rust-вычислителя; владение, Kafka-граница, собственная БД, вычислительные ячейки и контракт v1 сохраняются

## Контекст

[Сравнительный эксперимент](../../services/infrastructure/translator-service/test/model_comparison/result.md) выполнил по 40 переводов MADLAD, Index-Translate 2B и Index-Translate 9B на одном корпусе. Оператор выбрал 9B по качеству проверенных им ответов, явно приняв больший расход памяти и задержку. Измеренные значения 9B в эксперименте: p50 15,103 секунды, p95 25,287 секунды, максимум памяти контейнера 5,710 ГиБ при двух CPU. Корпус ограничен и не удостоверяет качество всех языков или всех текстов.

MADLAD и Index-Translate имеют разные архитектуры: подмена файла весов в прежнем вычислителе не работает. Требуется смена внутреннего движка без нового межсервисного интерфейса и без изменения Python, ОС, Kafka или структуры события.

## Решение

1. Действующий выбор — официальный `IndexTeam/Index-Translate-9B-GGUF`, `Index-Translate-9B.Q4_K_M.gguf`, Apache-2.0. Единственный канонический источник выбранных весов, SHA-256, размера, ревизий и параметров вычисления — собственный `translator.lock.json`. Задача сборки читает его напрямую, загружает диапазоны с ограниченным повтором и проверяет итоговые размер/SHA-256; тест сверяет рецепт с lock. Официальное зеркало ModelScope допускается только для тех же проверенных байтов, не как иной выпуск модели.
2. Python-вычислитель управляет закреплённым `llama.cpp` внутри контейнера `translator-model`. Нативный дочерний процесс слушает только loopback этого контейнера, работает без сетевого доступа и не предоставляет браузерный UI. Наружная граница вычислительной ячейки остаётся приватным Unix socket только для своего worker. C++ нужен для нативной зависимости выбранной модели; новый язык бизнес-реализации или общий модельный сервер не вводится. Python 3.13.7, Debian Bookworm и Poetry 2.2.1 сохраняются.
3. Профиль `index-plain-v1` соответствует проверенному простому запросу поставщика: без рассуждений, с температурой 0, закреплённым seed и без кеширования контекста чужих заданий. Два потока, контекст 2048 и бюджет ответа 1024 токена закреплены в lock. Длинный полный текст обрабатывается последовательными фрагментами; переполнение контекста или обрезанный ответ требуют меньшего фрагмента, а не выдачи неполного перевода как успеха. Общий deadline сохраняется; произвольный текст предельного размера не получает обещания завершиться за него.
4. `translator_ref` — SHA-256 канонического JSON объекта `{"model_sha256": ..., "runtime": ...}` с сортировкой ключей и разделителями `,`/`:`. Поэтому смена движка, профиля или параметров вместе с весами меняет идентификатор вычислительного выпуска. Имя поля и схема v1 не меняются. Клиент обязан указать новый точный идентификатор; переводчик не переписывает старый запрос и не выдаёт новую модель за прежнюю.
5. Каталог кодов внутри владельца соответствует заявленным поставщиком 150 языкам. Поддерживаемые ISO-коды и точные варианты письма разрешаются явно; неподдерживаемый код завершается технической ошибкой, без угадывания языка. Это заявленная поддержка модели, не подтверждение измеренного качества всех 150 языков.
6. Предел памяти локальной модели в примере поставки — 8 ГиБ вместо 4 ГиБ. Узел должен иметь эту память с запасом для ОС и остальных процессов; Compose не меняет ресурсы Docker VM или компьютера автоматически. Масштабирование остаётся добавлением одинаковых вычислительных ячеек, не общим socket между странами.
7. Обновление модели не выполняется автоматически. Новый кандидат получает отдельную закреплённую оценку, проверку качества и ресурсов, явное разрешение оператора, новый lock/идентификатор и проверку полного пути через Kafka. Исходники прежнего вычислителя сохраняются только как исторические материалы в собственном `obsolete`, не участвуют в сборке и тестировании действующей поставки.

## Миграция и сохранность

Публичные `TranslationRequested`/`TranslationCompleted`, две входные очереди, выходной topic, PostgreSQL, leases и outbox сохраняются. Схема БД не меняется. По умолчанию смена модели не разрешает удаление чьих-либо данных. В этом локальном переходе оператор отдельно разрешил удалить старые образы MADLAD, старые переводы и хвосты трёх принадлежащих переводчику topics; перед очисткой проверяется точное владение. Чужие topics, БД, контейнеры и системные настройки не входят в это разрешение. При отсутствии записей ничего удалять из пустой очереди не требуется.

Клиенты переводчика обновляют собственную конфигурацию идентификатора модели внутри своих границ. Их имена и настройки не появляются в инфраструктурном сервисе. Для исторического воспроизведения старый выпуск пришлось бы отдельно получить по архивному lock; сохранение старого образа на этом компьютере не является условием перехода и оператором явно отклонено.

## Проверка

Проверяются совпадение весов с SHA-256 и размером, совпадение нативной ревизии, невозможность незаметно изменить профиль, языковые коды, полный текст, отказ от обрезанного ответа, изоляция заданий, FIFO, ограниченный timeout и восстановление вычислителя. После сборки отдельно проверяются действующие Kafka и собственная БД: обе очереди, результат/outbox, повтор запроса без вычисления и перевод после перезапуска. Экспериментальный отчёт не подменяет эту проверку установленного сервиса.
