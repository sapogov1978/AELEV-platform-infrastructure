# ADR-0111: Отдельный операторский вход и явные режимы запуска

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261011-0111-owner-operator-access-modes.md`; SHA-256: `467123a58d7130fab3685330bce54b1d03c2774b3cc1bb0a79edf71eae80c8ac`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Принят по явному подтверждению оператора
- **Дата:** 2026-10-11
- **Основание:** A10, A12, ADR-0017, ADR-0082, ADR-0099, ADR-0107, ADR-0108
- **Частично заменяет (Supersedes):** ADR-0108 только в запрете дополнительного собственного прокси и постоянного контейнера для нативных продуктов без браузерной OIDC-авторизации. Правила переводчика, loopback, HTTPS и изоляция сохраняются.

## Контекст

Prometheus и Blackbox Exporter принимают технические запросы по mTLS. Браузер корпоративного компьютера не имеет клиентского удостоверения, а изменение системного доверия запрещено владельцем. Снятие проверки сертификата с существующего порта ослабит технические соединения; профили Compose сами по себе не изменяют настройки одного процесса.

## Критерии выбора

- Технические адреса, TLS/mTLS и данные не меняются.
- Режим задаётся явно собственным env, без автоматического перехода к HTTP.
- Сборка и запуск остаются внутри каждого владельца, без общего рабочего образа.
- Браузер авторизуется через Keycloak; права оболочки и технические ключи не передаются.

## Рассмотренные альтернативы

1. Установка сертификатов на корпоративный компьютер: запрещена оператором.
2. Отключение mTLS нативного порта или анонимный локальный интерфейс: отклонены.
3. Прокси в platform-ui или общая поставка доступа: отклонены из-за нарушения изоляции.
4. Отдельная операторская роль в каноническом Compose каждого владельца: принято.

## Решение

Prometheus и Blackbox Exporter поставляют собственную роль операторского входа, собранную в своём техническом образе. Общая реализация допустима только как независимо версионированный публичный артефакт с digest по ADR-0082; она не содержит каталога продуктов, потребителей или адресов. Оркестраторы включают те же сервисные модели без поправок.

`OPERATOR_MODE=local-test` требует HTTP на точном loopback origin и `OPERATOR_BIND=127.0.0.1`. `prod` требует HTTPS с серверным сертификатом, но не клиентским сертификатом браузера. Отсутствие или несовместимость настройки/сертификата запрещает запуск; запасного режима нет. Производственные доверие и ротация соответствуют ADR-0017. Локальный HTTP не предназначен для другого компьютера; удалённый оператор использует HTTPS либо явно настроенный локальный туннель.

Вход имеет собственный confidential OIDC-клиент с authorization code и обязательным PKCE S256, точным callback, без password/implicit grant и service account. Одноразовая задача владельца назначает собственную роль `operator-read` явно указанному существующему оператору и не перезаписывает чужой клиент. Runtime получает только собственный client secret и CA IdP, не административные реквизиты. Подтверждённая HTTPS-интроспекция проверяет active, issuer, audience, authorized party, срок и собственную роль; недоступность IdP закрывает доступ. Токены остаются только в ограниченной памяти процесса; браузер получает непрозрачную короткоживущую HttpOnly/SameSite cookie, Secure в prod. Перезапуск завершает сеансы; пароль пользователя не хранится у продукта.

Прокси обращается только к явно заданному собственному HTTPS endpoint с проверкой CA/SAN и своим клиентским сертификатом. Он не пересылает браузерные Cookie/Authorization, не принимает произвольный upstream и не выполняет административные команды, запись телеметрии или удаление данных. Разрешены GET/HEAD и ограниченный POST запросов чтения Prometheus с проверкой origin. Приватная проверка процесса всегда использует отдельный mTLS listener без host-публикации; издатель отражает операторский вход отдельной составной частью. Нативные продукты не зависят от UI или готовности операторского входа.

## Последствия

Production-доставка предоставляет отдельные удостоверения экземпляра через собственный OPERATOR_TLS_ROOT по ADR-0017, а не заимствует identity нативного процесса. Совпадающий с нативным каталог только в текущем локальном env является повторным использованием тестовой PKI, не продукционной SPIFFE-identity. Испытание переключения listener с этой PKI не закрывает проверку SVID/ротации.

Браузеру не требуется технический сертификат, а межкомпонентная защита сохраняется. Цена — одна дополнительная собственная роль у каждого затронутого продукта и зависимость только браузерного входа от IdP. Локальный HTTP не шифрует трафик и не заменяет production TLS. Доменный Kafka-транспорт, интерфейсы других продуктов, Python и ОС не меняются.

## Критерии проверки

- Недопустимые режимы, широкая публикация local-test, HTTP IdP/upstream и HTTP prod отклоняются.
- Без собственного права вход закрыт; повтор/подмена state и callback без cookie не создают сеанс.
- Настоящие интерфейсы открываются без клиентского сертификата браузера; нативные порты продолжают отвергать клиента без сертификата.
- Запись, reload, административный API и подмена upstream запрещены; Cookie/Authorization не доходят до нативного продукта.
- Самостоятельная, родительская и корневая Compose-модели совпадают; технические сбор/пробы и остальные контейнеры сохраняются.

## Миграция и откат

Сначала собираются собственные новые образы и явно подготавливаются OIDC-клиенты. Операторские порты отдельны от прежних технических: локально 19091 и 19116 вместо технических 19090 и 19115. Издатели публикуют новые ссылки и состав в большей ревизии без смены UUID или сброса последовательности. Адресно запускаются операторские роли и обновляются издатели; нативные процессы и тома не пересоздаются. При откате владелец сначала публикует прежние HTTPS ссылки/состав в ещё большей ревизии, затем снимает собственный адаптер; данные и журналы сохраняются.
