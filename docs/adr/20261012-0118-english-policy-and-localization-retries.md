# ADR-0118: Английская каноническая политика и повторяемые локализации

> **Происхождение standalone-редакции.** Источник: `docs/adr/20261012-0118-english-policy-and-localization-retries.md`; SHA-256: `448a759680154cd6fc1c2ce23958214fec0cbd02c82eb09ec274a20b0d89c419`; основание включения: прямая ссылка из поставки. Сохранены номер, статус, история замены и применимые решения; упоминания исключённых bounded contexts нейтрализованы без переноса их контрактов.

- **Статус:** Частично заменён [ADR-0122](20261013-0122-symmetric-topic-declaration.md) в предметной форме и [ADR-0124](20261013-0124-provider-owned-translation-execution.md) в зависимости от выпуска переводчика и условии планового повтора; сохраняются английский канон, UX локализаций и повтор перевода
- **Дата:** 2026-10-12
- **Основание:** A5, A10, A12, ADR-0087, ADR-0112, ADR-0116
- **Дополняет:** [ADR-0116](obsolete/20261012-0116-policy-management-service.md) в представлении предметного редактора, каноническом языке и жизненном цикле повторного перевода

## Контекст

Первый UI PMS повторил техническую форму импорта: показывал внутренний ключ, схему, сырой JSON, исходный язык и массив строк. Это раскрывало оператору детали хранения вместо согласованной предметной формы, допускало неанглийский источник и не позволяло заново запросить уже завершившийся перевод. Первая локальная поставка также была запущена с пустой БД без обязательного переноса последней политики, а неподдерживаемый моделью язык завершался ошибкой без явного английского fallback и автоматической повторной проверки после смены модели.

## Решение

Канонический язык каждой новой версии политики — только английский `en`. Русский и любой другой встреченный язык являются локализациями. Функциональный сервис по-прежнему сообщает только требуемый язык через Kafka, а PMS хранит отдельную запись локализации даже при неподдерживаемом языке; до готовности применяется неизменяемый английский снимок, и это состояние не выдаётся за завершённый перевод.

Предметный редактор темы содержит ровно название темы, краткое описание, положительные слова и фразы и отрицательные слова и фразы. Внутренний `policy_key`, числовая версия, схема, `policy_ref`, `localization_ref`, модель и номер попытки не являются предметными полями: они доступны только по отдельным ссылкам внизу страницы и открываются в модальных окнах. Platform UI не повторяет заголовок внедрённого владельца над iframe; единственная кнопка навигации называется именем сервиса, а сам сервис заявляет заголовок внутри собственного артефакта.

Любую неанглийскую локализацию можно запросить заново независимо от её текущего состояния. PMS не переписывает прежнюю попытку: увеличивает номер попытки, помечает незавершённые строки прежней попытки как `SUPERSEDED`, создаёт новые идентификаторы и принимает в текущую локализацию только результаты текущей попытки и закреплённого `translator_ref`. Старые результаты и outbox остаются аудитируемыми.

Ошибки `TRANSLATOR_UNSUPPORTED_TARGET_LANGUAGE` и `TRANSLATOR_UNSUPPORTED_SOURCE_LANGUAGE` показываются как неблокирующее состояние английского fallback. Отдельная роль по расписанию повторяет такие записи только после изменения неизменяемого `translator_ref`; ручной повтор разрешён и при той же модели. Так отсутствие поддержки не создаёт бесконечную очередь к неизменившейся модели, но новая модель автоматически пересматривает накопленные языки.

Последняя доказуемая политика прежнего владельца переносится до пользовательской работы с PMS. Если прежняя БД уже недоступна, допустимо одноразовое восстановление только из сохранённого эксплуатационного доказательства, которое содержит полный снимок и точную прежнюю версию; восстановление явно нормализует русский заголовок и описание в английский канон, сохраняет ссылку на прежнюю версию в результате операции и создаёт записи всех доказанно встречавшихся языков для нового перевода.

## Последствия

Контракт Kafka v1 остаётся совместимым: версии, повтор и fallback остаются внутренними состояниями владельца, а `READY` по-прежнему означает полный массив строк. Операторский HTTP API получает добавочный маршрут явного повтора. Alembic сохраняет номер текущей попытки и `translator_ref`; поздний результат заменённой попытки не меняет каноническую локализацию. Потребители продолжают применять английский `PolicyPublished`, пока точная локализация не стала `READY`.

## Критерии проверки

1. API отклоняет новую политику с исходным языком, отличным от `en`.
2. UI не показывает внутренний ключ, схему или JSON как поля редактора и предоставляет четыре предметных поля.
3. Каждая карточка неанглийской локализации имеет действие нового перевода, а две попытки создают разные line request ID без удаления первой.
4. Неподдерживаемый язык остаётся в списке, явно использует английский fallback и автоматически повторяется после смены `translator_ref`.
5. Platform UI показывает одну кнопку «Управление политикой» и не дублирует заголовок над iframe.
6. Локальный оператор получает роли PMS одноразовым owner-controlled provisioning, а runtime не получает административную identity Keycloak.
