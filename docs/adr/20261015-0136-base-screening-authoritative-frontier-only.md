# ADR-0136: Base Screening получает адреса только через Zone Ingestion

## Контекст

Base Screening должен выполнять простой первый отсев: прочитать точную публичную страницу, сопоставить её с локализованной политикой, отложить точно неподходящую страницу и передать любой иной результат следующей стадии. Реализация дополнительно извлекала HTML-ссылки двумя путями и создавала по ним новые записи того же frontier. Поэтому семь проверенных страниц породили 177 новых URL-заданий, включая ссылки со страниц, уже направленных в отсев, а операторский интерфейс смешал число доменов Zone Ingestion с числом самостоятельно созданных URL.

## Решение

Единственным непосредственным источником рабочих записей frontier Base Screening являются доменные записи, опубликованные через Kafka владельцем Zone Ingestion. Base Screening не различает и не обходит этот владеющий контур: он не принимает адрес от экспертной стадии напрямую, не читает её хранилище и не создаёт локальное ссылочное происхождение.

Base Screening не извлекает и не перечисляет ссылки из HTML, `canonical`, sitemap, RSS/Atom, JSON-LD, опубликованных API или других частей документа и не создаёт по ним frontier, provenance, счётчики либо операторские карточки. Redirect сохраняется только как доказательство чтения той же точной страницы и не создаёт новое задание.

Экспертная стадия Discovery после собственного допуска материала извлекает домены из фактически наблюдённых ссылок. Если Zone Ingestion ещё не имеет обработанной зоны, покрывающей такой домен, экспертная стадия формирует неизменяемый временный zone file с точным происхождением ссылки и передаёт его Zone Ingestion по Kafka. Zone Ingestion проверяет файл, дедуплицирует домены с уже известными зонами и проводит его через обычный владеющий контур зон. Только опубликованный Zone Ingestion результат создаёт или обновляет рабочую запись Base Screening. Таким образом, обнаруженный экспертом домен может позднее поступить в Base Screening, но прямого перехода `expert → base-screening` и локального link-only frontier нет. Страница, отсеянная Base Screening, не доходит до экспертной стадии и не становится источником такого файла.

Рабочие выборки, аренды, ручные решения, показатели очереди, скорости и срока Base Screening учитывают только запись с активным `ZONE_INGESTION_DOMAIN` и действующей локальной записью зоны. Произвольная либо историческая запись `OBSERVED_LINK`, созданная самим Base Screening, закрыто не получает lease, не показывается в рабочих списках и не может быть принята оператором.

Миграция `20261015_0070` отменяет действующие передачи link-only записей штатной командой, деактивирует их provenance и переводит такие записи в нерабочее историческое состояние. Сохранённые снимки и строки прежних таблиц физически не удаляются, но активная metadata, runtime, API и новые базы больше не содержат механизма ссылочного frontier. Прежние таблицы на существующей базе являются только историческим материалом и игнорируются проверкой drift.

## Последствия и проверка

Число рабочих записей Base Screening объясняется только входом Zone Ingestion и завершёнными маршрутами этих же записей. Чтение страницы в Base Screening с внутренними и внешними ссылками не изменяет frontier. Ссылки с отсеянной страницы не могут появиться во входящих, переданных или отсеянных карточках как отдельные задания. Расширение Web-графа выполняет экспертная стадия, но каждый новый домен возвращается в начало каскада только через временный zone file и Zone Ingestion.

Проверка подтверждает отсутствие link extractor, настроек глубины и числа ссылок, таблиц наблюдённых ссылок в активной metadata, создание lease только по активному происхождению Zone Ingestion и исключение прежних link-only строк из API. Для сквозного маршрута отдельно проверяются точное происхождение ссылки в экспертной стадии, временный zone file, его приём и дедупликация Zone Ingestion и отсутствие прямой команды Base Screening.

## Миграция и откат

Перед обновлением publisher продолжает доставлять уже сформированные команды. Миграция сначала создаёт отмены для действующих link-only передач, затем переименовывает происхождение принятого входа в `ZONE_INGESTION_DOMAIN`, деактивирует локальное `OBSERVED_LINK` и перестраивает рабочие проекции. Откат, который снова разрешает ссылочный frontier Base Screening, запрещён без нового архитектурного решения; исторические строки остаются доступными для аудита. Временные zone files экспертной стадии имеют собственное происхождение у их владельца и не восстанавливаются из этих исторических строк.
