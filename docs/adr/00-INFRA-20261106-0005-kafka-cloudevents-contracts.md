# 00-INFRA-20261106-0005-kafka-cloudevents-contracts — Kafka и управление событийными контрактами

- **Статус:** Принят
- **Дата:** 2026-11-06
- **Происхождение:** неизменяемые ADR-0001, ADR-0005 и ADR-0091 из [архива выделения](../audit/inherited-adrs/INDEX.md)

## Контекст

Потребителям требуется единый воспроизводимый межсервисный транспорт без скрытого синхронного RPC и без центрального владельца предметных схем.

## Ключевые решения

- Межсервисный предметный обмен использует Kafka и версионированный CloudEvents envelope.
- Издатель владеет именем topic, schema, partition key, compatibility policy и provenance события.
- Инфраструктура предоставляет брокер и технические административные возможности, но не создаёт topics конкретного потребителя.
- Consumers идемпотентны и фиксируют offset только после собственной устойчивой транзакции.
- JSON payload проверяется закреплённой JSON Schema; несовместимое изменение получает новую версию контракта.
- Технические протоколы внутри одного владельца, включая OTLP и SPIFFE Workload API, не считаются исключением из предметной Kafka-границы.

## Последствия

- Доменные владельцы развиваются независимо при явной совместимости контрактов.
- Kafka не превращается в центральный каталог приложений или schemas без владельца.
- Новый межсервисный предметный RPC требует отдельного заменяющего ADR.

## Проверка и откат

Contract tests проверяют envelope, schema digest, topic ownership и отрицательные несовместимые fixtures. Откат consumer не меняет историю topic; откат publisher допускается только к версии, совместимой с уже опубликованными событиями.

## Официальные основания

- [Apache Kafka documentation](https://kafka.apache.org/39/documentation/) описывает topics, partitions, consumer groups и delivery semantics.
- [CloudEvents 1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md) задаёт переносимый событийный envelope.
- [JSON Schema 2020-12](https://json-schema.org/draft/2020-12) задаёт версионированную проверку payload.
