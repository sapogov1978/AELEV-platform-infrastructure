# Changelog

## Unreleased

- Root/full-local больше не превращает принадлежащие Translator data/telemetry
  сети во внешние при подключении общего compute recipe; standalone-станция
  по-прежнему требует явные маршрутизируемые owner networks. Descriptor
  Translator повышен до revision 12, а bootstrap мигрирует только прежнее
  штатное значение 11, сохраняя операторские overrides. Provider/worker tmpfs
  явно заключён в кавычки, чтобы YAML не разбивал mount options на второй путь.
  Clean-room readiness учитывает фактический image-owned `HEALTHCHECK`, даже
  когда внешний black-box image закономерно не раскрывает его в Compose model.
- Translator worker release publishes a signed `linux/amd64`/`linux/arm64`
  image index; Apple Silicon startup no longer depends on amd64 emulation.
- Startup admits the multi-platform provider release `42615707050` at digest
  `0a09783d...ee016` and worker release `42615706844` at digest
  `d68d7024...a98a5`. Init migrates only the exact superseded image references;
  explicit operator overrides remain unchanged.
- Root capability `translation` и `full-local` 1.1.0 теперь включают отдельные
  подписанные provider/worker images по точным digests. Startup не клонирует
  mutable repository: create-only импортирует существующий ignored
  `TranslationProvider/.env.local` в generic read-only secret mount.
- Provider egress использует отдельную именованную сеть с явным owner-configured
  subnet и не зависит от свободного Docker default address pool.
- Clean-room manifest и gate получили двенадцатую функцию: image-owned health и
  worker-side opaque UDS probe точной пары images с синтетическим credential и
  без inference. Исторический PASS 11/11 не переносится на новый release.
- Translator compute recipe больше не блокирует внешний opaque provider через
  `network_mode: none`: он предоставляет исходящую сеть без входящих портов и
  generic read-only secret mount. После offline-проверок отсутствующий API key
  был единственным локальным runtime-вводом до его ручного заполнения; реальный
  inference дополнительно требует доступного provider balance.

## 1.0.0 — 2026-11-08

- Буквальный clean-room runbook сохраняет все выходы вне checkout, передаёт verifier тот же каталог, что и gate, и использует создаваемую локальным bootstrap operator identity; отдельная ручная установка SPIRE не навязывается автоматизированной приёмке.
- Повторная сверка закрывает несоответствия прежней структурной проверки: действующие архитектура и руководства больше не зависят от consumer-репозитория, публичные API не содержат чужих событий, screening routes или модельных ячеек. Предыдущие API сохранены побайтно с digest; неизменяемые документы SDK отделены от текущего нейтрального контракта.
- Documentation gate проверяет нормативные границы и frozen SDK provenance; негативные тесты воспроизводят прежние нарушения. Добавлены собственные deployment/storage/Platform UI/supply-chain документы, карта API и единая процедура release; исправлена официальная ссылка SPIRE federation и противоречие heartbeat/withdrawal.
- Семантически пересмотрены 18 диаграмм: из общей композиции исключены устаревшие модель/worker и ADR-ссылки, Translator показывает невыбранный внешний opaque provider, PostgreSQL — strict ANY 1 и native fencing без отдельного выборщика ведущего. Регрессия запрещает возвращать конкретную модель в каноническую композицию.
- Release metadata и full-local manifest согласованы на 1.0.0; API установки v1, bundle format v2, принятый стек, Kafka schemas и runtime сохраняются. Stable-публикация требует нового CI/full-local/verifier точного source commit и проверенных ZIP/lock/BOM/evidence; исторический PASS 0.2.0 не подменяет этот допуск.
