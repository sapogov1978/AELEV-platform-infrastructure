# Changelog

## 2026-11-06

- Добавлен подписываемый multi-architecture GHCR release pipeline для owner-controlled Observability Sender; он заменяет недоступный внешний Docker Hub base как воспроизводимый источник SQLite и sender runtime для clean-room.
- Full-local build/pull теперь передаёт plain BuildKit progress в ограниченный stage artifact вместо потери stderr внутри вложенного CLI; fail-closed clean-room evidence показывает точный упавший Dockerfile/слой без запуска контейнеров.
- Hosted clean-room выявил рассогласование local compute-профиля Translator: документированное пустое значение OTLP отклонялось только `compose.compute.yml`. Рендеринг приведён к основному Compose и защищён регрессией; production-требование HTTPS/mTLS telemetry не ослаблено.
- Первый hosted clean-room run подтвердил выдачу одноразовой машины и полный host-neutral `init`; fail-closed package preflight остановил дорогую сборку на отсутствующем межрепозиторном Actions read access к private provider package. Runbook и readiness-аудит фиксируют точное минимальное разрешение без PAT или пользовательского сервера.
- На чистом full-local checkout только что созданные env получают host UID/GID для локальной доставки секретов и provision; существующие env площадки не меняются. Это устраняет зависимость clean-room от macOS-значений `501/20` и заранее созданной группы `10000`.
- Full-local `init` теперь устанавливает lock-pinned operator dependencies каждого владельца Observability до запуска его `prepare.py` через собственное Poetry-окружение; чистая машина больше не зависит от случайно установленных глобальных `httpx`/FastAPI пакетов.
- Clean-room workflow переведён с отсутствующего постоянного self-hosted стенда на одноразовый GitHub-hosted Ubuntu runner: image digests берутся из versioned manifest, временный viewer secret создаётся владельческим `init`, а долгоживущие пользовательские runner/variables/secrets не требуются.
- Первый Translator worker release успешно выполнен на GitHub-hosted Linux runner без пользовательского сервера: опубликован image с SBOM, provenance и Cosign signature под точным digest `sha256:e006ab2466b6455d6a928e8aa9aa12fc023ac9a7e3c5897082508249b422f912`; digest и release evidence закреплены в full-local manifest, runbook и readiness-аудите.
- Исправлена чувствительная к регистру ссылка архивной композиции на корневой `INDEX.md`, обнаруженная Linux CI после унификации агентских карт.
- Первый Linux amd64 release отдельного translation provider успешно собран на GitHub-hosted runner без пользовательского сервера: verified model weights, SBOM, provenance и Cosign signature опубликованы под точным digest `sha256:4a820a13e6a03188589c09d14e52b5f2d05e9359d7df847bad768966016e9ec9`; full-local manifest и runbook закрепляют его как внешний вход.
- Тот же exact provider digest прошёл bounded quality smoke на чистом GitHub-hosted runner: 20/20 утверждённых синтетических переводов через opaque UDS, hash-only evidence и bounded cleanup; отдельная машина для provider release/quality не требуется.
- Создан отдельный private-репозиторий `sapogov1978/AELEV-translation-provider` с сохранённой subtree-историей реализации: модель, веса, runtime, prompt, cache, lock и healthcheck принадлежат provider, а Translator получает только непрозрачный UDS-контракт. Добавлены независимые подписываемые release workflows для provider и Translator worker; clean-room manifest и runbook теперь указывают канонические источники обоих digest.
- Добавлен отдельный clean-room `full-local` контракт: manifest 15 владельцев и 57 runtime-ролей, сохраняющий owner-local bootstrap, fail-closed preflight внешних входов/образов/owner paths, build без старта, release BOM, исполняемый lifecycle runner и независимый verifier evidence одиннадцати пользовательски наблюдаемых функций. Ручной GitHub-hosted workflow запускает тот же gate на одноразовой машине. До нового полного прогона общий статус репозитория честно остаётся `IN_PROGRESS / BLOCKED`; scoped-выводы самостоятельных продуктов и допуск площадки не смешиваются с ним.
- Все 17 агентских карт корня, композиции Observability и владельцев унифицированы как uppercase `INDEX.md`: каждая таблично отвечает «что и где искать» и явно дополняет Graphify, не подменяя AGENTS/README/SPEC/USER_MANUAL. Документационный gate запрещает активные lowercase `index.md` и проверяет назначение, таблицу и ссылку из README.
- Исправлена граница Translator: сервис владеет Kafka-контрактами, очередью, диспетчеризацией и результатами, но не моделью или способом перевода. Из активной поставки удалены reference provider, его веса, downloader, runtime и lock; внешний provider image самостоятельно владеет запуском и healthcheck. Worker отправляет ему только текст и языки через единый непрозрачный порт.
- Общие Graphify graph/report/manifest остаются версионируемыми, а локальная история запросов, reflections, vocabulary и learning sidecars исключены из Git, чтобы агентская навигация не публиковала пользовательский контекст.
- Нормативный ADR-каталог пересобран как 15 ключевых решений самого Platform Infrastructure по шаблону `00-INFRA-YYYYMMDD-NNNN-essence`; screening, crawler, research и иные consumer-решения исключены из него. Все 132 унаследованных файла и их SHA-256 сохранены без изменения в аудиторском архиве с явным disposition для каждого источника.
- Проведён полный аудит документации и диаграмм 15 самостоятельных владельцев и межвладельческих частей. Добавлены матрица Production Readiness, официальный реестр оснований решений и CI-gate полного комплекта README/SPEC/USER_MANUAL/диаграмм.
- Все действующие сервисные руководства дополнены прямыми ссылками на официальную документацию производителей и стандартов. Каждый нормативный `00-INFRA-*` ADR содержит официальные основания; унаследованный архив остаётся provenance, а не источником действующих решений.
- Полный suite обнаружил несовместимые со строгой проверкой Python/OpenSSL локальные цепочки Observability без SKI/AKI. Воспроизводимые патч-выпуски `aelev-observability-tools` 1.0.1/1.1.3 добавляют только идентификаторы ключей CA/leaf; принятые версии Python, Alpine, FastAPI и production PKI не меняются.
- Репозиторий переименован в `sapogov1978/AELEV-platform-infrastructure`; сервисы, корневой Compose и установщик перенесены прямо в корень без `services/infrastructure`. Все существующие удостоверения и настройки checkout сохранены.
- Выпуск `0.2.0` использует плоский формат пакета 2 с документацией и инструментами. CI, ссылки, диаграммы и security inventories следуют новому дереву; исторические README/CHANGELOG композиции архивированы с сохранением исходного поддерева.

- В `0.1.2` обязательная сборка объектного хранения включает собственный MinIO image; запуск больше не рассчитывает на образ, оставшийся от прежней установки. Отдельный CI gate проверяет покрытие сборкой всех выбранных runtime-образов с локальным рецептом.
- Сборка проверенных рецептов не требует владения уже работающей Compose-группой; проверка владения остаётся обязательной перед запуском и остановкой процессов.

- Исправлен первый запуск из чистого checkout: шаблон MinIO env больше не создаётся раньше владельческого генератора TLS и локальных настроек. Добавлена проверка этого порядка; существующие env и удостоверения не перезаписываются.
- Версия локального CLI и пакетного выпуска читается из единственного `services/infrastructure/release.json`; исправление публикуется отдельным патчем `0.1.1` без изменения прежнего тега.
- Сборщик получает версию и исходные байты из того же точного commit, явно отключая Git auto-CRLF; опубликованный ZIP воспроизводится независимо от настройки окончания строк у издателя и CI.

## 2026-11-05

- Добавлены публичный локальный установщик выбранных возможностей, проверка владения Compose, исключение модельных/очередных ролей и воспроизводимый пакет исходников с полной описью SHA-256.
- Чистая подготовка проверена без запуска контейнеров; локальные секреты и машинные координаты Graphify явно исключены из Git.
- README и SPEC общей композиции ссылаются на самостоятельный установочный интерфейс и сохраняют ручной владельческий режим эксплуатации.
- Локальная проверка готовности identity использует только фиксированный HTTPS endpoint через проверенную CA, без универсального URL opener; новый установщик проходит прежний строгий SAST gate без расширения baseline.
- В инструкциях агентов закреплён собственный зарегистрированный RMS project key PlatformInfrastructure и обязательная маршрутизация каждого вызова без смешивания памяти потребителей.
