# Translator canonical independently placed SQL profile

History-first review of Translator README/SPEC/CHANGELOG, the 17 November queue evidence and Keycloak's canonical network/identity-preparer confirms the SQL protocol is already qualified. The queue fixture creates its own TLS PostgreSQL container; canonical `compose.remote.yml` still defines the bundled `translator-database` without published ports, SSL command or external network access. This is a deployment gap in the full runtime inventory, not a reason to reimplement queue/SQL clients or silently remove the database role.

Pre-edit forecast: **45–60 minutes** recipe/helper/host checks, then **30–45 minutes** bounded native prepared task/server/client checks. The pinned `postgres@sha256:ef257d85f76e48da1c64832459b59fcaba1a4dac97bf5d7450c77753542eee94` is already inspected as PostgreSQL 17.6. No dependency, OS, provider, application SQL schema or runtime stack change is selected.

## Scope and conflict review

Add opt-in `compose.database-network.yml`, owner-local offline shell identity preparation and fixed HBA. The existing database role retains its image, entrypoint, data volume, password/user/database, resource limits and healthcheck; the overlay selects built-in TLS 1.2+, private server leaf/key/client-CA volume, fixed HBA and an explicit published bind/port. Its own project-scoped server network is routable. The default recipe remains byte-identical and local clients retain their old profile.

One new operation runs on the assigned SQL node using that same exact pinned image, root, network none, readonly rootfs/source, drop ALL plus only the established CHOWN/FOWNER/DAC_OVERRIDE and no-new-privileges. It derives the actual unprivileged postgres UID/GID from the pinned image (the Keycloak image's hardcoded UID must not be copied blindly), bounds regular nonlinked inputs, initializes an empty own target with `0700/0600` and refuses partial/foreign/drift rather than repairing or deleting. It is initial delivery, not issuer/rotation/recovery. Complete files/metadata are flushed before a successful result; repeat preserves exact bytes. A changed identity requires owner handoff. No CA private key enters runtime.

The matching task/runtime declare the same unique assigned-node TLS volume; task uses external=false, runtime external=true after the DAG awaits the task receipt. Different servers/replicas use separate volumes and keys. Existing clients use published host/port, `verify-full`, matching client identity and password through their own existing SQL settings; no shared server/client network or filesystem is required. Fixed network HBA rejects non-TLS and requires SCRAM plus clientcert=verify-full for IPv4/IPv6; local trust remains inside the SQL container's pre-existing administrative boundary.

All source/catalog/profile combinations, role counts and default behavior are checked before effects. Native proof uses fresh synthetic identities/data, actual prepare/task plus same SQL image and existing Translator client image on disjoint networks. Check CA/hostname/plaintext/no-client/foreign-client/password refusals, SQL insert/read and restart preservation, idempotent receipts, private-file permissions and exact owned cleanup. These do not establish full platform startup, replica failover, image admission, external PKI renewal, release or production readiness. Working data/queues, credentials and recovery budgets are untouched; no canonical RESUME or OpenAI.

## Documentary grounds

Before native execution, review found that unconditional EXIT cleanup of predictable `.prepare-$$` could remove preexisting staging after a refusal. The same prior Keycloak pattern additionally continued after catchable signals. The approved 20 November review selects stage ownership tracking and terminating HUP/INT/TERM handling in both helpers; only the stage successfully created by the current invocation may be removed. Preexisting/partial/foreign/stale-lock state is preserved. Host red tests reproduce the defect using real shell/filesystem operations with explicit UID/stat/sync adapters; they do not replace native Linux permission/durability proof. Targeted forecast: 15–20 minutes source and 20–30 minutes preservation/signal checks within the existing lane estimate. [POSIX trap](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/trap.html) describes deferred shell traps; AELEV defines the no-repair policy. [GNU sync](https://www.gnu.org/software/coreutils/manual/html_node/sync-invocation.html) documents the selected filesystem flush; actual command support in the pinned image remains a native check.
