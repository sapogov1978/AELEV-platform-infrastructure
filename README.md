# Platform Infrastructure

Самостоятельная целенезависимая поставка технической инфраструктуры: Kafka, PostgreSQL, объектное хранение, идентификация, Platform UI, наблюдаемость, контролируемый сетевой доступ и перевод. Прикладные политики, topics, базы, buckets и полномочия потребителей принадлежат самим потребителям.

## Локальный запуск

Требуются Docker Engine/Desktop с Linux containers, Compose 2.24.4+, Python 3.11+ и OpenSSL. После клонирования этого репозитория выполните:

```sh
./infrastructure up
```

Команда готовит отсутствующую локальную конфигурацию, собирает необходимые образы и запускает PostgreSQL, Kafka, MinIO, Keycloak и Platform UI. UI доступен по `https://127.0.0.1:18082`, имя оператора — `platform-operator`, пароль находится только в локальном исключённом из Git `services/infrastructure/platform-ui/secrets/provision/operator-password`. Самоподписанное локальное удостоверение требует доверия браузера. Модели, рабочие роли перевода и очереди этим входом не включаются.

```sh
./infrastructure plan
./infrastructure status
./infrastructure down
```

`down` останавливает выбранные инфраструктурные процессы и сохраняет данные. Прикладные продукты останавливаются отдельно. Для ограниченного состава повторяйте `--capability`, например `./infrastructure up --capability kafka`. Состав и зависимости возможностей определяет только [владелец](services/infrastructure/bootstrap.py); зависимость Platform UI от identity добавляется автоматически. `build` не запускает контейнеры. `init` только подготавливает локальные файлы и проверяет Compose.

Запуск относится к локальному ознакомлению. Реальные grants, сертификаты рабочих нагрузок, защищённые endpoints, backup, аппаратный допуск моделей и независимые области отказа подготавливаются по руководствам владельцев. Обычный запуск не разрешает возобновление ранее приостановленной обработки.

## Независимые выпуски

Потребитель закрепляет версию, исходный Git commit, SHA-256 ZIP и опись файлов. ZIP формируется только из отслеживаемого дерева `services/infrastructure`; рабочие `.env`, ключи, пароли, веса и runtime не входят. Канонический код находится только здесь. Продукт получает проверенный выпуск автоматически и сохраняет его как локальную зависимость, без редактируемой копии исходников в своём Git.

```sh
python3 tools/build_bundle.py --output dist/platform-infrastructure-0.1.0.zip
```

Первый выпуск поставляет закреплённые исходники и рецепты для локальной сборки. Он не объявляется подписанным выпуском готовых production images. Пакеты и образы следующих выпусков должны проходить те же проверки целостности, совместимости и допуска; автоматическая загрузка не даёт права обновить уже работающую общую установку.

Закрытый репозиторий требует доступа GitHub при первом получении выпуска. CI потребителя использует отдельный read-only deploy key только к этому репозиторию; личный токен владельца в CI не передаётся.
