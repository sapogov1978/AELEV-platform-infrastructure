# Технические интерфейсы SPIRE

В сетевом `GET /v1/public-state` поле `renewal` содержит только собственную identity `public-source` либо `null`. HTTPS source требует свежий отдельный `public-source.json`, совпадение SHA-256/expiry с фактическим `source.crt` и собственную installation identity при доставке. Observer/sender/publisher проверяют свои локальные receipts отдельно; source не свидетельствует об их credentials. Старый файловый режим сохраняет восемь identities и три квитанции.

`python -m aelev_spire.recovery_history --state DIRECTORY --role sender|observer` — читающий оператор полной собственной цепочки восстановления. Возвращает только `prior_attempts` и `evidence_sha256`; Docker socket, сетевой доступ и запись не нужны. Источник должен быть проверенным read-only состоянием владельца, не произвольной присланной квитанцией. Ошибки `SPIRE_RECOVERY_HISTORY_*` запрещают импорт неподтверждённого нуля или неполной истории; точные правила находятся в [SPEC](SPEC.md).

| Интерфейс | Область и допуск |
|---|---|
| Явно опубликованный HTTPS `GET /v1/public-state` | Опциональная собственная read-only проекция server по mTLS и точной client identity; исходный heartbeat до 15 секунд и санитарная renewal summary. Отрицательный ответ не переключает reader на файл; [контракт](SPEC.md) |
| SPIRE Server TCP 8081 | Штатный протокол аттестации/обновления SPIRE; первоначальное подтверждённое доверие и однократное право либо действующий agent SVID. Не браузерный и не предметный API |
| `/run/spire/admin/api.sock` | Стандартный административный API только локальной отдельной операторской задачи; TCP-публикации и mount в runtime потребителя нет |
| `/run/spire/workload/api.sock` | Стандартный SPIFFE Workload API внутри отдельного агентского контейнера; только его собственный аттестованный процесс доставки |
| `/run/svid/current.json` и поколение | [Ограниченная файловая доставка конечного SVID](SPEC.md#агент-и-удостоверения) в собственном временном volume потребителя; не доступ к canonical storage провайдера |
| Native `/live`, `/ready` на localhost:8082 | Только внутренние проверки supervisor; готовность не является новым разрешением |
| `/run/spire/heartbeat.json` | Прямое локальное чтение Docker-пробой `python -S`; сеть и приложение не загружаются |
| `/run/observation/heartbeat.json` | Отдельная производная проекция того же собственного источника, срок 15 секунд; не содержит административного socket или ключей |
| `https://spire-observer:8083/healthz`, `/readyz`, `/metrics` | Только собственная техническая identity чтения; [канонические тела проб](../docs/api/health-readiness.md), собственные численные показатели. Нового предметного API нет |
| `https://spire-telemetry-sender:4318/v1/logs`, `/v1/traces`, `/api/v1/write` | Существующий [защищённый контракт телеметрии](../docs/api/telemetry.md), собственный устойчивый журнал; не Kafka-домен |

Поставка не добавляет браузерный Swagger или доменный gRPC. Операторские `authorize`, `revoke`, `inspect`, `export-bootstrap` вызывают только фиксированные публичные SPIRE-команды, не принимают произвольный исполняемый файл. Параметры, наблюдение и повтор определены в [SPEC](SPEC.md), эксплуатация — в [руководстве](USER_MANUAL.md).

`python -m aelev_spire.installation export-bootstrap --project PROJECT --daemon-id ID --host-os Darwin|Linux|Windows --runtime-image IMAGE` принимает прежний `/run/input/request.json` и экспортирует только действующее начальное разрешение. Безопасный JSON-ответ возвращает ссылку на закрытый результат, не token; состав/срок и ошибки определяет [контракт](../docs/api/workload-identity.md#операторская-регистрация). Для приёма на другом узле прежняя `agent` поддерживает `--exported-bootstrap --bootstrap-operation UUID` и исходный каталог `/run/input`. Корень CA и административный socket получателю не выдаются. Shell/PowerShell-входы поддерживают обе операции; установка требует закреплённую согласованную пару образов.

`python -m aelev_spire.composition --project PROJECT --daemon-id ID --output DIRECTORY` — отдельный читающий операторский экспорт собственной установленной композиции. Требует read-only installer volume и локальный Docker-доступ только отдельной задачи; читает фактические образы/mounts/политики, завершённые записи восстановления и marker. Возвращает публичные файлы по [контракту происхождения](SPEC.md#публичная-композиция-установленного-провайдера), без секретов, административных задач или нативных операций выдачи. Несовпадение владельца/daemon/выпуска, незавершённое восстановление и неизвестные секретные поля возвращают безопасные коды `SPIRE_COMPOSITION_*`; до успешного экспорта рабочая привязка не переключается. Хостовые `export.sh`/`export.ps1` согласуют `.env` автоматически.

`python -m aelev_spire.sender_recovery` — отдельный операторский CLI адресной замены только исчерпанного собственного sender (по умолчанию) либо observer (явный `--role observer`); требует точные project/daemon/container ID, digest установленного образа и хеш проверенной остановленной копии. `--project` всегда обозначает прежнего логического владельца; физический Compose-координатор проверяется автоматически по его runtime. Устойчиво сохраняет прежние три рестарта и `restart=no`, сверяет владельца/mounts и повтор после потери ответа; новый отказ требует отдельного решения. Никакой сетевой runtime-точки с Docker-полномочиями не добавляет.
