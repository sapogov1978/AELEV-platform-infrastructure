# История SPIRE

- 2026-11-11: общий Python observation installer Shell/PowerShell на Docker Desktop разрешает фиксированный host alias через непривилегированный helper без секретов и socket. Установщик с Docker socket сохраняет `network=none` и формирует `extra_hosts` по проверенному адресу; native Linux и отсутствие aliases не требуют resolver.
- 2026-11-11: общая компиляция наблюдения применяет recovery-метки sender и observer после общих labels и configuration revision. Повторная установка после адресного восстановления сохраняет обе цепочки и `restart=no`; regression проверяет следующий допуск `require_running` и неизменные байты recovery-журналов.
- 2026-11-11: entrypoint адресного восстановления observer/sender сохраняет валидированный marker `native_restart_no_roles`; совместимость с ужесточённым установщиком проверена вместе с lost-ack и прежним исчерпанным бюджетом.
- 2026-11-11: одноразовый Shell/PowerShell installer получает `DAC_READ_SEARCH` для read-only входов другого Linux UID; без него закрытый host-каталог вызывал PermissionError при первом плане. Host permissions и полномочия постоянных runtime-ролей сохраняются.
- 2026-11-11: CI требует чистые Ruff/strict Pyright, восстановление раздельных Linux UID без пропусков и реальную повторную установку с native `no`. В проверочный образ включены публичные установочные входы, host bytecode/cache исключён; ошибочные структуры certificate-delivery отклоняются до публикации.
- 2026-11-11: выбранный либо наблюдаемый native `restart=no` сохраняется для каждой постоянной роли в installer marker, в том числе при отсутствии прежнего контейнера. `--native-restart-policy no` не создаёт второй controller, не включает остановленные очереди и не сбрасывает прежние attempts/holds; несовместимый старый установщик не может молча удалить этот выбор.
- 2026-11-11: восстановление сохраняет UID/GID целевых ролей, включая отдельный root оператора `installation`; неверный владелец этого root отклоняется до записи. Linux-проверка использует настоящий процесс UID 10001 и сохраняет разграничение доступа к runtime и installer state.
- 2026-11-07: default base стадии `telemetry-sender` переведён с недоступного локального Docker Hub sender 1.0.9 на подписанный owner-controlled multi-architecture GHCR digest `sha256:162f07e6fd043eb3d9e04e7c415bee07771321a6f7f3864fcba0ce1f80dd941e`. Собственная SQLite-оболочка, SPIRE runtime, журналы и прежние датированные evidence не меняются.

- 2026-11-04: Shell/PowerShell-операторы установки и экспорта закрыто требуют одноразовое явное подтверждение root-equivalent доступа к Docker socket до первого обращения к daemon; helper-контейнеры получили `network=none` и предел процессов, постоянные SPIRE-роли не изменены.

- 2026-10-27: helper доставки принимает старый и новый CA одним публичным bundle, корректно перебирает разные ключи при одинаковом subject и использует отдельный lock для `status`, `status-query` и `status-publisher`. Одновременные минутные циклы больше не создают ложные отрицательные квитанции; все три профиля переведены на один проверенный immutable digest.

- 2026-10-27: восемь локальных identity наблюдения подключены к трём раздельным owner-задачам автоматического продления; `/readyz`, Platform UI, Prometheus и тревоги требуют три свежие квитанции и 30-дневный запас. Для query/server/write CA подготовлено новое 365-дневное поколение с перекрывающим доверием; адресное обновление observer, publisher и sender сохранило SPIRE Server, агенты, журналы и историю восстановления.

- 2026-10-26: публичный установщик агента принимает проверяемые `--compose-project` и читаемое `--container-name` с обязательным префиксом `aelev_`. Физический Compose-проект отделён от логической установки и выбирается только при отсутствии действующей инкарнации; имя контейнера сохраняется в собственной модели Compose, допускается его одноразовое добавление к прежнему тождественному плану. Имена представления не становятся идентичностью: прежние метки установки, node state, регистрации, тома SVID и правила отзыва сохраняются.

- 2026-10-25: [четыре постоянные роли зарегистрированы в прежнем автоматическом восстановлении](test/recovery-registration-result-20261025.md), attempts 0/3/0/3 сохранены. Возвращён только прежний sender после проверки остановленной копии; Server/SDK/identities не обновлялись. Добавлен читающий экспорт уникальной цепочки прежних попыток, общий Compose сохраняет native `no`.

- 2026-10-25: [адресная установка observer и запуск прежнего sender подтверждены](test/observer-liveness-result-20261025.md): 118 тестов, проверенное восстановление архивов, healthy четырёх ролей, mTLS и свежая центральная телеметрия. SDK sender, Server, publisher, identities и бюджеты не менялись; собственная общая композиция актуализирована.

- 2026-10-25: observer учитывает завершённые ограниченные подшаги вместо суммарной длительности всего цикла; после диагностики повторно проверяет отказ и не завершает восстановившийся поток по старому наблюдению. Отметки фаз не продлевают живость, настоящие зависания и смерть потока сохраняют отказ; пределы запросов, подтверждения пакетов и SDK sender не меняются.

- 2026-10-24: выбран публичный sender 1.0.9 с повторной проверкой критического отказа после диагностики/записи истории. Собственная оболочка не патчит SDK; прежние Python/Alpine/SQLite, Prometheus, локальная проба и пороги сохранены. Проверки остановленного журнала и адресная установка фиксируются отдельно, другие роли SPIRE не обновляются.

- 2026-10-23: [изолированный bootstrap-прогон](test/bootstrap-export-result-20261023.md) подтвердил два одинаковых экспорта, установку отдельного настоящего SPIRE Agent из пакета, повтор и запрет после отзыва. 113 автономных проверок прошли, рабочие SPIRE/identities не переключались; физические Windows/NVIDIA и защищённый межмашинный канал остаются отдельными проверками.

- 2026-10-23: добавлен публичный `export-bootstrap` для уже завершённого точного разрешения, без нового token/entry и продления 600 секунд. Проверяются действующая регистрация, исходные scope/node/token/bundle; пакет закрыт, повтор сохраняет байты, отзыв/истечение/дрейф запрещают экспорт. Отдельный агентский вход проверяет переданный пакет без доступа к состоянию сервера. Shell/PowerShell и контейнерная пара поддерживают новый интерфейс; рабочая установка этим этапом не меняется.

- 2026-10-23: [операторы разделяют логического владельца и физический Compose-координатор](test/coordinator-result-20261023.md): прежние marker/планы/тома/регистрации и бюджеты сохраняются, общий проект не присваивает чужих соседей, смешанные/двойные инкарнации закрыто отклоняются. 100 хостовых проверок и 99 автономных прошли, строгая типизация чистая; два настоящих Docker-сценария подтвердили повтор, выдачу/отзыв и общий проект с чужим соседом. Новый читающий оператор подтвердил прежнюю публичную композицию без смены четырёх рабочих runtime. Фактический перенос рабочего Server не выполнялся.

- 2026-10-23: [публичный экспорт установленной композиции проверен и применён](test/composition-export-20261023.md): общий Compose выбирает четыре прежних разных образа, внешние тома и сохранённые политики без административных задач.
