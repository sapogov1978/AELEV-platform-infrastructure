# Задачи SPIRE

Историческая поставка по 00-INFRA-20261106-0007-workload-and-operator-identity прошла ворота поддерживаемого одноузлового профиля; результаты, границы испытаний и точные сборки находятся в [отчёте жизненного цикла](test/lifecycle-20261020.md). [Установка на рабочий локальный стенд 20 октября](test/stand-20261020.md) доказывает состояние на дату проверки, а не текущую доступность. Изменённый кандидат 1.1.3 требует свежих CI/clean-room и отдельной установки на рабочий стенд; его допуск описан в [общем аудите](../docs/audit/production-readiness.md).

- [x] закрепить стандартные SPIRE Server/Agent и собственные Python-зависимости;
- [x] отделить операторский API и состояние от runtime потребителя;
- [x] реализовать атомарную доставку и запрет восстановления отозванной регистрации;
- [x] проверить настоящие выдачу, ротацию и отзыв двух раздельных identities, запрет восстановления отзыва;
- [x] проверить точные identities потребителя, горячее обновление TLS и ожидание начального SVID без рестарта модели;
- [x] завершить Shell/PowerShell-входы установки с хранением итогов в Docker, проверкой ОС/Engine/владения и повтором без пересоздания; настоящий Shell-сценарий пройден на Docker Desktop;
- [x] подключить собственные устойчивую телеметрию, правила/Grafana и публикацию состояния по 00-INFRA-20261106-0009-independent-observability-and-telemetry/0101; проверить настоящие доставку/задолженность/возврат и права Grafana без отдельного уведомителя;
- [x] установить собственные Server/observer/publisher/sender на рабочем стенде; проверить обычный вход в UI и свежую метрику центрального Prometheus, не перезапуская прежние провайдеры;
- [x] проверить независимое зашифрованное восстановление состояния сервера, узла и оператора в новые тома без возврата отозванного доступа;
- [x] проверить собственный Docker `checks`, Ruff, форматирование, строгий Pyright, Poetry lock, Shell, общий Compose и документацию.
- [x] адресно восстановить только sender с проверенной остановленной копией, автономной heartbeat-пробой и запретом старому установщику восстановить бюджет; [протокол](test/sender-recovery-20261020.md).

На стенде остаётся отдельный SPIRE-проект. Проверенная модель включения `workload-identity` не является выполненным переносом этой установки в общий инфраструктурный проект; сервер, регистрации и сертификаты потребителей этим сопровождением не переключались.

Для внешней production-площадки отдельно подтверждаются начальные полномочия/внешний issuer, KMS/HSM, доставка секретов, доверенные узлы и их attestation, Kubernetes-политики, аппаратные области отказа/RPO/RTO, проверка backup/restore, подписанный admission и доставка тревог существующей системой наблюдения. Это не разрешение заменить их локальным CA или отдельной системой уведомлений.
