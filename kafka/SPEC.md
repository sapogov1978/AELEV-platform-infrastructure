# kafka: спецификация

Присутствие собственного издателя, штатная подтверждённая отписка и потеря связи определяются только [каноническим UI-контрактом](../docs/api/platform-ui-injection.md#присутствие-и-штатная-отписка) и 00-INFRA-20261106-0008-platform-ui-owner-injection. Отписка скрывает модуль без удаления журнала или изменения ревизии; отсутствие публикаций без отписки оставляет строку с потерей связи. Повтор и восстановление сохраняют владельца, UUID, последовательность и точные неподтверждённые байты.

Нативная топология, ответственность, безопасность и сроки хранения определены в [документации развёртывания](../docs/architecture/deployment.md), относящихся к продукту принятых ADR и [README](README.md). Конкретные потребители, их данные/контракты и политики не входят в поставку инфраструктуры.

Собственное техническое состояние публикуется независимой необязательной ролью `ui` по [каноническому протоколу](../docs/api/platform-ui-injection.md). Описание имеет тип INFRASTRUCTURE и перечисляет только собственные компоненты. Владельцу принадлежат проверки, identity, журнал и сборка; источников соседних сервисов, Docker API или общего образа издателя нет. Недоступность UI не останавливает нативный процесс; сетевое отсутствие подтверждения и истечение срока свежести означают UNKNOWN, а не доказанный OFFLINE. Отдельная задача развёртывания получает административные файлы только явно и удаляется после выполнения.

## Устойчивый журнал и конечное восстановление

Образ собственного издателя закрепляет SQLite 3.53.4 из публичного образа транспортной библиотеки по digest, сохраняя Python 3.13.7, Alpine 3.22 и клиент Platform UI 1.1.1. Перед заменой единственный писатель останавливается, полный собственный том с WAL сохраняется и проверяется старым и новым движком на изолированных копиях; UUID, последовательность и неподтверждённые байты должны совпасть.

`AELEV_INFRASTRUCTURE_KAFKA_UI_RESTART_POLICY` по умолчанию в примере равен `no`: новый экземпляр не получает автоматических попыток до проверки здоровья и регистрации либо передачи прежнего бюджета в [существующем ограничителе](../USER_MANUAL.md#ограниченное-восстановление-по-unhealthy). У ещё не переведённых целей прежний ограничитель использует оставшийся бюджет `on-failure:N`, при исчерпании — `no`. После явного перевода на 00-INFRA-20261106-0010-bounded-recovery-and-process-control native-политика остаётся `no`, а тот же хостовый контроллер выполняет ограниченные по частоте повторные попытки с сохранением накопленной истории. Значение env остаётся `no` для безопасного создания следующей инкарнации и не пересоздаёт уже зарегистрированную. Создание нового контейнера не обнуляет прежние попытки. Отказ наблюдаемого провайдера не является отказом живого цикла издателя.

## Лёгкая проба издателя

Docker-проба собственного издателя запускает `python -S /opt/aelev/publisher-health.py AELEV_INFRASTRUCTURE_KAFKA_` и читает только UUID и подтверждённый heartbeat собственного журнала `/var/lib/aelev-status/outbox.sqlite` в режиме только чтения. Проверка из закреплённого `aelev-platform-ui-client==1.1.1` не импортирует издатель или приложение и не выполняет HTTP/TLS-подключений; отсутствующий, чужой, устаревший или некорректный сигнал отклоняется. Прежние предел свежести `2 × UI_INTERVAL_SECONDS + 40 × UI_TIMEOUT_SECONDS`, интервалы и таймауты сохраняются. Это живость цикла, а не готовность провайдера или подтверждение доставки; порядок обновления — в [руководстве](USER_MANUAL.md#лёгкая-проба-издателя).

## Нативная проба broker/controller

Docker запускает непосредственно `/opt/aelev/kafka-health`, без shell, JVM, Python или дочерних процессов. Клиент соединяется только с loopback IPv4 и выполняет read-only `ApiVersions` v0, затем `Metadata` v1 с пустым, не null, массивом topics. Корректный ответ должен иметь ожидаемую correlation, совместимые версии API, уникальные API keys и broker IDs, непустой список brokers и известного controller в этом списке. Topics, сообщения, consumer groups, offsets и ACL не читаются и не меняются; справочник прикладных ресурсов не вводится. Это ограниченная техническая готовность собственного одноузлового процесса, не подтверждение записи во все разделы, TLS/ACL, WAN или HA-кластера.

Все подключения/чтения/записи используют один монотонный дедлайн 4 с, не отдельный таймаут каждого фрагмента. Ответ ограничен 64 КиБ; отрицательная/неполная длина, усечение, дубликаты, неизвестный контроллер и лишние поля закрыто отклоняются. Успех — exit 0 без вывода; ошибка — exit 1 и безопасный `KAFKA_HEALTH_*`, неверный локальный порт — exit 2. Прежние Docker interval 10 с, timeout 5 с, retries 20 и start period 20 с сохранены. Штатный `init: true` собирает завершённых детей, включая прежние административные CLI, без собственного второго supervisor. Runtime и его зависимости берутся из прежнего точного Apache Kafka 3.9.1; компилятор находится только в отдельной стадии сборки, статическая проба не заменяет библиотеки брокера.

Первоначальная конфигурация не выдаёт автоматический бюджет: `restart=no` сохраняется до явной регистрации в штатном ограничителе 00-INFRA-20261106-0010-bounded-recovery-and-process-control. Новый контейнер не обнуляет lifetime-попытки предшественника. Нездоровую замену не допускают, исчерпанный бюджет остаётся закрытым. [Операционная последовательность](USER_MANUAL.md#обновление-нативной-пробы) обязательна при самостоятельном и общем Compose; повторный `up` не заменяет передачу бюджета.
