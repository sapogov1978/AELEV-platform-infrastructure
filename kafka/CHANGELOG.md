# История kafka

- 2026-11-14: собственная зависимость Platform UI client обновлена до immutable SDK 1.1.2 (SHA-256 d7fc03eee7df98d906a5390505a15e67c008fbeccd856f73ac0d5c67f62efb86): operator prepare явно задаёт SKI/AKI. Runtime/protocol Python-модули побайтно совместимы с 1.1.1; существующие credentials, UUID/sequence, журналы и восстановительные бюджеты этим handoff не меняются.

- 2026-10-23: собственный издатель использует SQLite 3.53.4 при прежних Python/ОС/SDK и явную конечную restart-политику. Полный журнал проверяется до замены; UUID, последовательность и прежний бюджет сохраняются. Проверка сборки не подменяет фактическую установку.

- 2026-10-21: нативная проба и init адресно установлены на действующий локальный экземпляр. Реальная холодная копия сохранена, байты 1132 файлов восстановлены в изолированном tmpfs, все 194 подтверждённые partition boundaries и meta.properties проверены; три исходных тома и окружение сохранены. Здоровая новая инкарнация получила тот же бюджет штатным `replace`, без `reset`; [протокол](test/native-health-result-20261021.md) отделяет эти результаты от HA/WAN и остальных незавершённых изменений.

- 2026-10-21: добавлен собственный образ поверх прежнего точного Apache Kafka 3.9.1 с минимальной статической пробой без JVM/скриптов/дочерних процессов. Read-only `ApiVersions` v0 и пустой `Metadata` v1 проверяют ответ протокола и известного контроллера при общем дедлайне 4 с. Штатный Docker `init` обеспечивает уборку потомков. Compose не выдаёт бесконечный native-restart: бюджет подключается отдельным ранее установленным оператором; при замене прежние попытки сохраняются. Настройки, данные, listeners, node ID и предметные контракты не меняются.

- 2026-10-19: подключена автономная read-only проба heartbeat из клиента Platform UI 1.1.1 без импорта издателя и сетевых подключений. Сохранены собственные UUID, журнал, пороги и интервалы; нативный провайдер и его готовность не меняются.

- 2026-10-14: после сверки самостоятельной сборки, постоянного журнала, restart/replay, конфигурационных регрессий и публикации состояния продукт отмечен `PRODUCTION_READY`; будущий защищённый географический Kafka остаётся отдельной внешней установкой и не приписывается одноузловому Compose.
